# EVERFLOW 통합 임시 맵 구현 기록

검증 환경: Unity 6000.3.21f1, Windows, 2026-10-11.

## 열기

- 씬: `Assets/Scenes/Everflow_World_Graybox.unity`
- Project 창에서 씬을 열고 Play. 생성 메뉴를 다시 실행할 필요가 없다.
- 기존 타이틀은 기존 `Everflow_6Puzzles`로 진입한다. 타이틀·Build Settings·릴리스 버전은 변경하지 않았다.
- WASD 이동, 우클릭 드래그 카메라, Space 점프/덩굴 이탈, E 탑승, 1/2/3 능력 선택, 좌클릭 사용, R 현재 퍼즐 재시도.
- 에디터/Development Build의 F8은 전체 조망을 켜고 끈다. 조망 중 이동 입력은 멈춘다.
- 여섯 구역 완료 후 중앙 광장에 걸어 들어가면 엔딩 조망이 시작된다. 3초 후 `Restart world` 버튼으로 전체 상태를 초기화한다.
- F1~F6 구역 이동은 기본 비활성화다. 개발자가 Systems의 `debugStageSelection`을 켠 경우 에디터/개발 빌드에서만 사용 가능하며, 선행 완료 기록을 자동으로 만들지 않는다.

## 원본 조사와 재사용

원본은 `Assets/EverflowMVP/Scenes/Everflow_6Puzzles.unity`, 해당 씬의 제작 데이터 `Assets/EverflowMVP/Layout.json`, `Assets/EverflowMVP/Runtime`이다. 독립된 퍼즐 프리팹 대신 개별 오브젝트·노드·참조로 구성돼 있다. 동일 제작 데이터를 재사용하여 새 씬에 직렬화하고, 런타임 코드를 `EverflowGraybox` 네임스페이스로 복사했다. 새 씬은 원본 씬을 추가 로드하지 않는다.

원본의 재질 8개는 읽어서 공유하며, 원본 스크립트·재질·씬·타이틀은 수정하지 않았다. `MechanicsLab`과 `EverflowPrototype`도 보존했다. 작업 전 이미 변경돼 있던 로고 PNG 4개와 URP 아이콘은 유지했다.

| 구역 | 재사용한 노드 | 원래 기능과 새 완료 조건 |
|---|---|---|
| P01 | Flower, Vine | 꽃 성장·도약, 진자 덩굴 성장·탑승·이탈. 실제 꽃 사용 및 덩굴 탑승 후 출구 도착 |
| P02 | FallingStone, Slate | 반복 낙하석과 회전 석판 FREEZE. 동결 낙하석을 실제로 밟고, 두 대상이 동결되고 석판이 정렬된 상태에서 출구 도착 |
| P03 | Machine | PULSE로 회전, FREEZE 정렬. 전력·동결·정렬 상태에서 출구 도착 |
| P04 | Sluice, Water | 수문 PULSE → 물 충전 → FREEZE → 잎 탑승·가속·자동 도약. 실제 탑승과 얼음 상태를 확인하고 착지 출구 도착 |
| P05 | Source, Root, Door | 성장한 뿌리로 전도해 문을 올림. 뿌리 성장·문 전력과 출구 도착 |
| P06 | Source, Root, Rotor, Core | 뿌리 성장 → 전력 공급 → 회전 다리 FREEZE 정렬 → 최종 Core 별도 PULSE → 출구 도착 |

P06의 FREEZE 대상은 물이 아닌 회전 구조물이다. 원본에 능력 구체의 수량·회수·공전 제약은 없으며, 능력을 반복 사용하는 기존 규칙을 유지했다. 이동 속도 6, 중력 24, 일반 점프 높이 1.35, 사거리 15, 활강 가속도 8, 최대 속도 18은 원본 씬과 새 씬에서 동일하다.

## 실제 배치

아래 Y는 발을 딛는 바닥 상면이다. 플레이어 스폰의 중심은 상면보다 1.15 높다. 퍼즐 루트의 스케일은 모두 `(1,1,1)`이며, 로컬 동작 거리와 회전 반경은 원본을 유지한다. 외곽은 대략 X=-56~69, Z=-65~47이다.

| 구역 | 퍼즐 루트 (X,Y,Z) / Y축 회전 | 주 바닥 점유 폭×길이(X×Z) | 바닥 높이 | 스폰 중심 | 출구 목표 상면 |
|---|---|---|---|---|---|
| S | 시작 테라스 중심 X=0,Z=-55 | 24×20 | 0 | `(0,1.15,-58)` | 서쪽 길 |
| P01 | `(-50,0,-55)` / 0° | 12×43 | 0→3 | `(-50,1.15,-55)` | `(-50,3,-20)` |
| P02 | `(-50,3,-8)` / 0° | 12×42 | 3→5 | `(-50,4.15,-8)` | `(-50,5,24)` |
| P03 | `(-40,5,40)` / 90° | 42×12 | 5 | `(-40,6.15,40)` | `(-7,5,40)` |
| P04 | `(8,-1,40)` / 90° | 58×14 | 5→1 | `(8,6.15,40)` | `(47,1,40)` |
| P05 | `(55,1,22)` / 180° | 12×40 | 1 | `(55,2.15,22)` | `(55,1,-11)` |
| P06 | `(40,1,-24)` / 270° | 52×12 | 1 | `(40,2.15,-24)` | `(-6,1,-24)` |
| W | 광장 중심 `(0,3,3)` | 28×14 | 3 | 도착 영역으로 보행 | 광장 내부 |

폭×길이는 시작·중간·착지 바닥의 합집합을 감싼 범위이며, 빈틈까지 전부 바닥으로 메운 면적이 아니다. 연결 길·장식의 외곽은 별도다.

연결 길은 폭 6, 바닥 두께 0.7이다. S→P01은 항상 열려 있고, 각 구역의 완료 시 해당 출구 연결 길과 식생·문양이 나타난다. 다음 구역 진입 트리거는 플레이어를 이동시키지 않고 현재 구역과 체크포인트만 갱신한다. 잘못된 순서의 진입은 현재 체크포인트로 복귀시킨다.

- S→P01: `(-10,0,-60)` → `(-50,0,-60)` → P01 시작 바닥.
- P01→P02: `(-50,3,-17)` → `(-50,3,-12)` → P02 시작 바닥.
- P02→P03: `(-50,5,29)` → `(-50,5,40)` → `(-43,5,40)`.
- P03→P04: `(-2,5,40)` → `(3,5,40)`.
- P04→P05: `(60,1,40)` → `(66,1,40)` → `(66,1,27)` → `(55,1,27)`.
- P05→P06: `(55,1,-14)` → `(55,1,-24)` → `(43,1,-24)`.
- P06→W: `(-8,1,-24)` → `(-12,1,-24)` → `(-12,3,-10)` → `(-12,3,-6)` → `(0,3,-6)` → 광장.

## 설계 제안에서 보정한 이유

1. **높이 0→8→17 대신 0→3→5.** 꽃 발사 속도 `(0,14,7)`과 원본 착지 선반 높이 3을 유지했다. P02의 원본 상승은 2이므로 다음 능선은 Y=5다. 능력 속도나 캐릭터 크기를 강화해 설계 높이에 맞추지 않았다.
2. **P03/P04 북쪽 배치와 P06 동서 길이를 실제 퍼즐 크기에 맞춤.** P03 회전 다리는 길이 16, P06은 로컬 Z=48까지 바닥이 이어진다. P06의 제안 예약 폭 28에 압축하면 성장 다리·회전 다리·목적지 간격이 망가지므로 실제 X 폭을 52로 확보했다.
3. **P04 경사 낙차는 원본 3.9 유지.** 수평 진행 약 14.7, 경사 약 14.9°다. 제안의 35~45m 경사·10~13m 낙차로 확대하지 않았다. 월드에서는 동쪽으로 활강한다. 입구 상면 5, 착지 상면 1이다.
4. **P04 착지 바닥 확대.** 원본 로컬 Z=32~44의 12×12 바닥을 Z=32~52의 14×20으로 확장했다. 도약 립과 착지 시작의 틈은 유지하고 감속 여유만 추가했다. 실제 자동 활강 테스트에서 로컬 `(0,3.05,38.64)`에 정지했다.
5. **월드 +Z 고정 방향 수정은 새 복사본에만 적용.** 덩굴 이탈 보조 속도, 활강 이탈·조향을 퍼즐 루트 방향으로 변환했다. P05 문의 점유 검사는 부모 로컬 좌표로 변경했다. 90°/180°/270° 배치에서도 같은 물리 성능을 유지하기 위한 수정이다.
6. **기존 연속 19m 경계벽 제거.** 조망을 가리는 검증실 벽 대신 안전 바닥의 낮은 가장자리, 단절, P05 문 옆 유적 벽을 사용했다. 절벽 외형은 바닥 아래에 붙인 비충돌 장식이며 퍼즐 틈을 채우거나 추가 발판을 제공하지 않는다.
7. **광장 Y=3, 물레방아 중심 `(0,15,3)`, 직경 24.** 바퀴 하단이 광장 상면과 맞닿는다. 바퀴는 XY 평면에서 회전하며 고정 축은 Z 방향이다. 북쪽 보행 능선을 억지로 높이지 않고 별도 고가 수로를 Y≈29에 두어 바퀴 상단으로 물이 내려오게 했다. 수로·폭포·출수는 비충돌 시각 표현이며 유체 시뮬레이션은 아니다.
8. **실제 검증으로 발견한 경사 턱 제거.** P06→W의 6m 코너 바닥이 원래 경사 위로 약 0.33m 튀어나와 stepOffset 0.3에 걸렸다. 경사를 Z=-10에서 끝내고 Z=-6까지 평탄한 구간을 추가했다. 최종 검증에서 점프 없이 광장 내부 `(-0.05,4.05,-2.90)`까지 보행했다.
9. **시작 카메라 보정.** 원본 pitch 27°에서는 바퀴 상단이 잘렸다. 시작/전체 재시작에서 pitch 8°, yaw -12°로 설정해 바퀴와 서쪽 유도 흔적을 보이게 했다. 이후 우클릭으로 자유롭게 관찰한다.

일반 점프의 이론상 동일 높이 체공시간은 약 0.67초, 속도 6일 때 중심 이동거리는 약 4.02m다. 이는 중력·점프 높이에서 계산한 값이며, 모든 출발 위치에서 측정한 최대 우회 거리라는 의미는 아니다. 캡슐 반경·가장자리·낮은 착지점의 영향은 수동 우회 점검 대상이다.

## 진행·복귀·복원

- P01~P06의 상태와 완료 기록을 분리했다. 이동 퍼즐은 필요한 상태뿐 아니라 꽃/덩굴/낙하석/활강 사용 기록도 확인한다.
- 원본 중간 체크포인트(P01 선반, P02 중간, P06 중간)를 유지했다.
- 일반 추락 시 현재 체크포인트로 복귀하며 이동 속도·탑승 상태를 정리한다. 기존 퍼즐 상태와 완료 기록은 유지한다.
- 구역 시작 높이보다 9m 아래에서 복귀하며, 원본의 Y<-15 복귀도 유지된다.
- 잘못된 위치에 동결했으면 FREEZE로 해제하거나 R로 현재 퍼즐을 초기화한다. 다른 완료 구역은 지우지 않는다.
- 완료 구역의 식생·문양은 별도 오브젝트다. 원본 얼음·성장 다리·동결 석판을 복원 연출 때문에 되돌리지 않는다.
- 여섯 완료 후 바퀴가 회전하고 입수·출수가 켜진다. 광장 진입 후 전체 조망으로 전환하고 플레이어 입력을 멈춘다.
- 전체 재시작은 완료 배열, 노드 상태, 사용 기록, 탑승, 체크포인트, 선택 능력, 복원·바퀴·엔딩·카메라를 초기화한다.

### 씬 생성·컴파일·참조

- Unity에서 씬 생성 및 저장 성공: `Logs/graybox-build.log`.
- 추가 지형/경사 보정 저장 성공: `Logs/graybox-upgrade.log`.

- 누락 스크립트 검사 통과.
- 원본 MVP/Prototype, MechanicsLab, ProjectSettings, Packages의 Git diff가 비어 있음 확인.

### Unity Play Mode

최종 결과: **55개 검사 통과**. 원문: `docs/graybox-captures/play-test-results.txt`, 상세 실행 로그: `Logs/graybox-play.log`.

- 1/60초 고정 프레임의 에디터 전용 입력으로 실제 EFPlayer.Update 및 CharacterController 충돌을 사용했다.
- S→P01, P01→P02→P03→P04→P05→P06, P06→광장 연결 길을 걸어서 검사했다.
- P01 꽃 사용 시험의 시작만 꽃 위로 배치했다. 꽃에 올라타는 접근 동작과 마우스 조준을 포함한 무편집 전체 플레이는 아니다.
- 능력 적용은 `EFNode.Apply`를 호출했다. 실제 좌클릭 raycast, 사거리·시야 판정과 모든 카메라 조작을 자동으로 검증한 것은 아니다.
- 꽃 착지 로컬 `(0,4.05,13.18)`, 덩굴 착지 `(0,4.05,29.01)`, 낙하석 착지, 중간 선반 도약, 정렬 석판·회전 다리 보행, 90° 회전된 활강 착지·감속을 확인했다.
- P05/06 뿌리 전도·문/회전 다리와 최종 Core 별도 입력, 순서 제한, 잘못 동결한 상태의 R 재시도, 추락 복귀, 여섯 완료 후 바퀴·물, 광장 진입 엔딩, 전체 재시작을 확인했다.
- 모든 타이밍·조향·해상도·프레임레이트를 망라한 플레이테스트는 아니다. 8~9분 목표 플레이 시간은 측정하지 않았다.

### 중단 당시 조회 오류와 테스트 실패의 구분

처음 로그 조회가 exit 1이었던 시점에는 Play Mode 결과 파일이 아직 없었다. 이것만으로 Unity 실패를 판단하지 않았다. 이후 생성된 두 로그에서 실제 첫 실행 실패를 별도로 확인했다: 초기 3개 검사 통과 후 꽃 착지 검사 실패.

꽃 검사에서는 전진을 계속 눌러 선반을 지나쳤으므로 자동 입력을 수정했다. 덩굴 검사는 너무 일찍 이탈하는 타이밍을 수정하고 비행 좌표를 기록했다. P05/06은 충돌체인 뿌리 단자를 돌아가도록 테스트 보행을 수정했다. 반면 최종 광장 경사 턱은 실제 맵의 충돌 문제였으므로 지형을 수정했다. 최종 로그는 수정 후 55개 통과 결과다.

이와 별개로 일부 셸 실행은 샌드박스 도우미 초기화 또는 Git LFS 임시 파일 권한 오류로 실패했다. 일반 환경에서 재조회했고, 이를 Unity 컴파일/테스트 실패로 취급하지 않았다.

### Windows 빌드

- `Build/Graybox/EVERFLOW_Graybox.exe`: 새 씬 하나만 포함하는 별도 Development Build 생성 성공.
- 결과: **Succeeded, Errors 0, Warnings 485**.
- 결과 파일: `docs/graybox-captures/build-test-results.txt`. 상세 로그: `Logs/graybox-windows-build.log`.
- 485개 모두 기존 `com.unity.ai.inference` 패키지의 Sentis 셰이더 경고다. ConvGeneric 460개, ScatterND 9개, ConvTranspose 6개, SliceSet 4개, GridSample 3개, ScatterElements 2개, Pad 1개를 확인했다. 지원되지 않는 변형·정수 연산 성능·부호 불일치 등이며 맵 C# 컴파일 오류는 아니다. 패키지 소스는 수정하지 않았다.
- 빌드 후에도 ProjectSettings/Packages/MVP의 Git diff가 비어 있음 확인. 기존 타이틀·릴리스 버전을 변경하지 않았다.
- 독립 실행 파일에서의 수동 플레이는 미검증이다. 위 55개 물리 검사는 Unity Editor Play Mode에서 실행했다.

## Unity에서 직접 확인할 항목

1. 새 씬을 열고 Play. 시작 카메라에서 바퀴와 서쪽 길을 찾을 수 있는지 확인한다.
2. 꽃에 직접 올라가 성장시킨 뒤 Space로 선반에 착지한다. 전진을 계속 누르면 선반 끝을 지나칠 수 있다.
3. 덩굴을 성장시키고 손잡이 근처에서 E, 앞쪽으로 올라가는 동안 Space로 이탈한다. 너무 이른 이탈과 너무 늦은 이탈의 허용 범위를 확인한다.
4. 낙하석을 낮은 표식 부근에서 동결한다. 잘못 동결하면 다시 FREEZE 또는 R. 석판은 0° 또는 180°에 가까울 때 동결한다.
5. 회전 장치에 PULSE 후 정렬 순간 FREEZE. 3인칭 카메라에서 클릭 대상·각도·출구를 쉽게 읽을 수 있는지 확인한다.
6. 얼음 활강을 A/D 양쪽 끝까지 조향해도 착지 가능한지, 잎을 다시 탈 수 있는지 확인한다.
7. P05/06에서는 단자 자체가 충돌체이므로 옆으로 돌아 이동한다. 성장 전에는 전도가 막히고 성장 후에만 문/회전 다리에 전력이 도달하는지 확인한다.
8. 높은 곳에서 중앙이나 다음 구역으로 점프해 필수 능력 없이 우회 가능한 곳이 없는지 확인한다. 전 구역의 모든 비정상 궤적은 자동 검증하지 않았다.
9. 추락·R·F8 전환 이후 입력과 체크포인트, 이전 구역 복원 상태가 자연스러운지 확인한다.
10. 마지막 Core에 PULSE하고 출구를 지나 광장으로 걷는다. 바퀴 회전, 입출수, 전체 조망, `Restart world` 버튼을 직접 확인한다.

남은 평가 범위는 실제 마우스 조준/가림, 모든 덩굴 이탈·활강 조향 타이밍, 다양한 화면 비율의 HUD/시야, 우회 시도, 난이도·플레이 시간이다. 환경은 의도적으로 단순 도형의 그레이박스이며 물의 유체 시뮬레이션·최종 미술·음향은 구현 범위가 아니다.
