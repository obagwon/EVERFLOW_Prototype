# EVERFLOW 초행 플레이 안내 개선

후속 능력 이미지·시작 카메라와 UI 재배치는 [능력 UI·시작 연출 보고서](EVERFLOW_Ability_UI_Opening_Report.md)를 참고한다. 이 문서는 안내 작업 당시의 구현·검증 기록이다.

대상은 `Assets/Scenes/Everflow_Map_v2_test_with_puzzle.unity`다. 씬을 열고 **Play → Game View 클릭**으로 확인한다. 안내는 이 씬의 기존 World가 생성하는 전용 컴포넌트에 적용했다. 원본 씬과 FBX, PuzzleLab, 물·배치 정리 에셋, 능력/회로/복귀 규칙은 보존했다.

## 돌아와서 확인할 곳

1. **S 시작 전망대 / A 연못:** 왼쪽 위의 목표와 두 해법, 하단의 세 능력 및 구체 상태를 확인한다. **F1**으로 조작/자동 회수 도움말을 열고 닫는다. 도움말은 게임을 멈추지 않으며 Esc로 일시정지할 수 있다.
2. **A의 뿌리·잎·물살:** 1/2/3으로 능력을 바꿔 조준한다. 한글 대상 이름, 성장·고정·물 동결의 차이, 사용할 수 있는 능력 키, 사거리/몸 앞 가림 안내가 표시된다.
3. **FLOW 장치:** 첫 클릭으로 방향을 열고 **E / Tab / 휠 → 같은 대상 재클릭**으로 확정한다. 선택한 방향과 적용된 방향을 구분해서 보여준다.
4. **D1/D3/D5:** 작업대 접근과 공급 연결을 구분한다. 공급 전에는 덩굴/얼음 해법을 안내하며 부두 잎은 공급 후 지름길이라고 표시한다. D5에서는 내부 물 동결과 어긋난 구조물 고정을 서로 다른 오류로 설명한다.
5. **D2/D4:** 오른쪽 상태판에서 공급·선택된 분기·수문·주 물길 얼음을 확인한다. 수문을 끝까지 연 뒤 주 출구로 전환하고 얼음을 해동하는 다음 행동이 실제 상태에 맞춰 바뀐다.
6. **W 복원 이후:** 연출 중에는 작은 복원 메시지만 남긴다. 조작이 돌아오면 열린 D4 출구와 회랑으로 정원에 걸어갈 것을 안내한다. 정원에서는 탐험/Enter 재시작을 안내한다.

## 구현한 내용

- 화면 위·아래를 넓게 덮던 디버그 HUD를 현재 목표 카드, 능력 카드, 조준 대상 카드, 짧은 알림으로 분리했다. 내부 오브젝트 이름과 `Ready/Flying/Placed/Returning` 표시는 한글 사용자용 이름과 상태로 바꿨다.
- 사거리 밖, 몸 앞 가림, 맞지 않는 능력을 구분한다. 맞지 않는 능력은 가능한 능력과 키를 표시한다. 동결된 물에는 해동, 고정된 구조물에는 고정 해제라는 다른 문구를 쓴다.
- FLOW 선택 패널에서 현재 선택을 강조하고 확정 방법을 계속 표시한다. 능력 변경 시 취소되는 기존 규칙도 안내한다.
- F1 도움말에 시작부터 세 능력을 모두 쓸 수 있다는 점, 한 능력당 구체 하나, 다른 유효 대상 사용과 24m 거리라는 두 자동 이동/회수 조건, 효과 유지, R 복귀를 설명한다. 거리는 실제 World 설정을 읽는다.
- 지하 상태판은 `Supply`, `branch.Direction`, `exitGate.IsOpen`, `mainIce.Frozen`, `StableFor`를 읽는다. 새로운 성공 조건이나 단계 제한을 만들지 않았다. 우회 공급이 실제로 성공하면 사용하지 않는 정상 수로의 얼음 때문에 공급 실패라고 표시하지 않는다.
- 작업대 접근 여부는 기존 `returnWalk.activeSelf`, 구역은 기존 체크포인트, 문/구체/식물 상태는 기존 장치 값을 읽는다. 안내용 별도 완료 횟수나 퀘스트 저장 상태는 없다.
- 주요 목표의 방향과 직선 거리를 작은 표식으로 표시한다. 이는 경로 탐색이나 내비게이션 경로가 아니며, 지형을 통과하는 최단 보행로를 보장하지 않는다.
- 현장 안내·체크포인트·방향 이름을 한글로 정리하고 가까운 구역 위주로 보이게 했다. 목표 이름은 HUD에 모아 중복된 대상 이름이 장치 위에 겹치지 않도록 했다. 게임 판정용 원래 이름/방향 배열은 유지한다.

## Play 검사와 수정

Unity 6000.3.21f1, URP 17.3.0, PC/D3D12의 실제 1920×1080 Game View에서 확인했다.

| 구분 | 결과 / 근거 |
| --- | --- |
| 안내 전용 Play 검사 | 24개 통과. `guidance-validation/runtime-guidance.txt` |
| 뿌리 중심 연속 경로 | 18개 통과. S→A 뿌리→B→G 뿌리→D1→D3 덩굴→D5 우회→D4 뿌리→주 출구→W→정원→Enter. `runtime-route-bloom.txt` |
| 잎·얼음·수차 연속 경로 | 28개 통과. A 잎→C 성장 잎→G 수차→D3 얼음→D5 정렬/고정→D4 수차→주 물길 해동→W→정원→Enter. `runtime-route-alternate.txt` |
| 컴파일 | 실제 Unity 임포트/Play, 별도 Roslyn 런타임·Editor·플레이어 구성 컴파일. 배포 실행 파일 빌드는 아님 |
| 보존 검사 | `preservation-results.json`. 원본/물/배치 정리 에셋, 씬 YAML/GUID, 기존 사용자 변경과 핵심 메서드 비교. 정적 검사이며 Play와 구분 |

안내 전용 검사에서 F1, 능력 선택, FLOW의 첫 클릭·E 선택·두 번째 클릭은 실제 Input System 합성 이벤트를 사용했다. 대상 판독은 실제 레이캐스트를 사용하되 검사용 카메라 위치를 강제로 배치했다. 이후 공급 오류·분기·문·얼음·엔딩 상태는 명시적으로 장치 상태와 플레이어 위치를 설정한 검사다. 이를 보행 완주로 계산하지 않는다.

두 연속 경로는 실제 게임의 이동·카메라·조준·구체·물리·문·엔딩 코드를 합성 키보드/마우스로 실행한다. 강제 순간이동이나 장치 Apply/문 Tick으로 통과시키지 않는다. 정원 도착까지 **137.79초 / 142.14초**였다. 미리 정한 경로를 따르는 unscaled 시간이며 사람의 첫 탐색 실측이나 15~20분 기획 목표 실측값이 아니다.

첫 검증에서 발견하고 수정한 항목:

1. 밝은 지형/하늘에서 F1·보조 조작 문구의 대비가 부족했다. 해당 문구에도 어두운 배경판을 붙였다.
2. F1 도움말 마지막 R 설명이 잘렸다. 문장을 줄이고 전용 글자 크기로 재배치한 뒤 실제 캡처에서 마지막 줄까지 확인했다.
3. 화면 오른쪽 밖에 있는 목표 표식이 일부 잘렸다. 패널 전체 폭을 고려해 가장자리 제한을 보정했다.
4. 구체가 날아가는 동안 능력을 바꾸면 성공 알림이 현재 선택 능력으로 잘못 해석될 수 있었다. 실제 적용 이벤트의 능력 이름으로 표시하도록 바꿨다.
5. 정원 도착 메시지의 “다시 시작하세요”를 재시작 완료 알림으로 잘못 인식할 수 있었다. 실제 재시작 이벤트의 접두어만 구분하도록 수정했다.
6. 문구 줄바꿈이 어색했던 해동/정원 안내를 짧게 정리했다. 도움말은 재시작 시 닫힌 초기 상태로 복구한다.

## 수정 파일과 보존 범위

- `Assets/EverflowMap/Runtime/EFV2Guidance.cs`: HUD·도움말·한글 이름·목표/오류 안내·현장 글꼴과 표시 거리.
- `Assets/EverflowMap/Runtime/EFV2PuzzleWorld.cs`: 기존 OnGUI를 전용 표현 컴포넌트로 옮기고 Awake에 부착 한 줄과 글꼴 읽기 속성을 추가. 기존 게임 메서드 19개 본문은 바이트 단위로 동일하다.
- `Assets/EverflowMap/Editor/EFV2GuidanceChecks.cs`: Play 상태/입력 검사와 캡처.
- `Assets/EverflowMap/Editor/EFV2EditorBridge.cs`, `tools/request_v2_editor.py`: 고정된 `guidance-check` 명령 추가.
- `tools/verify_v2_guidance.py`: 보호 파일·GUID·Git diff와 기존 메서드 본문 비교.

원본 맵/PuzzleLab/FBX, 복제 씬의 YAML, 물 표현과 기존 모델 정리 코드, 캐릭터/입력/카메라 코드, 패키지·URP·빌드 목록은 변경하지 않았다. 테스트 중 임시로 켜진 백그라운드 실행 설정은 마지막 검사에서 작업 시작 값으로 원복한다.

## 남은 확인

- 사람이 처음 접했을 때 경로를 이해하는 시간, 힌트 의존도, 문장 난이도는 실제 초행 사용자 플레이가 필요하다. 자동 경로 완주만으로 초심자 이해를 통과했다고 판단하지 않는다.
- 실제 시각 검증은 현재 PC의 1920×1080이다. UI는 비율을 유지하며 화면 크기에 맞춰 배치하지만, 다른 해상도·글꼴 환경·배포 빌드·다른 그래픽 API는 별도 확인이 남는다.
- 안내를 위한 목표 위치 표시는 단순 직선 방향/거리다. 지하의 모든 우회 보행 경로를 화면에 그리는 기능은 추가하지 않았다.
- 긴 일부 문장의 한국어 자동 줄바꿈과 장치 주변의 모든 카메라 각도는 추가 사용성 검토 대상이다.
