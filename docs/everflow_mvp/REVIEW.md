# 검토와 조치

## 2026-10-17 통합 MVP 자체 검토 (최신)

이번 통합은 단일 에이전트가 구현 후 별도로 diff·새 소스·저장 씬·실행 증거를 검토했다. 독립 에이전트 검토가 아니다. 아래 과거 독립 검토 기록은 이전 회차에 해당한다.

- 수정: P3 첫 계단/펌프 받침대 옆길과 발바닥 접촉 검사 가정. 실제 접근과77개 회귀 PASS 후 통합했다. 충돌 전체 해제/진행 조건 제거는 하지 않았다.
- 수정: 준비 조건으로 자동 엔딩이 발생하던 기존 경로를 MVP의 `mvpFinale`에서 대체했다. 수문 supply는 별도 마지막 제어부이고 준비 requirements에서 수문/최종 제어부를 분리해 순환 조건을 피했다. stage5는 보조 완료 API 대상에서 제외된다.
- 수정: 최종 연결의 먼 가장자리 접촉만으로 횡단 증거를 만들 수 있는 논리적 우회를 자체 검토에서 발견했다. 정비 안전대 및 연결의 정비 측 절반에서 진입한 뒤 먼 데크에 실제 접지해야 한다. 새로운 관찰 지점/짧은 타이밍 조건은 없다. 직접 도달·먼 가장자리 fixture 차단 및 정상 횡단 PASS.
- 수정: 스킵 fixture의 기본 BLOOM 선택, 이동 타깃의 오래된 조준 좌표, 정렬창 경계에서의 검사 지연을 보정했다. 테스트를 통과시키기 위해 게임의 원래 충돌이나 조건을 완화하지 않았다. 최초 실패 로그도 보존했다.
- 수정: Game 캡처에서 새 표지의 과도한 크기/거울 문구를 확인해 짧은 문구·카메라 방향으로 수정했다. 표지 이관은 기존 문구만 대상으로 하고 사용자 편집 문구는 보존한다. 표지 변경 전 byte 백업과 변경 후 캡처를 남겼다.
- 확인: 정상/초반 Space 스킵/후반 공통 완료 API의 완료·물·수문·식생·빛·카메라/입력 상태 일치. 연속 회전 각도/플레이 경과 시간은 비교에서 제외했다. 탐색 복귀 시 조작 복구, 연출 중 예외 낙하/재시작, 반복 새 게임 PASS.
- 확인: 최종249개 Play PASS, 빌드0오류/485경고, 실제 headless player PASS. 원본·P3·공용 자산332개 baseline에 예상 외 변경이 없다. 저장 MVP hash가 최종 검증 stamp와 일치한다.
- 보류: 기존 inference/Sentis 셰이더 경고485개, 빌드 렌더링·수동 완주, 모든 임의 우회/화면 비율·카메라 각도, 초심자 이해도/재미/소요시간. 장식/패키지 교체로 범위를 늘리지 않았다. 예전 원본용 테스트의 타이틀 경로 가정은 최신 통합 검사로 대체하며 역사 파일은 변경하지 않았다.

아래는 과거 시점의 기록이다. 최신 결과는 위와 HANDOFF를 우선한다.

## 2026-10-17 재개 검토

- 실제 저장된 씬·실패 보고서를 재확인했다. P3는 기획 P3+P4 / 실제 UI P4 / stage index3 / `SM_IceSlide` 대상이다. UI P3/index2의 `SM_RotatingBridge`와 혼동하지 않았다.
- R15 실행 확인: `p3-checks-20261017-041754-665.txt`는 출발대에서 first hit가 마지막 계단이고 두 collider 거리가 모두0.199999임을 기록했다. 지정 바닥 직접 검사 수정으로 해당 지지/CP와6개 회귀 fixture가 PASS하여 기존 원인 가설을 실행 증거로 확인했다.
- R16 새 실패: 같은 보고서는 잎 경로 캡슐 이동까지 통과한 뒤 종점의 고정 데크 지지 검사에서 FAIL. 실제 지지는 데크26.00보다7cm 높은 잎26.07이다. 지정 데크 판정을 완화하지 않고 실제 걷기로 잎에서 내려온 뒤 검사하도록 **테스트 가정**을 수정했다. 이 수정 후 이동은 재검증 대기다.
- R17 검증 공백: 기존 검사는 출발대로 텔레포트하므로 계단 머리 걸림/실제 조준을 검증하지 못한다. 별도 `EFCanalApproachChecks.cs`로 실제 spawn→마당→측면 계단→출발대 이동, 낮은/높은 물 타깃의 실제 카메라 레이·키·클릭 검사를 추가한다. 순간이동이나 충돌 비활성화로 통과시키지 않는다. 상단 데크와 계단 겹침의 물리 접근 위험은 실행으로 확인해야 한다.
- 구현 담당과 다른 검토 담당이 새 `IsStandingOn` 변경을 검토하고 격리 회귀 fixture와 실패 진단을 작성했다. 이후 별도 helper의 실제 입력 경로·실패 정리도 독립 검토했고, 호출 runner의 정상/예외 이터레이터 Dispose와 단계별 미실행 표시를 보강했다. 파일 소유권은 WORKLOG 참조. 실제 실패 보고서는 삭제·덮어쓰지 않는다.
- 최신 접근/하차 보강본은 컴파일 통과 후 Play 재실행 대기다. 전체 실행 검증 통과/새 P0 결함0으로 판정하지 않는다. 출구·재시작·최종 입력은 미검증이다.
- 후속 독립 구조 조사: 회전기는 기존 FREEZE 해제·재가동을 지원하지만 A 유지에는 별도 latch/고정 발판이 필요하다. P6 수문을 마지막 입력 뒤 열려면 기존 준비 requirements에서 수문을 분리해야 순환 조건을 피한다. 이 조사는 미구현이며 P3 기술 통과 전 통합하지 않는다.
- R18 실제 Editor 컴파일 실패: 새 helper는 올바른 namespace/internal class/유일 GUID로 존재하고 asmdef 분리도 없으나 Bee의 컴파일 목록에 없다. 사용자 Safe Mode Refresh로 인식 갱신부터 확인한다. 필요하면 기존 검사 파일에 helper를 함께 배치하는 대안이 있으나 아직 적용하지 않았다. 캐시 전체 삭제나 라이선스 변경은 하지 않는다.
- R18 후속: Refresh 불충분으로 helper를 기존 Tests 컴파일 단위에 병합했다. 독립 검토에서 클래스 경계/using/중복 선언 없음과 로직 보존을 확인했고 실제 13:30 Play 보고서로 컴파일 차단 해소를 확인했다.
- R19 실제 접근 차단: 첫 턱 높이≈0.75m가 CC.stepOffset0.55m를 초과했다. 총괄이 첫 계단 시작을 낮추는 사본 한정 수리를 작성 중이다. 측면 계단의 데크 하부 겹침도 피하기 위해 동일 길이/경사로 동쪽 평행 이동한다. 짧게 줄이면 유효 경사가 올라가는 문제는 독립 검토에서 지적하여 평행 이동으로 수정했다. 실제 수리 저장과 이동 재검증은 아직 필요하다.
- 환경/런처 검토: 실제 토큰 계정 차이를 사용해 실패 배치 재실행을 막고, Hub helper와 Editor를 구별한다. 다른 버전/경로 불명 Unity 프로세스도 차단하며 기존 PID·UnityLockfile을 제거하지 않는다. 자체 helper 배타 잠금과 실행 직전 재검사를 추가했고 10개 보호 회귀 검사는 통과했다. 외부 GUI 실행과의 모든 경쟁 조건을 완전히 없앤다고 보장하지 않는다.

검토 담당은 위 최종 수정본과 테스트 도구를 다시 읽고 즉시 확정할 수 있는 신규 P0 진행 차단을 추가로 찾지 못했다고 보고했다. **무결함 보증이 아니며 Unity 실행 없이 물리·시야·재로드 성공을 판단하지 않았다.** 기존 최종 자동 시작은 R07의 미수정 결함으로 남는다.

별도 배정한 테스트 도구는 원본 보존, API 상태 fixture, 실제 잎 캡슐 이동 구간, 2회 사본 재시작을 구분해 기록한다. 전체 경로/카메라 클릭/초심자/빌드를 검사했다고 주장하지 않는다. 소스 검토는 사람 테스트나 물리 진행 성공 증거가 아니다.
