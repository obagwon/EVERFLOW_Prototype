# EVERFLOW 졸업전시 MVP 개선 기획안·실행 계획

작성 기준: 2026-10-16. 기획 초안 v1.1. 실제 Unity 프로젝트·빌드 미제공. 이 문서는 구현 사실을 추가로 확정하는 문서가 아니라, 현재 보고된 상태에 근거한 검증 가능한 작업 명세다.

**추천안: 초반 2개와 잎 슬라이드는 짧고 쉽게 유지하고, 3번 수로·5번 회전 연결기·6번 물레방아를 인과관계가 있는 공간 퍼즐로 확장한다. 먼저 3번 한 구간을 임시 도형으로 검증한 뒤 나머지를 제작한다.** 8~9분은 설계 가설로 유지하되, 첫 완성 기준은 도움 없이 이해하고 끝낼 수 있는 연결된 여정이다. 검증 후에도 분량이 부족하고 가용 작업량이 적으면 5~6분의 완성된 체험을 채택한다.

### 1.3 우선 진단: 원인일 가능성과 먼저 확인할 순서는 다르다

**가장 가능성이 높은 가설은 ‘대상을 찾으면 곧바로 해법을 실행하는 짧은 능력 시연 구조가 남아 있다’이다.** 배경 자료의 초기 구조와 잘 맞지만 현재 씬을 보지 못했으므로 확신도는 중간 이하다. **가장 먼저 검사할 항목은 우회·조기 클리어다.** 이것이 있으면 측정한 분량 자체가 왜곡되기 때문이다.

| 가설 우선순위 | 진단 가설 | 근거 수준 | 확인 방법·판단 |
|---|---|---|---|
| 1 | 능력 한 번이면 해결되는 구조가 남아 있다 | 중간 이하: 과거 배경 자료 p.1이 능력 1회 구조 명시. 현재는 미검증 | 구간별 ‘발견→판단→사용→변화→이동’을 영상에 표시. 한 입력 뒤 남는 판단과 이동이 있는지 확인 |

| 3 | 두 능력을 쓰지만 두 번째 입력이 자동으로 정해져 조합 판단이 없다 | 낮음~중간: 현재 3번은 조합이나 실제 정보 배치는 모름 | 첫 플레이어에게 물이 흐른 뒤 ‘무엇 때문에 다음 행동을 했는가’ 사후 질문. 순서 암기인지 물/높이/출구를 읽었는지 구별 |
| 4 | 퍼즐은 독립된 장애물이고 결과가 다음 공간·최종 목표로 안 이어진다 | 낮음~중간: 보고된 목록만으로 연결은 확인 안 됨 | 이전 결과가 다음 입구에서 보이는지, 플레이어가 최종 목표와 관계를 설명하는지 확인 |
| 5 | 해결과 이동이 분리되어 변화한 지형을 직접 이용하지 않는다 | 낮음: 이동 요소는 보고됐지만 실제 배치 자료 없음 | 해결 후 실제 점프/등반/슬라이드 사용 여부와 고정 우회 보행 경로 존재를 기록 |
| 6 | 세계 회복이 작은 이펙트나 완료 UI로만 보인다 | 낮음: 복원은 요구 방향만 확인 | 소리 없이 영상만 봐도 전후 차이를 찾는지, 플레이어가 무엇이 회복됐는지 말하는지 확인 |

첫 플레이가 길더라도 길 찾기·조작 혼란·반복 추락 때문이면 분량이 충실한 것이 아니다. 반대로 처음 하는 사람도 다음 행동을 스스로 판단하며 빠르게 끝낸다면, 실패를 늘리지 말고 중후반의 상태 변화·공간 관계를 확장한다.

## 2. 추천 개선 방향

### 2.1 채택안: 기존 6요소를 한 물길의 복구 과정으로 묶는다

1~2는 환경 변화와 이동을 배우는 짧은 시작, 3은 ‘작동시켜 만든 상태를 얼려 경로로 바꾸기’, 4는 그 성과를 이용하는 이동, 5는 ‘가까운 길과 먼 흐름을 차례로 연결하기’, 6은 이 규칙을 이용해 최종 운전 위치에 도달하고 물레방아를 직접 재가동하는 종합 구간으로 만든다.

이 안을 고르는 이유는 현재 꽃·덩굴·수로·잎·회전기·물레방아를 재사용하면서, 입력 수 대신 관찰해야 할 높이·방향·연결 상태를 늘릴 수 있기 때문이다. 전 구간 재제작이나 능력 제한 시스템의 신규 도입보다 변경 범위를 제한할 수 있다.

| 분류 | 처리 |
|---|---|
| 그대로 유지 | 이동·추적 카메라, 3능력 의미, 현재 기본 입력, 타이틀/HUD 방향, 너그러운 통과 인정·완료 유지, 꽃의 첫 성공 경험 |
| 배치·안내 수정 | P1·P2의 출구/대상 시야, P4 진입·착지, 랜드마크 재노출, 진행 볼륨, 지역 복구 지점 |
| 기존 퍼즐 확장 | P3 물길과 출구 높이의 관계, P5 연결 상태의 재구성, P6 최종 장치까지 도달하는 인과 |
| 반드시 필요한 신규 작업 | P3 실험 배치, 필요한 지역 상태의 저장/재적용, 최종 수문→물→회전→식생 연쇄, 플레이 기록 양식, 반복 재시작 검사. 기존 기능이 있으면 연결·수정으로 대체 |
| 이번 MVP 보류 | 전투·적·인벤토리·별도 퀘스트·새 능력·전체 유체 시뮬레이션·새 지역·다수 수집품·구체 자원 관리 |
| 구현되어도 줄일 후보 | 의무 회수/재배치가 통과한 길을 무너뜨리는 기능, 전시용 하드웨어, 긴 소개·중간 컷신, 기능 중복 슬라이드, 과도한 광원·파티클, 확장에 쓰이지 않는 구형 퍼즐. 존재부터 확인하고 프로토타입은 보존 |

### 2.2 완료 유지와 우회 방지를 함께 지키는 규칙

아래는 기능 역할 이름이며 실제 클래스명 제안이 아니다.

- **구간 완료:** 한 회차에서 거짓→참으로만 바뀐다. 재진입·추락·능력 해제로 되돌리지 않는다.
- **기계 상태:** 펌프·다리·동결 등 실제 환경 상태다. 미완료 중에는 조절 가능하지만 완료 후에는 안전한 최종 상태를 재적용한다.
- **연출 상태:** 미실행/진행/종료를 별도로 관리한다. 완료 판정과 중복 연출을 분리한다.
- **안전 지점:** 안정된 지면에 실제 도착한 뒤 갱신한다. 높은 곳을 스쳐 지났다는 이유로 갱신하지 않는다.

**일반 성공은 변화한 환경을 이용해 안전한 출구에 도달하는 것. 보조 성공은 그 뒤의 다음 구간 진입부에 도달했을 때 이전 완료를 보정하는 것.** 보조 성공에 정확한 각도·중앙 착지·능력 사용 로그를 다시 요구하지 않는다. 작은 경계 오차로 일반 성공 이벤트를 놓쳐도 같은 완료 처리로 합류한다.

조기 완료는 트리거를 좁혀서 해결하지 않는다. 진행 볼륨을 마지막 장애물 뒤의 넓은 착지·안전 구역 안쪽으로 옮기고, 그 옆에는 출발점과 같은 높이의 우회 지면이 이어지지 않게 한다. 절벽·난간·수로 벽은 보이는 지형으로 만든다. 관통·단순 옆걸음으로 도달한다면 배치 오류다.

예상 밖의 지름길로 안전한 출구에 이미 도달한 회차에서는 완료를 인정하고 되돌리지 않는다. 기록 후 다음 빌드에서 지형을 수정한다. 다른 구역에서 떨어져 트리거 상공만 통과한 경우는 성공과 다르므로, 안전 지면 밖의 낙하는 마지막 안전 지점으로 복구한다. 완료 볼륨은 맵 전체 높이를 덮지 않게 한다.

먼 미래 구역 진입으로 모든 이전 퍼즐을 일괄 완료시키지 않는다. 지역별 인접 관계를 조사해 실제 통과한 구간만 보정한다. 이미 다음 구간에 안정적으로 도착했다면 현재 구간의 기본 능력을 이전 각도 오차로 막지 않는다. 최종 퍼즐의 실제 준비 상태·마지막 PULSE는 별도이며 도달 보정으로 대체하지 않는다.

## 3. 전체 플레이 흐름과 맵 구성

### 3.1 제안 배치의 관계

현재 Everflow_Map의 확정 도면이 아니다. 기존 큰 지형·모델 배치는 최대한 유지하고, 각 구간의 입구·장치·출구·보조 통로를 아래 역할로 정리하는 제안이다.

| 위치·역할 | 진입 시 목표와 시야 | 이동·고저차 | 다음 구간에 남기는 흔적 |
|---|---|---|---|
| 시작 전망대 | 멀리 멈춘 물레방아, 가까이 마른 수로. 거대 풍경보다 회전 날개 실루엣 식별 우선 | 안전하고 넓은 평지에서 시점·이동 확인 | 수로·조형 반복으로 먼 목표와 가까운 길 연결 |
| P1 꽃 / 낮은 단차 | 위쪽 밝은 착지대와 시든 꽃을 함께 보여줌 | 꽃 점프 한 번으로 첫 시야 상승 | 작은 식물 띠가 P2 입구까지 이어짐 |
| P2 덩굴 / 짧은 틈 | 건너편 수로 시설과 끊어진 보행 경로 | 성장한 덩굴을 직접 밟거나 기존 이동 기능으로 통과 | 뿌리가 수로 시설의 기초를 받치는 모습. 새 전도 규칙은 없음 |
| P3 수로 / 측면으로 접힌 공간 | 출구는 건너편 높게, 펌프는 낮게, 경사수로 시작은 옆의 높은 자리 | 펌프→물길 추적→높은 출발점→얼음 도약 | 별도의 좁은 우회 수로로 물이 P4 방향에 도착 |
| P4 잎 / 하강 | 경사 끝의 넓은 착지대와 그 뒤 회전 연결기 | 짧은 슬라이드. 난간으로 조작 부담 낮춤 | 착지 후 뒤를 보면 P3의 얼음과 물이 함께 보임 |
| P5 연결기 / 중앙 테라스 | 가까운 정비 경로와 먼 물레방아 공급선. 첫 위치에서 세부는 일부 가림 | 가까운 연결→중간 지점에서 먼 연결 판단→출구 | 최종 시설의 공급선/준비 표시가 실제 활성화 |
| 최종 접근 / 짧은 전망 | 물레방아 재노출. 지나온 꽃·수로 중 2곳 이상 조망 | 안전한 짧은 연결길 | 앞선 국소 복원과 아직 마른 주 수로의 차이가 보임 |
| P6 물레방아 / 종합 | 낮은 정비 장치, 높은 최종 제어부, 닫힌 주 수문 | 성장 경로→장치 가동→정렬 고정→최종 제어부 도달 | 최종 물줄기가 앞선 수로들과 연결되며 세계 복원 |

권장 흐름은 **시작→꽃→덩굴→펌프·얼음 도약→잎 하강→회전 연결기→물레방아 정비 구역→최종 제어부**다. 동선 길이를 늘리기 위해 S자로 늘이지 않는다. 방향 전환은 다음 장면의 정보가 새로 보이는 지점에만 둔다.

### 3.2 공간의 여유와 안내를 만드는 방법

- 각 퍼즐의 필수 경로 옆에 작은 관찰 여유 공간 1곳 정도를 둔다. 보상 수집 대신 다음 장치의 구조·이전 변화·물레방아를 볼 수 있게 한다. 필수 진행과 구별되는 막다른 전망대로 만들며 새로운 큰 샛길은 만들지 않는다.
- 바위나 벽으로 다음 장치 전부를 숨기지 않는다. 진입 때는 목적지와 막힌 이유, 위치를 바꾼 뒤에는 연결 방식이 드러나게 한다.
- 물레방아는 시작, P2 이후의 상승 지점, P5 출구, 최종 접근에서 다시 보이게 하는 것을 목표로 현 맵을 확인한다. 불가능하면 가장 효과적인 3곳을 먼저 확보한다.
- 연결 구간은 장치 변화가 다음 입구로 도착하는 짧은 호흡이다. 별도 빈 걷기 시간을 배정하지 말고 각 구간 예산에 포함한다.
- 국소 물길은 P3 펌프의 소규모 순환수, 최종 물길은 주 수문의 큰 물줄기로 구별한다. 초반부터 모든 곳에 물이 흐르거나, 얼린 경사로 때문에 최종 주 수로가 막혀 보이는 모순을 피한다. 별도 좁은 홈·관으로 우회 연결을 표현한다.
- 진행 방향은 바닥 흐름선, 실제 성장 식물, 켜진 장치, 소리의 발생 위치로 알린다. 능력 색만으로 모든 정답을 칠하지 않고 형태·운동·아이콘도 함께 쓴다. HUD에는 선택한 능력과 대상이 받을 변화가 보이되 처음부터 전체 사용 순서를 적지 않는다.
- 중간 변화 카메라는 기본적으로 조작을 유지한 채 플레이어 카메라 안에서 보이게 한다. 가려지는 큰 변화만 약 1초 안팎의 선택적 시선 유도 후 기존 추적 상태로 복귀시킨다. 구현 전 카메라 구조를 조사한다.

### 3.3 모델 배치를 보존하는 수정 순서와 낙하 처리

먼저 현재 맵의 화면 캡처에 입구·출구·능력 대상·안전 지점·진행 볼륨을 표시한다. 작은 장치 이동/회전→착지판·바위 추가→보조 수로 추가→구간 입출구 수정 순으로 검토한다. 전체 섬·지형·랜드마크 이동은 마지막 수단이다.

팀원과는 변경 전후 평면·측면 캡처, 옮길 대상, 고정해야 할 지형, 충돌 범위, 물 흐름 방향, 회전축·피벗, 시들음/복원 상태, 카메라에서 가려지는 범위를 합의한다. 장식 배치는 기존 모델의 자식 구조와 프리팹 연결을 조사한 뒤 적용한다.

타 구역으로 떨어지는 지점에는 보이지 않는 긴 벽 대신 낮은 지형·분명한 난간·구간별 낙하 복구 볼륨을 우선한다. 미완료 구간에서 떨어지면 그 구간의 안정된 직전 발판으로, 완료 후에는 해당 출구 안전 지점으로 돌려보낸다. 이전 완료는 유지한다. 후반에 합법적으로 먼저 도착했더라도 전역 능력을 잠그지 않고, 최종 퍼즐의 실제 공급·접근 가능 상태를 안전하게 보정한다. 보정으로 최종 PULSE·엔딩 자체를 실행하지 않는다.

## 4. 퍼즐별 상세 설계

### 공통 수치 검증

이 절의 공간 관계는 제안이다. 좌표·통과 가능성은 확정하지 않는다. 먼저 기본 이동 속도, 실제 점프 최대 높이/수평거리, 꽃 도약 높이/거리, 슬라이드 도약 거리, 캡슐 폭·높이, 경사 제한, 능력 사거리·시야 판정을 측정한다. 정지 점프와 달리기 점프, 꽃과 슬라이드 도약을 별개로 기록한다.

**초기 테스트용 제안값:** 필수 발판 폭은 캐릭터 충돌 폭의 약 2.5~3배부터, 안전 착지 깊이는 그보다 넓게 시작한다. 틈은 해당 이동 방식으로 반복 측정한 안정적인 도달 거리의 약 60~75%부터 시험한다. 높은 발판은 같은 방식의 실제 상승 한계보다 충분히 낮게 둔다. 이는 조작 여유를 만드는 시작값이며 모든 컨트롤러에 통하는 공식은 아니다. 점프 판정·마찰·가속·카메라에 따라 다시 조정한다. FREEZE의 성공을 좁은 프레임·각도 구간에 의존시키지 않는다.

### P1. 꽃: 변화한 환경을 직접 이용하는 첫 성공

**1) 역할·학습.** 이동·시점·BLOOM의 기본 학습. ‘식물을 피우면 통과 지형이 된다’를 가르치고 P2의 성장 경로를 준비한다. 사고 난이도를 올릴 대상이 아니다.

**2) 진입 장면.** 시작 전망대에서 완만하게 내려와 낮은 마당에 진입한다. 앞에는 보통 점프로 닿기 어려운 상단 착지대가 있고, 아래쪽 꽃은 그 착지대 쪽으로 기울어 있다. 꽃과 출구가 한 시야에 들어오게 한다. 물레방아는 멀리 배경에 남긴다.

**3) 해결.** 상단 길 발견→시든 꽃이 닿을 높이를 만들어 줄 것으로 판단→BLOOM→꽃잎 전개·도약 기능 표시→꽃을 밟아 상단으로 이동. 처음에는 이 정도로 직접적이어도 된다. 다른 능력에는 대상이 변하지 않고 짧은 대상 아이콘/건조한 반응으로 알린다. 튕기는 타이밍을 맞추는 추가 입력은 요구하지 않는다. 현재 점프 키 방식이 이미 안정적이면 유지한다.

**4) 공간.** 꽃 앞은 시점 조절이 가능한 안전 마당, 꽃 위는 도약 방향을 읽는 공간, 상단은 넓은 착지대, 그 뒤는 P2를 보는 짧은 평지다. 기존 꽃·바위·착지 지형을 조금 옮기는 것으로 우선 검증한다. 임시 도형은 꽃의 받침 원기둥·성장 전후 판·상단 큐브만 필요하다. 일반 점프로 옆 사면을 걸어오르는 통로는 없게 하되 도약 후 착지는 넓게 받는다.

**5) 판정·복구.** 정상은 상단 안전 구역 도달. 보조는 상단 이후 P2 입구의 넓은 구역 도달. 꽃 위로 지나가는 중간 높이에 완료 볼륨을 두지 않는다. 실패는 꽃 앞 마당으로 복구하고 성장 상태는 유지한다. 완료 뒤 꽃은 계속 핀 안전한 점프대다. 재진입 시 성장 사운드·카메라·완료를 재실행하지 않는다.

**6) 피드백.** 꽃이 실제로 펴지고 주변 작은 식물 띠가 P2 방향으로 이어진다. 부드러운 개화음과 착지음으로 성공을 구분한다. 성장 자체는 추적 카메라 안에서 보이게 하며 강제 컷은 생략한다. 이 작은 식물 띠가 최종 복원에서 더 넓어지는 모습을 재사용한다.

**7) 제작 범위.** 개발: 타깃 안내·도약/착지·완료 유지 검사. 디자인: 시든/개화 상태의 실루엣과 꽃 방향 정리. 최소는 기존 모델의 두 상태·확대 애니메이션·단순 충돌판. 여유가 있으면 잎 흔들림·씨앗 파티클. 리깅 재작업·물리 꽃잎은 비용 대비 보류.

**8) 완료 기준.** 초심자가 꽃을 변화시킨 뒤 스스로 꽃을 밟고 위로 올라가면 통과한다. 위쪽 출구를 못 보거나 BLOOM 성공 후에도 이동 방법을 몰라 다른 능력을 계속 쓰면 안내/시야 설계 실패다. 정상·가장자리 착지·추락 후 재시도·재진입에서 모두 진행이 유지되어야 한다.

### P2. 덩굴: 높이보다 연결 형태를 읽게 한다

**1) 역할·학습.** P1과 같은 BLOOM을 쓰되 ‘위로 튀어오르기’에서 ‘끊긴 경로를 연결하기’로 결과를 바꾼다. P3에서 물이 만들어 줄 이동 경로를 읽는 기초다. 새로운 줄타기·진자 물리는 요구하지 않는다.

**2) 진입 장면.** 꽃 상단에서 짧은 틈과 건너편 수로 시설 입구가 보인다. 시든 덩굴은 틈의 양쪽 받침을 향해 자라다 멈춘 형태다. 출구는 정면보다 약간 옆/위에 있어 성장 방향이 목표와 연결되어 읽히게 한다.

**3) 해결.** 건너편 목표→덩굴의 두 끝이 어디에 걸릴지 관찰→BLOOM→덩굴이 경로를 완성→그 위로 이동. 입력은 한 번이어도 결과의 형태가 P1과 다르다. 성장 순서 암기, 중간 지점 연속 발동은 추가하지 않는다. 현재 구현이 사다리라면 실제 등반을, 다리라면 보행을 유지하고 서로 바꾸는 비용부터 조사한다. 본안의 최소 형태는 안정된 성장 다리/발판이다.

**4) 공간.** 진입 안전대→시든 덩굴→한 번 쉬는 넓은 받침→수로 입구다. 성장 후 중간 받침에서 물레방아 또는 P3 펌프 중 하나를 볼 수 있게 한다. 덩굴 모델의 뻗는 방향·콜라이더만 조정하고, 임시 도형으로는 성장 전 막대와 성장 후 연속 판을 사용한다. 끝부분은 지면과 충분히 겹쳐 보행 끊김을 줄인다.

**5) 판정·복구.** 정상은 건너편 안전대, 보조는 그 뒤 수로 입구. 옆 장식 바위가 틈의 다리 역할을 하지 않는지 점검한다. 떨어지면 덩굴 직전 안전대로, 성장 상태는 유지한다. 완료 후 덩굴은 안정된 경로로 남는다. 능력 회수로 통과한 길이 무너지는 구현이 있다면 완료 후 안전 상태를 유지하는 지역 처리부터 검토한다.

**6) 피드백.** 시작점에서 끝점 방향으로 성장음·잎 확산이 진행된다. 끝이 받침에 붙으며 작은 안착음이 난다. 카메라는 성장 끝과 수로 입구가 보이는 구도로 둔다. 덩굴은 수로를 받치는 뿌리처럼 시각적으로 이어지지만 ‘식물이 전기를 전도한다’는 새 규칙은 부여하지 않는다.

**7) 제작 범위.** 개발: 성장 후 콜라이더·끝단 통과·체크포인트. 디자인: 끝단 접합·성장 방향·안전 발판. 최소는 기존 덩굴+단순 충돌판. 여유는 성장 중 잎 전개. 로프 물리·매달리기·애니메이션 재제작은 보류한다.

**8) 완료 기준.** 초심자가 성장 결과를 길로 읽고 P3로 이동해야 한다. 덩굴에 능력을 반복 사용하거나 꽃처럼 점프하려다 멈춘다면 형태/이동 안내를 수정한다. 짧은 틈 때문에 옆으로 걸어서 해결 과정이 생략되면 지형을 수정하고, 이미 건넌 회차는 진행시킨다.

### P3. 수로: 작동시킨 흐름을 이동 가능한 형태로 바꾼다 — 첫 확장 실험

**1) 역할·학습.** 첫 본격 조합. ‘빈 곳을 얼리는 것’과 ‘물이 생긴 경사로를 얼리는 것’의 차이, 출구 높이·도약 방향의 관계를 판단한다. P4 이동과 P6의 ‘상태를 만든 뒤 고정하기’를 준비한다.

**2) 진입 장면.** 입구는 낮은 정비 마당. 건너편 높은 착지대/출구는 보이지만 직접 점프는 불가능한 관계로 시험한다. PULSE 펌프는 마당 옆, 경사수로의 출발점은 짧은 측면 계단 위, 수로 끝은 출구를 향한다. 입구에서는 마른 수로 전체가 겹쳐 보여도, 옆으로 이동하면 경사와 도착 높이를 분명히 볼 수 있게 한다.

**3) 해결.** (a) 출구가 높고 틈이 있음을 파악한다. (b) 마른 수로와 펌프를 연결하는 관을 보고 PULSE가 먼저 필요한지 판단한다. (c) 펌프 가동 후 실제 물 흐름을 따라 시선을 옮긴다. (d) 흐르는 물 그대로는 지지면이 아니며, 경사수로를 얼리면 출구를 향하는 길이 된다고 판단한다. (e) FREEZE로 넓은 경사 구간을 얼리고, 측면의 짧은 계단으로 높은 출발점에 오른 뒤 슬라이드·도약한다.

의미 있는 판단은 **작동 대상/동결 대상의 구별, 상태의 선후관계, 도약 경로를 만드는 수로의 방향**이다. 물이 생긴 뒤 바로 얼리거나 높은 출발점에서 얼리는 순서 모두 허용한다. 관찰 위치 도달을 숨은 필수 이벤트로 만들지 않는다. 마른 수로 FREEZE는 ‘얼릴 물이 없음’을 짧은 물 모양 아이콘과 마른 소리로 표시하며 자원·진행을 소모하지 않는다. 가짜 정답 수로를 여러 개 추가하지 않는다. 이 구성으로 판단이 생기지 않으면 반복 입력을 추가하지 말고 시야·수로 관계를 먼저 수정한다.

**4) 공간.** 낮은 입구·옆 펌프·측면 계단·높은 출발대·얼릴 경사수로·넓은 도착대·그 뒤 안전 출구로 구성한다. 펌프 조작을 위해 먼 왕복을 시키지 않는다. 입구/계단/출발대를 한 작은 공간 안에 둔다. 현재 펌프·수로·얼음 모델과 착지 지형을 재배치한다. 임시 도형은 펌프 큐브, 얇은 수로 판, 물 표시 판, 얼음 충돌 경사판, 측면 계단, 착지 큐브면 충분하다. 물리 유체·신규 탈것은 필요 없다.

**5) 판정·복구.** 정상은 변화한 경로를 이용한 반대편 안전 착지. 보조는 그 뒤 P4 진입대. 경사 중간이나 착지대 앞의 공중에서 완료하지 않는다. 도착대 옆으로 원래 지면이 이어지지 않도록 지형을 검사한다. 펌프 가동·얼음 생성 후 추락하면 도달했던 높은 출발대로 복구하고 이미 만든 상태는 유지한다. 아직 도달하지 않은 높은 지점을 체크포인트로 미리 열지 않는다. 완료 후 펌프의 국소 물길과 얼음 통로는 안정적으로 남고, 최종 주 수로는 별도 우회 관으로 이어진다. 재진입은 펌프음의 기본 루프만 유지하고 가동/성공 이벤트는 반복하지 않는다.

**6) 피드백.** 펌프 회전→수로에 물이 채워짐→얼음 표면·지지면 생성→도약·착지의 순서가 화면에서 보인다. 가동음/물소리/짧은 결빙음/착지음을 구분한다. 펌프를 누르는 위치에서 물의 첫 도착이 보이게 배치하고, 별도 강제 컷은 우선 생략한다. P4 쪽 작은 수로에도 물이 도착해 ‘여기서 만든 흐름이 이어진다’를 남긴다.

**7) 제작 범위.** 개발: 물 없음/흐름/결빙 상태 연결, 타깃 설명, 경사 충돌·슬라이드·복구, 완료 시 안전 상태. 디자인: 펌프→수로 관, 경사 방향, 얼음 전후 실루엣·착지대. 최소는 기존 모델·두 재질·단순 물 표시. 여유는 도약 잔상·물방울. 위험은 실제 슬라이드 속도/마찰·카메라·콜라이더와 기존 능력 생명주기 충돌이다. 새 물 셰이더 제작부터 시작하지 않는다.

**8) 완료 기준.** 초심자 2~3명 중 최소 2명이 작업자 설명 없이 ‘펌프로 물을 만들고 그 물을 얼려 길을 만든다’를 행동과 사후 설명으로 보여야 한다. 모수가 작으므로 통계적 결론은 아니다. 물을 본 뒤 다음 행동이 안 보이거나, 능력 두 번을 무작정 누르면 자동 통과되거나, 얼음을 만든 뒤에도 점프 위치를 찾지 못하면 수정한다. 우회·끝단 추락·보조 판정·재진입에서 진행 오류가 없어야 다음 확장으로 넘어간다.

### P4. 잎: 해결한 뒤 몸으로 흐름을 느끼는 짧은 구간

**1) 역할·학습.** 새 판단을 많이 추가하지 않는 이동 하이라이트다. P3와 같은 물→얼음 조합을 또 요구하지 않는다. 본안은 기존 잎 슬라이딩을 독립된 짧은 하강으로 사용한다. 실제로 P3와 같은 장치라면 진행 ID를 억지로 분리하지 않고 ‘P3 출구의 P4 이동 구간’으로 묶는다.

**2) 진입 장면.** P3 착지 후 잎 표면이 내리막으로 휘어 있고 끝의 넓은 착지대와 P5 구조물이 보인다. 경사의 끝이 절벽·낭떠러지처럼만 보이지 않게 도착 지면을 보여준다.

**3) 해결.** 잎의 방향과 안전 착지 위치 관찰→입구로 이동→기존 슬라이딩 조작으로 하강→착지. 별도 능력 재사용·열쇠·중간 정밀 점프는 없다. 현재 잎이 탑승체인지 바닥인지 확인하고 동작을 보존한다. 신규 탈것 시스템이 없다면 잎 경사면+기존 이동 처리로 최소 구현한다. 하나의 넓은 경로 안에서 좌우 여유는 허용한다.

**4) 공간.** 출발 안전대·짧은 잎 경사·넓은 착지대·정지 여유·P5 입구다. 경사 양쪽은 보이는 잎 가장자리/바위로 안내한다. 기존 잎을 회전·연장하거나 임시 경사판으로 먼저 검증한다. 속도감을 위해 도착 지면을 좁히지 않는다. 측면이동·카메라 선회 여부에 따라 착지대 폭을 조절한다.

**5) 판정·복구.** 정상은 하단 안전 착지, 보조는 그 뒤 P5 입구. 출발이나 경사 중간 접촉으로 완료하지 않는다. 미끄러지다 빠지면 출발 안전대로, 하단 도착 후에는 하단으로 복구한다. 이미 완료한 P3를 반복하지 않는다. 완료 뒤 잎은 그대로 남고 재탑승 시 성공 연출은 반복하지 않는다.

**6) 피드백.** 이동 시작 잎 마찰음·짧은 바람음·착지 반응. 카메라는 기존 추적을 유지하고 도착대가 시야 밖으로 사라지지 않게 한다. 새 카메라 시스템·긴 시점 전환은 필요 없다. 하단에서 뒤돌아보면 P3의 변화가 보이고 물소리는 P5 쪽으로 이어진다.

**7) 제작 범위.** 개발: 진입/이탈·착지·복구·기존 카메라 튜닝. 디자인: 잎의 경사·난간 형태·착지대. 최소는 기존 잎과 충돌 경사판. 여유는 잎 흔들림·바람. 새 보드 탑승·물리 서핑은 보류한다. P3와 이동감이 완전히 같으면 P4를 더 짧게 줄이고 P5에 제작량을 옮긴다.

**8) 완료 기준.** 초심자가 도착 위치를 예상하고 이동을 즐기며 P5로 진입해야 한다. 추락의 주원인이 카메라·충돌·조향이면 난도를 조정한다. ‘또 똑같이 얼려야 하나’라고 오해하거나 완료 후 입구를 못 찾으면 장면 연결 실패다.

### P5. 회전 연결기: 한 장치로 가까운 길을 만든 뒤 먼 흐름을 연결한다

**1) 역할·학습.** P3의 상태 만들기→고정하기를 공간 재구성으로 확장한다. 새 능력 대신 같은 연결기의 출력 방향이 ‘내가 갈 길’과 ‘최종 시설의 공급’에 각각 어떤 결과를 만드는지 이해한다.

**2) 진입 장면.** 입구 테라스에는 회전 연결기, 가까운 수신부 A, 낮거나 접혀 있는 정비 발판이 보인다. 먼 수신부 B의 관/케이블은 물레방아 방향으로 이어지지만 첫 위치에서는 세부가 일부 가려진다. 정비 발판 너머의 중간 안전 테라스에서 B와 물레방아가 더 명확히 보인다. A/B는 번호 UI가 아니라 형태와 실제 연결선으로 구별한다.

**3) 해결.** 가동 중인 회전기의 에너지/흐름 방향 관찰→A로 연결하면 가까운 발판이 열리는 관계 판단→FREEZE로 넓은 A 방향 구간에서 고정→A 발판 전개·기계 걸쇠 잠김→중간 테라스로 이동→B가 최종 시설로 이어지는 것을 발견→기존 동결 해제로 회전을 재개→B 방향에서 고정→B의 공급선과 출구 경로 연결→출구로 이동한다. 회전기가 원래 자동 가동이면 불필요한 초기 PULSE를 추가하지 않는다. 전원 입력이 기존 규칙이면 그것을 사용한다.

A 발판은 기계 걸쇠로 남기 때문에 B로 바꿔도 지나온 길이 무너지지 않는다. B를 먼저 맞추면 먼 선이 잠깐 반응해 목적을 알려주고 A 발판은 열리지 않는다. 비용·리셋 없이 방향을 바꿀 수 있다. A를 연 뒤 B를 연결하면 완료된다. 순서를 틀렸다는 벌점은 없다. ‘두 번 멈추기’가 아니라 **먼 곳에 가려면 먼저 내 위치와 시야를 바꿔야 한다**는 공간 차이를 만들어야 한다.

본안의 두 단계는 동결 해제/재가동을 안전하게 할 수 있어야 한다. 기존 해제 기능과 구체 제한은 확인 필요다. 해제가 없거나 추가 비용이 크면 이번 MVP에서는 단일 B 연결+넓은 횡단으로 축소하고, A는 고정된 진입 발판으로 둔다. 이 목적 때문에 새 전역 구체 회수 시스템을 만들지 않는다. 이 축소 시 시간 예산도 함께 낮춘다.

**4) 공간.** 입구→A 방향과 회전기를 보는 지점→A 발판→안전한 중간 테라스→B 방향과 물레방아를 보는 지점→고정된 연결기/출구 경로→출구 안전대다. FREEZE 해제는 움직이는 물체 위가 아닌 중간 고정 테라스에서 수행하게 배치한다. 회전기·관·기존 돌판 재배치가 우선이다. A 발판은 큐브의 접힘/전개 두 자세로 검증한다. 회전 출력은 큐브 화살표·가느다란 선으로, B 반응은 작은 발광판으로 시험한다.

**5) 판정·복구.** 정상은 B가 연결된 상태에서 안전 출구 도달. 허용 방향은 좁은 목표각이 아니라 실제 연결면이 넓게 겹치는 구간으로 잡고, 멈춘 뒤 부드러운 정렬 보조를 허용한다. 인접한 전혀 다른 출력까지 자동 정답 처리하지는 않는다. 보조 출구 도달은 기존 원칙대로 완료를 보정하고 A 걸쇠/B 최종 연결을 안전 상태로 적용한다. 그 후 되돌리지 않는다. 완전 우회라면 배치 오류로 기록한다. 추락은 마지막 고정 테라스로, A 걸쇠는 유지한다. 완료 후 회전기는 B 방향으로 안정화되고 재가동 입력으로 최종 공급이 끊기지 않는다.

**6) 피드백.** A 때 발판 움직임·걸쇠 ‘철컥’ 소리, B 때 먼 공급선에 진행하는 빛/물과 물레방아 시설의 준비 표시. 마지막 큰 수문은 아직 닫혀 있어야 한다. A 변화는 가까이 직접 보고, B 변화는 테라스 시야 안 또는 아주 짧은 시선 유도로 보여준다. 단순히 전체 기계가 밝아지는 것보다 빛/물이 어디까지 도착했는지 보이게 한다.

**7) 제작 범위.** 개발: 출력 분기·A 걸쇠·재가동·B 상태·완료 안정화. 디자인: 연결 방향을 읽는 관·수신부·발판, 걸쇠 모양. 최소는 기존 회전 모델+판/큐브+선 발광. 여유는 케이블 맥동·걸쇠 애니메이션. 위험은 현재 회전/동결 구조와 2단계 상태 충돌이다. 가장 먼저 축소 가능한 확장이고 P3 검증 전 모델링하지 않는다.

**8) 완료 기준.** 초심자가 A는 가까운 이동, B는 최종 시설 공급이라는 서로 다른 결과를 설명해야 한다. 같은 대상에 아무 방향으로 두 번 누르면 끝나거나, B 전환으로 지나온 길이 사라져 돌아가야 하면 실패다. 정확한 각도 오차로 출구 도달 후 재시도시키는 회귀가 없어야 한다.

### P6. 물레방아: ‘마지막 버튼’에 도달하는 과정이 종합 퍼즐이다

**1) 역할·학습.** BLOOM은 접근 경로, PULSE는 움직일 상태, FREEZE는 안전한 연결을 만든다. 이 결과를 직접 건너 최종 제어부에 도달한다. 입력 후의 복원 영상과 구분한다.

**2) 진입 장면.** 멈춘 거대한 바퀴와 닫힌 주 수문, 낮은 정비 구역의 시든 뿌리, 움직일 도수판/기계 연결부, 높은 최종 제어부가 보인다. P5에서 이어진 공급선은 정비 구역까지 살아 있지만 주 수로는 아직 마르다. 최종 제어부의 위치 때문에 정비 경로가 필요한 것이 보이게 한다.

**3) 해결.** 높은 최종 목표 관찰→BLOOM으로 낮은 정비 구역에 이르는 뿌리 경로 성장→직접 건너가 PULSE로 정비 장치 가동→도수판/다리의 움직임과 최종 제어부 방향 관찰→FREEZE로 넓은 연결 구간에서 고정→안전 연결을 직접 건너 최종 제어부 도달→최종 PULSE. 처음 PULSE는 정비 모터만 움직이고 주 수문을 열지 않는다. 마지막 PULSE가 실제 수문 구동을 수행한다. 정비 장치가 없는 현재 구현이라면 기존 회전 연결기 축소 재사용이 신규 거대 모델보다 우선이다.

**4) 공간.** 입구·성장 경로·정비 안전대·움직이는 연결부·높은 제어 안전대·엔딩 전망 위치다. 최종 제어부는 입구에서 사거리/가림 관계상 바로 발동되지 않게 실제 구조를 구성한다. 단순 원거리 저격으로 종합 과정이 생략되면 제어부의 위치·기계 덮개·접근 지형을 수정한다. 보이지 않는 제한 구역만 추가하지 않는다. 뿌리/덩굴·회전 연결기·수문 판·원기둥 바퀴로 최소 검증한다.

**5) 판정·복구.** 성장·정비 가동·안전 연결·제어부 접근은 각각 보존한다. 추락은 마지막 안정된 정비/제어 안전대로 복구한다. **제어부 도달은 최종 완료가 아니다.** 마지막 PULSE는 실제 공급·안전 연결이 준비된 상태에서만 수락한다. 준비 부족은 불빛이 끊긴 관·정지한 장치로 원인을 보여주고 입력을 소비하지 않는다. 예상 밖의 통과로 이미 제어부에 도달했다면 작은 각도 차이는 안전 상태로 보정하고, 마지막 입력은 남겨 둔다. 완료·연출 중 재입력은 재시작을 일으키지 않는다.

**6) 피드백.** 뿌리는 접근로, 정비 모터는 움직임, 고정은 걸쇠 체결과 최종 제어부까지 이어지는 표시로 각각 결과를 다르게 보여준다. 다음 절의 수문→물→바퀴→식생이 최종 피드백이다. 앞선 구간의 밝아진 선/식물/물길이 엔딩 조망에서 다시 보인다.

**7) 제작 범위.** 개발: 기존 세 기능 연결·최종 준비 조건·단발 연출·초기화. 디자인: 수문·도수판의 피벗·뿌리 접합·물레방아 회전축·전후 식생. 최소는 기존 식물/회전 모델 재사용, 수문 판의 단순 이동, 바퀴 회전. 여유는 복원 파동·음악 전개. 위험은 물리 힘으로 물레방아를 실제 가동하려는 구현, 다수 시뮬레이션, 거대한 신규 리깅이다.

**8) 완료 기준.** 초심자가 세 입력을 이유 없이 순서대로 누르는 대신 ‘경로를 만들어 장치를 가동하고, 움직이는 길을 고정해 마지막 장치로 간다’를 이해해야 한다. 최종 도달만으로 엔딩이 뜨거나, 마지막 빛만 보고 물·바퀴 변화를 못 알아차리면 미완료다. 건너뛰기·재시작을 포함해 한 회차 엔딩은 한 번만 실행되어야 한다.

## 5. 최종 물레방아와 복원 연출

### 5.1 퍼즐의 인과와 연출 시작 조건

최종 퍼즐은 **뿌리 성장으로 정비 장치에 접근→PULSE로 연결부 가동→FREEZE로 제어부에 이르는 경로 고정→직접 횡단→최종 PULSE**다. 마지막 제어부는 단순 체크리스트의 세 토큰을 검사하지 않고, 정비 공급과 안전한 연결이 실제 준비된 상태인지 확인한다. 구현에서 이 조건은 지역 상태로 표현하되 존재하지 않는 클래스명을 전제하지 않는다.

최종 PULSE가 수락되는 순간에 한 회차의 ‘복원 시작’을 단 한 번 기록한다. 그 뒤 물 파티클이 카메라에 보이지 않거나 특정 애니메이션 콜백이 누락되어도 논리적 복원은 끝나야 한다. 연출 종료 시 적용할 최종 상태를 별도로 두고 정상 종료·건너뛰기·복구 모두 같은 상태로 합류한다. 최종 완료를 어디서 기록할지는 기존 진행 구조를 조사하되, 도달만으로 완료되는 경로는 두지 않는다.

### 5.2 정상 관람 약 30초의 초안

아래는 제안 타이밍이다. 연출 길이를 맞추기 위한 강제 대기는 없으며, 보인 결과를 이해하는 데 필요한 만큼 테스트로 줄인다. **시작부터 건너뛰기를 허용**하고, 건너뛴다고 퍼즐 결과가 생략되지는 않게 한다. 실제 키는 기존 입력 충돌을 확인한 뒤 화면에 표시한다.

| 단계·초안 시간 | 발생 조건 | 화면 변화 | 카메라·조작 | 중복·건너뛰기 처리 |
|---|---|---|---|---|
| ① 마지막 입력·장치 반응 0~1초 | 준비된 제어부에 최종 PULSE 수락 | 제어부에서 수문까지 맥동이 이동. 즉각 낮은 구동음 | 안전한 제어대에서 이동/능력 입력 잠금. 기존 카메라·입력 상태 보관 | 시작 기록을 먼저 잠금. 중복 PULSE 무시. 건너뛰기는 즉시 최종 상태 적용 |
| ② 주 수문 개방 1~4초 | 복원 시작 | 큰 수문 판이 들리고 뒤의 물 표면이 드러남 | 제어부와 수문을 함께 보여주도록 이동 | 한 번만 개방. 스킵 시 열린 자세 고정 |
| ③ 물길 연결 4~8초 | 수문이 물 출구를 드러냄 | 주 수로를 따라 물 표시가 구간별로 이어져 바퀴 낙수구에 도착 | 카메라가 물의 출발·도착을 따라 짧게 이동 | 파티클 충돌 이벤트가 아닌 연출 상태/시간으로 도착 보장 |
| ④ 물레방아 회전 8~12초 | 논리적으로 물이 바퀴에 도착 | 정지→느린 회전→안정된 회전, 낙수와 바퀴음 | 물줄기와 바퀴 축을 한 화면에 배치 | 회전 루프는 하나만 유지. 스킵 시 즉시 안정 속도 |
| ⑤ 주변 세계 회복 12~18초 | 바퀴 회전 개시 | 주 수로에서 가까운 식생→먼 식생으로 복원, 조명/문양이 연결 | 넓어지는 구도로 변화의 전파 표시 | 구간당 복원 이벤트 한 번. 이미 핀 P1/P2는 리셋 없이 주변만 확대 |
| ⑥ 지나온 길 조망 18~26초 | 복원 최종 상태 준비 | 앞선 꽃·수로·연결기 등 실제 보이는 2~3곳을 물레방아와 함께 조망 | 비용이 큰 전체 맵 투어 대신 1개 넓은 구도. 계속 건너뛰기 가능 | 숨은 장소까지 무리하게 한 화면에 넣지 않음. 스킵 시 동일 최종 구도/종료 UI |
| ⑦ 종료 안내 26~30초 | 정상 관람 종료 또는 스킵 | 복원 상태 유지, 간단한 종료 문구와 다시 시작 안내 | 게임 입력은 종료 상태로 전환, UI 입력 활성화·커서 상태 설정 | 종료 UI 단일 인스턴스. 이후 재시작만 새 회차를 생성 |

화면 밖 식생 변화는 엔딩 구도가 실제로 보여줄 구역부터 제작한다. 전체 맵의 모든 오브젝트를 한꺼번에 변환하지 않아도, 물이 이어지는 경로와 대표 지점의 전후 차이가 읽히면 최소 목표를 달성한다. 조명은 과한 전체 밝기 상승보다 장치 발광·식생 색·물 표면·국소 보조광으로 먼저 구성한다.

### 5.3 물과 기계의 최소 구현

| 표현 | 최소 구현 | 보완 시 | 피할 비용 |
|---|---|---|---|
| 수문 | 기존 판/모델을 정해진 두 자세 사이로 이동 | 물 뒤 실루엣·기계 소리 | 유체 압력과 실제 수문 물리 연동 |

렌더 파이프라인·기존 물 재질은 확인 필요다. 기존 효과가 있으면 재사용하고, 이 계획을 위해 외부 에셋 구매나 패키지 도입을 전제하지 않는다. 화면 효과와 플레이 충돌판은 분리해, 물 표시의 활성/비활성 때문에 바닥이 사라지지 않게 한다.

### 5.4 연출 중 입력·추락·초기화

- 마지막 입력은 고정된 안전 제어대에서 받는다. 이동 입력을 잠그기 전에 현재 속도와 플레이어 지지 상태를 조사·안정화한다. 기존 컨트롤러를 모른 채 강체 설정을 일괄 변경하지 않는다.
- 연출 중 WASD·점프·능력·마우스 회전은 게임 장치를 다시 작동시키지 않는다. 건너뛰기/UI 입력만 받는다. 입력 해제는 연출 시작 전 상태 복원 또는 종료 UI 상태 전환으로 명확히 처리한다.
- 예외 낙하/물리 오류가 생겨도 퍼즐을 되돌리지 않는다. 안전 제어 위치로 복구하고 연출을 계속하거나 최종 상태로 합류한다. 외부 일시정지/포커스 복귀에서 카메라와 잠금이 남지 않는지 확인한다.
- 건너뛰기는 진행 중 이동·카메라·음향 전개를 정리하고 수문 열림·물 표시·회전·식생·완료·종료 UI를 한 번에 일치시킨다. 장면만 건너뛰고 결과 상태가 반만 남아서는 안 된다.
- 새 게임/전시 재시작은 구간 완료, 보조 도달, 안전 지점, 펌프·얼음·걸쇠·뿌리·수문·바퀴, 식생·재질·빛, 연출 잠금·대기 중 콜백·사운드 루프, 카메라·커서·일시정지 상태까지 초기화한다. 기존 상태 관리자·정적 변수·저장 데이터의 범위를 조사한다.
- 가장 단순하고 안정적인 재시작 경로를 우선한다. 씬 재로드로 충분한 구조라면 이를 쓰되 정적 상태/구독이 남는지 검사한다. 복잡한 범용 세이브 시스템을 새로 만들 필요는 없다.
- 정상 엔딩, 연출 초반 스킵, 후반 스킵, 중간 퍼즐 도중 재시작, 새 게임 직후 첫 꽃 사용을 포함해 최소 3회 연속 회차를 확인한다. 별도 운영자 재시작 조작은 능력 키와 충돌하지 않게 설정한다. 무입력 자동 초기화는 전시 운영 방침이 정해진 후 선택한다.

## 6. 플레이 시간 예산과 사용자 테스트

### 6.1 8~9분의 위치와 산정 근거

현재 확인된 측정은 사용자가 보고한 ‘개발자 전체 플레이 2분 미만’뿐이다. 첫 플레이 평균·중앙값·완주율은 없다. 타이틀/로딩/엔딩이 그 측정에 포함됐는지도 확인해야 한다.

아래는 **확장안이 만들어진 뒤 검증할 설계 예산**이다. 실제 측정치·예상 평균으로 읽으면 안 된다. 초반은 짧게, P3·P5·P6의 경로/상태 해석에 시간을 배정했다. 최종 복원 정상 관람은 30초이며 스킵하면 그만큼 짧아진다. 실패는 필수 콘텐츠가 아니며 예산 16초는 소규모 실수의 여유일 뿐이다.

각 구간 이동에는 다음 입구까지의 짧은 연결길을 포함한다. ‘최종 접근’은 P5 이후 전망 구간만 별도 계산한다. 같은 행동을 두 열에 중복 계산하지 않는다. 실패가 없으면 494초=8분 14초, 최종 연출을 일찍 건너뛰면 더 짧아진다. 이는 산술 결과이지 실제 플레이 예측이 아니다.

가장 불확실한 수치는 P3·P5·P6에 합계 163초를 배정한 관찰·판단이다. 공간이 이 판단을 실제로 만들지 않으면 8~9분은 성립하지 않는다. 타이머·강제 대기·힌트 지연으로 채우지 않는다. 현재 개발자 기록과 510초를 빼서 ‘추가로 몇 초만 만들면 된다’고 계산할 수도 없다. 숙련도와 포함 범위가 다르기 때문이다.

참고로 과거 v1.0 p.12의 구간별 최소/최대 시간을 합산하면 **440~630초=7분 20초~10분 30초**다. 문서의 ‘8~9분’ 표기는 검증된 범위가 아니라 당시 중앙 목표에 가깝다.

### 6.2 이 예산을 성립시키는 실제 콘텐츠 변화와 축소안

8~9분을 검증하려면 최소한 P3의 물/높이 해석, P5의 두 위치에서 연결 관계 재해석, P6의 접근→가동→고정→횡단을 실제로 만들고, 서로 연결된 결과를 보여야 한다. 설명문·컷신만 붙여서는 이 예산을 정당화할 수 없다. 숙련 개발자가 여전히 빠른 것은 허용한다.

**5~6분 축소안의 중앙 목표 예시:** 시작 25 + P1 25 + P2 30 + P3 60 + P4 30 + P5 45 + 최종 접근 15 + P6 75 + 복원 25 = **330초=5분 30초**. 이 또한 측정 전 가설이다. P5를 단일 연결로 줄이고, P3는 한 경사로, P6는 같은 인과를 좁은 공간에 배치하며, 큰 전맵 복원 대신 보이는 대표 지점만 연출한다. 정상 진행·완료 유지·최종 수문/물/회전은 줄이지 않는다.

현재 자원으로 어느 목표가 현실적인지는 코드 상태와 가용시간을 봐야 한다. 제작 가능한 작업량이 본안의 하한보다 작거나 P3 검증 후에도 판단이 생기지 않으면, 8~9분 약속을 고집하지 않고 축소안을 채택하는 것이 추천이다.

### 6.3 측정 방식

1. 같은 빌드·같은 시작 상태에서 개발자 보통 플레이를 기록한다. 최단 경로 스피드런은 별도 표기한다. 처음 조작 가능한 시점→최종 PULSE 수락을 플레이 시간, 그 뒤 종료 안내까지를 연출 시간으로 분리한다. 타이틀·로딩·설정 시간은 별도 기록한다.
2. 처음 하는 사람 2~3명을 대상으로 설명 없는 첫 플레이를 기록한다. 퍼즐 해법을 알려주지 않고 키보드·마우스 사용 가능 여부만 확인한다. 게임 경험·이전 EVERFLOW 노출 여부를 적는다. 기본 화면 안내 자체가 시험 대상이다.
3. 플레이 중 계속 생각을 말하게 하면 시간이 늘 수 있으므로 기본은 조용히 플레이하고, 직후 영상의 멈춘 위치를 짚으며 이유를 묻는다. 기록자가 관찰 시간을 추정했음을 표시한다.
4. 주 행동은 학습/판단/이동/실패복구/연출 중 하나로 분류한다. ‘길 잃음·조작 혼란·버그·도움’은 추가 태그로 기록해 총합에 다시 더하지 않는다. 프레임 수준 정밀 측정은 필요 없고 영상 시각과 구간 경계가 일치하면 된다.
5. 테스트 시작 전 도움 기준을 정한다. 예: 같은 행동을 반복하며 약 45~60초 동안 진행이 전혀 없거나 도움을 요청하면 관찰을 마치고 목표만 짚어준다. 이는 초기 테스트용 운영값이지 정답을 늦게 주는 게임 규칙이 아니다. 도움 시점·말한 내용을 기록하고 이후 구간은 ‘도움 후’로 구분한다.
6. 동일한 사람이 개선본을 다시 하면 학습 후 재플레이다. 첫 플레이 시간과 섞지 않는다. 가능하면 개선본은 새 참가자 2~3명에게 확인한다. 추가 참가자가 없으면 개선본의 첫 플레이 시간은 미검증으로 남기고, 기존 참가자로 동작/회복/연결 이해만 검사한다.

### 7.3 디자이너가 지금 병행할 일과 검증 뒤 할 일

**지금 가능:** 현재 FBX·프리팹·텍스처·충돌/피벗 목록, 꽃/덩굴 성장 전후 확인, 수로/관 모듈 정리, 회전축 수정 필요 표시, 물레방아 실루엣 점검, 수문 이동 가능한 분리 여부, 복원 색감 소규모 샘플. 개발자의 기준 맵 캡처 위에 시야 표시도 병행한다.

**구간 검증 후:** P3 경사수로 길이·도약대·착지 구조 모델 확정, P5 A/B 수신부와 걸쇠, 최종 정비 구조/뿌리 경로, 연출 카메라에 보이는 복원 식생 배치. 임시 도형의 통과 검증 캡처·크기·피벗을 전달받은 뒤 만든다. 개발자는 모델이 오기 전 기능 검증을 계속하고, 모델 교체 뒤 해당 이동·충돌 경로만 재검사한다.

## 8. Codex CLI에 전달할 작업 단위

### 모든 작업에 적용할 계약

- 실제 클래스·컴포넌트·이벤트·입력 키를 먼저 찾고 경로와 관계를 기록한다. 아래 역할 이름을 기존 코드명으로 간주하지 않는다.
- 원래 씬/프리팹·사용자 변경을 보존하고, 승인된 한 구간만 수정한다. 대규모 리팩터링·패키지 교체·전체 맵 재배치는 하지 않는다.
- 너그러운 완료·보조 통과 인정·완료 유지·최종 도달 자동 완료 제외를 공통 보존 조건으로 둔다. 버전/타이틀/HUD/카메라 등 무관한 기존 동작도 보존한다.
- 검증 보고는 정적 확인, 컴파일/Editor, 실제 플레이, 빌드 실행을 구별한다. 실행할 수 없으면 ‘실행 미검증’이라고 적는다. 코드를 읽었다는 이유로 퍼즐 동작 완료를 선언하지 않는다.
- 문서는 새로 제안하는 `docs/everflow_mvp/` 아래에 남긴다. 실제 저장소의 기존 문서 규칙이 있으면 그 구조를 우선한다. 각 작업에서 변경 파일·씬, 사용법, 검증 결과·증거, 미확인·위험, 원복 방법을 기록한다.

### C00. 현황 조사·기준 보존

- 목표·조사: 네 씬과 능력→대상→진행→복구→엔딩→새 게임 연결을 실제 경로로 파악한다.
- 수정 범위: 문서·안전한 실험 사본 준비만. 기능 수정은 다음 단위다.
- 보존: 미커밋 변경·원본 맵·빌드 목록. 구형 씬 삭제 금지.
- 검증·완료: 6요소의 실제 ID/위치/사용 순서/보조 완료 지점/모델 상태를 표로 작성. Unity 가용성과 측정할 수 없는 값을 표시한다.
- 문서: `00_baseline.md`, 현재 정상 경로·우회 후보·P3 재사용 가능 구조.

### C01. P3 한 구간 임시 도형 확장

- 목표·조사: 펌프·물 FREEZE·슬라이드·착지·완료를 조사해 4절의 P3 관계를 구현한다.
- 수정 범위: 실험 씬의 P3, 필요한 지역 기능과 테스트 배치. 원본 전체 맵은 바꾸지 않는다.
- 보존: 이동 수치·카메라·입력·P1/P2/P4~P6·기존 완료 원칙.
- 검증·완료: 물 없는 동결 시도, 정상 순서, 얼리는 위치의 다른 순서, 추락·재진입·보조 완료·우회 검사를 수행/미수행으로 구분한다. 사용자 이해는 별도 미검증 항목이다.
- 문서: `01_p3_prototype.md`, 실험 씬 여는 법·상태표·튜닝 값·영상/수동 검사 항목.

### C02. P3 검증 결과 반영

- 목표·조사: 기록 양식·영상에서 막힌 위치와 이유를 정리한다.
- 수정 범위: P3 대상/출구 시야·출발대·안내·복구 중 원인이 확인된 항목만.
- 보존: 빨리 끝난다는 이유로 속도·판정·강제 대기를 변경하지 않는다.
- 검증·완료: 수정 전후 원인별 사례 비교. 같은 참가자는 학습 후 검사로 표기. T04 통과/재작업/축소 결정을 기록한다.
- 문서: `02_p3_validation.md`, 참가자 익명 기록·변경 이유·남은 가설.

### C03. 초반과 잎 구간 정리

- 목표·조사: 꽃/덩굴의 실제 이동 타입, 잎이 P3와 분리된 기능인지 조사한다.
- 수정 범위: P1/P2/P4의 시야·착지·복구·진행 볼륨. 필요하면 진행 ID 통합 제안과 참조 영향 먼저 기록한다.
- 보존: 짧고 쉬운 첫 성공, 현재 이동 동작, 완료 이후 경로 유지.
- 검증·완료: 각 정상/가장자리/추락/보조 통과와 P3 연결 확인.
- 문서: `03_early_traversal.md`, 실제 입력·오브젝트 위치·성공/보조 조건.

### C04. P5 회전 연결 확장

- 목표·조사: 회전·FREEZE·해제·출력 전달·기존 각도 판정 조사.
- 수정 범위: A 걸쇠·중간 안전대·B 공급. 해제 구조가 불가하면 단일 B 구성으로 범위를 명시해 축소.
- 보존: 완료 후 되돌리기 금지, 넓은 방향 허용, 지나온 A 발판 유지.
- 검증·완료: B 먼저 시도, A→B, 해제 중 낙하, 완료 뒤 재입력, 보조 통과를 검사. 실제 성공각/면 관계는 측정 근거를 남긴다.
- 문서: `04_connector.md`, 상태 전이·축소 여부·해제법·실제 수치.

### C05. 최종 퍼즐까지만 연결

- 목표·조사: P5 공급과 기존 최종 PULSE·엔딩 호출·물레방아 모델 구조 조사.
- 수정 범위: 성장 경로→정비 가동→고정 경로→최종 제어부. 엔딩은 최소 완료 표시까지만 연결.
- 보존: 마지막 직접 입력 필수, 이미 통과한 길/퍼즐 완료 유지.
- 검증·완료: 최종 도달만으로 엔딩 없음, 준비 부족 피드백, 정상 입력 단발, 중간 복구.
- 문서: `05_final_puzzle.md`, 제어부 조건·실제 호출 관계·사용법.

### C06. 복원 연출 최소본

- 목표·조사: 현 물 재질·렌더 파이프라인·카메라 전환·사운드·초기화 조사.
- 수정 범위: 수문→물 메시→바퀴→대표 식생→조망→종료 UI, 스킵·중복 방지.
- 보존: 게임 입력·카메라 정상 복귀, 정상/스킵 최종 상태 일치.
- 검증·완료: 정상·연속 입력·초반/후반 스킵·예외 낙하·포커스 복귀 확인.
- 문서: `06_restoration.md`, 단계·소요·스킵·최종 상태·미검증.

### C07. 실제 맵과 아트 통합

- 목표·조사: 실험 씬과 실제 Everflow_Map 차이, 프리팹·피벗·스케일·콜라이더 조사.

- 보존: 팀원 배치·참조·원본, 프로젝트 스타일. 큰 지형 변경 전 영향 문서화.

- 문서: `07_map_integration.md`, 이동/교체 자산·디자이너 확인점·성능 후보.

## 10. 결정에 필요한 핵심 확인 질문

질문의 답이 없어도 위 초안으로 조사·P3 실험을 시작할 수 있다. 답을 받으면 다음 설계를 확정한다.

1. **현재 Everflow_Map의 정상 플레이 영상과 위에서 본 배치, 특히 P3~P6의 위치 관계는 어떤가?** → 전체 지형을 옮길 필요 없이 가능한 시야·입출구·우회 차단 위치와 정확한 작업량이 달라진다.
2. **능력 효과는 영구/일시 중 무엇이고, FREEZE를 해제·재사용하거나 여러 대상을 동시에 유지할 수 있는가?** → P5의 두 단계 연결 채택 여부와 완료 후 안전 상태 처리 방식이 달라진다. 새 구체 제한을 도입하자는 질문이 아니다.
3. **P3와 P4는 실제로 독립된 이동 구간인가? 잎은 바닥인가 탑승체인가? P5는 전력/물 중 무엇을 연결하는가?** → 진행 ID·반복 슬라이드 축소·공급선 표현과 최종 퍼즐 재사용 범위가 달라진다.
4. **개발자 2분 기록의 시작·끝은 어디이고, 처음 하는 사람을 몇 명·언제 테스트할 수 있는가?** → 현재 분량 판단과 8~9분/5~6분 목표 선택의 근거가 달라진다.
5. **실제 전시/중간 점검 마감과 두 사람의 주당 가용시간, 전시 PC·프로젝터 조건은 무엇인가?** → 작업 범위·달력 일정·그래픽 품질을 정한다. 답이 없을 때 특정 날짜나 성능을 보장하지 않는다.
