# P3 수로 실험 — 소스·생성 도구

2026-10-17 현재 상태: **실험 씬 생성·저장 및 Editor 재오픈 참조 검사는 완료. 최신 Play는 runtime30개 통과 후 잎 종점 고정 데크 지지에서 실패했다.** 출발대 지지 수정·6개 지원 회귀·잎 경로 이동은 통과했다. 이후 실제 하차 보행과 계단 접근·카메라 레이 입력 검사를 보강했다. 최신 소스는 별도 컴파일을 통과했지만 Unity 시작에서 새 helper가 컴파일 목록에 빠진 CS0103을 확인하여 Safe Mode Refresh로 재발견을 요청한 상태다. 아래 좌표는 코드 설정값이며 실제 이동 측정값이 아니다. 최신 결과는 HANDOFF/VERIFICATION을 우선한다.

## 원본과 실험의 관계

- 원본: `Assets/Scenes/Everflow_Map.unity` (변경하지 않음).
- 실제 생성된 사본: `Assets/Scenes/Everflow_Map_P3_DesignTest_20261016.unity` (2026-10-16 22:28:50 KST 저장).
- 역할 P3는 실제 Map의 stage index 3/UI P4다. 전역 진행 ID와 원래 꽃·덩굴·낙하발판·회전다리·문을 재번호화하지 않는다.
- P3/P4는 기존 물·얼음·나뭇잎 이동을 함께 사용하므로 두 번의 새 퍼즐로 분리하지 않았다. 사본의 시작부터 수로까지는 기존 경로다.
- 공유 자산을 Apply하지 않고 사본의 모델 인스턴스 Transform override와 새 임시 도형만 사용한다.

| `Editor/EFCanalExperimentSetup.cs` | 원본 구조 검사→SaveScene(saveAsCopy)→사본 편집→참조/캡슐 여유 검사→사본 저장 |
| `Editor/EFCanalExperimentTests.cs` | 저장된 사본의 참조·API fixture·잎 이동 구간·재시작 검사 도구. 실제 실행은 실패 단계까지만 완료 |
| `Editor/EFCanalApproachChecks.cs` | 실제 계단 이동·자동 카메라 조준·Player 키/클릭 검사. 실행 대기 |

펌프는 `SM_PowerSource_P4`, 수문은 `SM_WaterGate_P4`, 물/얼음은 `SM_IceSlide`다. 기존 source→gate→water 공급 참조와 기존 5개 ridePath/잎 이동을 재사용한다. 낮은 집수조와 높은 수로는 동일 Water receiver에 연결되어 어느 쪽에서 얼려도 같은 상태가 된다. 관찰 지점 방문 플래그는 없다.

## 상태·완료·복구

- 마른 수로 FREEZE는 기존 CanApply에서 거부하며 진행·자원을 소비하지 않는다.
- PULSE→수문 애니메이션 완료→물 생성. 낮은 집수조/높은 수로의 FREEZE로 얼음 상태 생성. E는 준비된 잎 가까이에서만 가능하다.
- 낙하 복구는 Respawn을 사용해 펌프·수문·얼음을 유지한다. 출발대에 실제 도착해 CP를 저장하기 전에는 기존 시작 지점으로 돌아간다.
- 높은 수로 아래 지역 복구와 출발대 아래 원본 지형 접지 복구를 추가했다. 합법적 계단/마당은 구분한다. 경계가 적절한지는 실행 검증이 필요하다.
- 정상은 준비된 경로로 출구 데크에 실제 접지한 뒤 완료 선 도달. 보조는 능력 사용/정렬 기록이 부족해도 같은 안전 출구 접지와 완료 선을 확인해 인정한다. 공중 스침은 거부한다.
- 완료는 단조 증가한다. 완료 후 source/gate/water를 안전 상태로 보정하고 반복 입력으로 해제하지 못한다. 완료된 최종 stage는 이 보정 대상이 아니다.
- R은 기존 정책대로 현재 미완료 퍼즐을 의도적으로 초기화한다. 자동 추락 복구와 다르다. 전체 Restart는 사본을 새로 로드한다.

## 여는 법과 실패 시 처리

현재는 사본이 이미 있으므로 **Create P3 Copy를 다시 실행하지 않는다.** 정상 사용자 계정의 Unity 6000.3.21f1에서 기존 사본을 열고 스크립트 컴파일 완료 후 `Tools > EVERFLOW > MVP Experiment > Run P3 Checks`를 실행한다. 이 메뉴가 Play에 진입한다. 원본 Title의 시작 버튼은 여전히 원본 Map을 연다.

다른 새 실험이 필요할 때에만 Create P3 Copy 생성 절차를 검토한다. 미저장 씬이 있거나 같은 이름이 존재하면 생성 도구는 거부한다. 현재 사본/원본을 자동 덮어쓰거나 삭제하지 않는다.

생성 중 참조/캡슐 충돌 검사가 실패하면 사본이나 미저장 변경이 남을 수 있다. 자동 삭제·덮어쓰기는 하지 않는다. Console과 `evidence`의 실패 기록을 확인하고 사본을 검토·보관한 뒤 다른 이름으로 다음 실험을 진행한다. 생성 실패한 사본을 완료된 실험으로 취급하지 않는다.

검증 도구: `Tools > EVERFLOW > MVP Experiment > Run P3 Checks`. API/텔레포트 fixture, 실제 잎 구간, 전체 물리 횡단은 구분한다. CLI 실행 방법은 HANDOFF 참고.

## 남은 검증과 우회 후보

새 계단의 실제 접근/모델 충돌, 높은 수로 조준, 낮은 집수조에서의 카메라 시야, 수로 메시와 잎 경로 접합, 끝단 도약, 출구 프레임 가림, 원래 지형을 이용한 우회, 하강 계단 역접근, 복구 영역 모서리를 직접 확인해야 한다. 완주 시간·첫 이해·재미는 미검증이다.

사람 테스트에서는 설명 없이 펌프/물의 대상을 구별하는지, 낮은/높은 위치의 동결 순서를 스스로 선택하는지, 출발대와 높은 출구 관계를 읽는지, 추락 후 준비 반복 없이 재시도하는지를 기록한다. 이번 회차에서는 참가자를 기다리지 않았고 사람 테스트를 수행하지 않았다.

원복: 생성 사본을 사용하지 않고 원본 Map을 연다. 공유 코드 원복이 필요하면 이번에 추가한 World의 실험 옵션·도착/완료 분기·Editor 재로드 분기와 Node.ApplyCompletedState만 수동으로 되돌린다. 사용자 작업을 포함할 수 있는 일괄 git reset/clean은 사용하지 않는다.
