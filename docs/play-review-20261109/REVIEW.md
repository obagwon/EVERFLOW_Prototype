# EVERFLOW 플레이 영상 검토 · 선택형 개선 목록

대상 씬: `Assets/Scenes/Everflow_Map_v2_test_with_puzzle.unity`

입력 자료: `Recordings/Movie_007.mp4` (2분 52.87초, 1920×1080, 30fps)와 사용자 캡처 5장.

전체 구간을 2초 간격 87장으로 확인하고 주요 화면을 별도로 추출했다. 아래 시각은 영상 기준의 대략적인 구간이다. 사운드는 파일 레벨과 소스 코드를 분석했으며, 사용자의 실제 청취 환경 음량은 측정하지 않았다. 진단 단계에서는 게임 코드·씬·오디오 설정을 변경하지 않았으며, 이후 사용자 선택을 받은 항목만 구현한다.

## 진행 방식

한 항목 선택 → 해당 항목 구현 → Unity에서 확인 → 결과 보고 → 다음 항목 질문 순서로 진행한다. 추천은 자동 선택이 아니다. 사용자는 A/B/C 외에 조합이나 다른 방식을 지정할 수 있다. 다음 항목의 선택은 미리 요구하지 않는다.

## 1. 맵 안 낙하의 잘못된 강제 복귀

사용자 제보 및 영상 1:38~1:50 주변의 재접근/위치 복귀 구간. 영상만으로 각 복귀가 자동인지 R 입력인지 구분할 수는 없지만, 잘못 발동할 수 있는 코드 조건은 확인했다.

`EFV2PuzzleWorld.Update()`는 현재 Y가 최하단 한계(-45) 아래이거나, 탑 내부의 좁은 예외 영역 밖에서 마지막 안전 지점보다 8m 낮아지면 즉시 `Respawn()`한다. 아래에 착지할 바닥이 있는지, 플레이어가 맵 밖으로 나갔는지는 검사하지 않는다. 높은 곳에서 정상 하층으로 내려갈 때에도 발동할 수 있다.

- **A · 맵 밖 전용 복귀 영역 + 최하단 안전선 (추천).** 절벽 바깥의 낙하 공간에만 복귀 영역을 두고, 맵 전체 아래의 안전선은 최종 보호 장치로 남긴다. 맵 내부의 단차/계단/아래층은 높이 차와 무관하게 착지 가능하다. 의도가 가장 명확하지만 새 맵 확장 시 영역도 갱신해야 한다.
- **B · 착지 가능 지면을 검사하는 동적 판정.** 아래쪽 지면/움직이는 발판/얼음길과 플레이 영역을 검사하고, 착지 가능한 바닥이 없고 영역 밖에 있는 상태가 일정 시간 지속될 때만 복귀한다. 자동 대응 범위는 넓지만 복잡한 지형·가동 발판 경계에서 오판 방지 검증이 더 필요하다.
- **C · 상대 높이 조건 제거, 최하단 안전선만 사용.** 8m 조건을 없애고 실제 플레이 공간보다 충분히 아래인 최하단을 통과할 때만 복귀한다. 가장 작고 빠른 수정이며 내부 낙하 오판은 없어진다. 대신 바깥으로 떨어졌을 때 바닥선에 도착할 때까지 더 오래 떨어진다.

검증: G→하층 및 C→하층에서 실제 바닥에 착지, 높은 계단/연결길의 복귀 없음, 외곽 절벽 낙하 시 1회 복귀, 리스폰 중복/체크포인트/퍼즐 결과 보존. `R` 수동 복귀와 D2 깊은 수조의 별도 위험 판정(`EFV2WaterHazard`)도 원인을 구분해 확인한다. D2 위험 규칙 변경은 이 선택의 자동 부수 효과로 처리하지 않는다.

## 2. 바닥 위에서 근거 없이 꺾이는 물길

캡처 5, 영상 0:48~0:56. 탑 주변의 물이 지면 위에 넓은 띠로 놓여 있어, 평평한 바닥에서 모양대로 방향을 바꾸는 이유를 읽기 어렵다. 이어진 물 표면만으로는 수로의 바닥·둑·높이 차를 표현하지 못한다.

- **A · 낮은 석조 수로 (추천).** 기존 곡선에 맞는 수로 바닥과 낮은 양쪽 턱, 코너 안쪽 벽, 배수구를 만들고 수면 높이와 낙차를 연결한다. 유적의 다른 석조 수로와 가장 잘 맞고 기존 물 공급 경로를 보존하기 쉽다.
- **B · 얕게 팬 자연 하천.** 완만한 굽이와 낮아진 하상, 자갈/흙 경계, 둑의 돌과 풀로 지형이 물을 유도하게 만든다. 자연스럽지만 기존 직선형 유적 수로와 이어지는 전이 구간 및 지형 작업량이 더 크다.
- **C · 지면에서 분리된 낮은 고가 수로.** 받침과 양쪽 벽이 있는 수로를 놓아 물이 바닥 위를 흐르는 대신 구조물 안으로 흐르게 한다. 물길이 잘 읽히지만 통행로와의 높이 관계·교차부를 함께 설계해야 한다.

검증: 공급/차단/동결 조건과 물길의 시작·끝 유지, 수로와 지면의 깜빡임 없음, 코너 연속성, 통행/능력 조준/가동 수로 범위 보존.

## 3. 계속 들리는 물소리와 거리감

사용자 청취 제보. 현재 별도 물소리 에셋/AudioMixer는 없으며 `EFDemoFeedback`의 합성 노이즈를 4초 루프로 재생한다. 단일 물소리 소스가 가장 가까운 물의 **렌더러 AABB** 위치로 이동한다. 물에서 약 22m 범위까지 볼륨을 올리고, 소스 최대 거리도 38m다. 벽 차폐나 얕은 수로/폭포의 소리 차이는 없다. 큰 곡선 물 메시의 AABB는 실제 물 표면보다 넓어서 거리가 과하게 가깝게 잡힐 가능성도 있다. 중복 생성이 원인이라고 단정할 근거는 없다.

참고: 녹화 전체 평균 약 -48.6dBFS, 최대 약 -27.4dBFS로 파일 클리핑은 확인되지 않았다. 절대 피크보다 지속음의 질감·상대적인 소리 비율·청취 거리부터 다룬다.

- **A · 조용한 근거리 물소리 (추천).** 물소리를 현재보다 약 10~12dB 낮춘 시작점으로 잡고, 유효 거리를 약 6~10m로 줄인다. 실제 물줄기 위치를 기준으로 감쇠하고 얕은 수로는 더 작게 만든다. 효과가 빠르며 기존 사운드 구조를 유지한다.
- **B · 폭포/수로별 3D 소스와 환경음 믹서.** 물 구역별 고정 소스, 가까운 소수만 재생, 벽 차폐/저역 통과, 환경음 볼륨 조절을 도입한다. 조절성과 거리감은 가장 좋지만 A보다 구현 범위가 크다. 패키지/유료 에셋은 필요 없다.
- **C · 폭포만 조용하게 상시 재생.** 평상시 얕은 물길의 루프를 거의 없애고 폭포 근처 및 공급이 연결되는 순간에만 물소리를 강조한다. 가장 편안하지만 작은 물길의 존재감은 줄어든다.

검증: 능력/문/완료 소리가 물에 묻히지 않음, 구역 이동 시 볼륨 급변 없음, 일시정지/재시작/리스폰 후 루프 중복 없음. 최종 청취 음량은 사용자 확인을 받는다.

## 4. 지지 구조 없는 계단·다리와 접합

캡처 1~3, 영상 0:24~0:30 및 0:46~1:16. 절벽 옆 계단은 얇은 발판이 공중에 이어지고, 상단의 넓은 판과 비스듬히 겹친다. 긴 갈색 연결길도 지지 구조와 경계가 적어서 임시 판처럼 보인다. `EFV2PuzzleAssembly.Steps/Deck`는 대부분 기본 상자로 만든 별도 구조다.

- **A · 유적 석조 계단/교량 (추천).** 계단 옆면과 기초를 채워 절벽에 붙이고 상단은 단일 착지대에 접합한다. 긴 다리는 교각/아치/난간과 석재 모듈로 정리한다. 맵의 유적 주제와 일관된다.
- **B · 목조 작업용 잔교/계단.** 널빤지, 보, 가새, 기둥, 난간을 붙여 의도적인 정비 통로로 만든다. D5 작업 구역과 잘 맞지만 유적의 주동선 전체에 쓰면 재질 비중이 달라진다.
- **C · 지형에 파인 길과 짧은 연결부.** 절벽 테라스를 따라 경사/계단을 만들고 공중 교량은 꼭 필요한 간극에만 둔다. 가장 자연스럽지만 지형과 동선 조정량이 크다.

검증: 계단 상·하단 높이/폭 일치, 물레/문/가동 발판과 관통 없음, 실제 보이는 발판과 충돌면 일치, 퍼즐 간극을 새 길이 우회하지 않음.

## 5. 겹친 착지판·떠 있는 뿌리/장식

캡처 4, 영상 0:26~0:30, 1:00~1:10. 회색 판 위에 밝은 판이 다시 올라가며, 절벽 중간의 뿌리 조각도 바닥/벽에 붙은 근거가 약하다. 코드에서 기존 지형 위에 착지 데크와 체크포인트용 데크를 별도로 만들고, 일부 뿌리 모델은 위치만 옮겨 배치한다. 정확히 어떤 판을 제거할지는 구현 시 현장별로 식별한다.

- **A · 기존 지형 우선 통합 (추천).** 지면이 이미 받치는 곳의 추가 안전판은 제거하고 체크포인트는 보이지 않는 트리거로 유지한다. 필요한 연결부만 남기고 뿌리는 실제 벽/지면에 닿도록 정렬한다. 가장 적은 구조로 정리할 수 있다.
- **B · 의도적인 건축 착지대로 통일.** 겹친 판을 하나의 기초/테두리가 있는 착지대로 교체하고 주변 지형과 접합한다. 뿌리도 같은 기초 틈에서 자라게 배치한다. 원래 동선을 유지하기 쉽지만 구조물은 남는다.
- **C · 해당 접합부의 바닥 메시를 재구성.** 지면·착지대·연결부를 하나의 연속 표면으로 다시 만든다. 이음새 품질은 가장 좋지만 작업량과 충돌 검증 범위가 크다.

검증: 표면 중첩/미세 깜빡임 없음, 허공의 활성 상호작용 대상 없음, 보이는 바닥 밖의 투명 지지면 없음, 체크포인트 안전 위치/가동 장치의 범위 유지.

## 6. 좁은 공간의 카메라와 캐릭터 가림

영상 1:18~1:34, 1:40~1:46. 탑 내부에서 머리가 화면 대부분을 가리며 능력 모드에서도 중앙 조준 부분이 막힌다. 현재 Cinemachine Deoccluder의 최소 거리 설정은 0.25m다. 기존 캡슐보다 부피가 큰 캐릭터의 머리까지 고려한 근접 가림 처리가 없다.

- **A · 벽 회피 튜닝 + 가까운 캐릭터 디더 페이드 (추천).** Cinemachine을 유지하며 과도한 밀착을 줄이고, 좁은 공간에서 불가피하게 가까워질 때만 캐릭터를 부드럽게 옅게 한다. 현재 조작/자유 시점과 가장 잘 이어진다.
- **B · 좁은 구역 전용 카메라 볼륨.** 탑/터널에서 높고 짧은 구도로 전환한다. 통로를 읽기 쉽지만 자유 시점과 전용 구도 사이의 전환 설계가 필요하다.
- **C · 카메라를 가리는 벽/천장 일부 디더 처리.** 캐릭터 크기와 거리를 유지하면서 가리는 건축 표면만 옅게 한다. 넓게 보이지만 벽 너머 공간이 드러나며 가림 대상 분류 작업이 필요하다. 능력의 실제 벽 가림 판정은 유지한다.

검증: 벽 관통 없음, 머리/등에 조준 UI가 가려지지 않음, 능력 모드 진입·종료 시 구도 점프 없음, 오프닝/엔딩 전환 유지.

## 7. 능력 모드 밖에서도 남는 강한 단색

영상 0:36~0:46의 성장한 잎. 선택 모드를 나와도 잎이 밝은 초록색 면으로 남는다. `EFV2AbilityTargets`의 선택 오버레이와 별개로, `LabTarget.Refresh()`가 성장/고정 상태의 `_BaseColor`를 덮어쓴다. 현재 선택 표시와 완료 상태의 색이 서로 비슷해질 수 있다.

- **A · 탐색 중 원래 재질, 능력 모드에서만 윤곽 강조 (추천).** 적용 순간 짧은 색 파동을 주고 원래 잎 색으로 돌아온다. 성장 상태는 크기/형태로, 고정 상태는 작은 얼음 장식 등으로 읽히게 한다.
- **B · 지속 표시는 아주 약한 색조만 사용.** 원래 재질을 유지하면서 성장/동결 결과 색을 10~15% 정도 혼합한다. 상태 구분은 쉽지만 탐색 중에도 약한 색 변화가 남는다.
- **C · 결과를 형상/국소 장식으로 표현.** 잎맥, 새싹, 고정부의 얇은 서리, 물방울 등만 바꾼다. 가장 자연스럽지만 상태별 표현 리소스가 더 필요하다.

검증: 탐색/선택/적용 결과가 서로 구분됨, 재시작 시 원래 재질 복구, 다른 씬에서 쓰는 LabTarget의 기존 동작에 영향 없음.

## 8. 목표 안내·표식의 현재 위치/층 구분

영상 0:54~1:14, 1:38~1:50 및 탑 내부. 물리적으로 이동한 구역과 화면 상단 지역/다음 목표가 어긋나 보이는 구간이 있고, 층을 구분하기 어려운 거리 표식이 다른 벽면을 향한다. `EFV2Guidance.Refresh()`의 구역 분류가 현재 공간보다 마지막 체크포인트 라벨에 크게 의존한다.

- **A · 진행 상태 기반 목표 + 현재 구역/층 감지 (추천).** 체크포인트는 복귀용으로 분리하고 현재 영역을 별도로 표시한다. 현재 층에서 접근 가능한 다음 연결부만 목표로 가리킨다. 기존 HUD 크기를 유지할 수 있다.
- **B · 화면 안내 최소화 + 갈림길 환경 표지.** 지역명/짧은 목표만 화면에 두고 계단 입구·분기점에 세계 안 표지를 배치한다. 화면은 깔끔하지만 표지의 배치와 가독성 작업이 필요하다.
- **C · 층별 간단 지도/경로 요약.** 현재 층과 다음 이동 구간을 지도에 보여 주고 화면 목표는 짧게 만든다. 복잡한 지하 구조에 유리하지만 UI 범위가 가장 크다.

검증: 뒤로 돌아갈 때 완료 목표로 잘못 회귀하지 않음, 위/아래층의 목표 구별, 캐릭터/능력 후보를 가리지 않음, 기존 퍼즐 해법을 강제하지 않음.

선택 A 구현 결과와 플레이 기록은 [위치·층별 목표 안내 검증](location-guidance/RESULT.md)에 정리했다.

## 9. 정원 도착 공간의 완성도

영상 2:48~2:52. 도착 보상이 작은 평판과 몇 개의 잎/효과 중심이라, 물레방아를 복원한 후 도착한 정원이라는 공간적 변화가 약하다. 기능 오류가 아닌 후순위 미술/연출 개선 항목이다.

- **A · 작은 유적 화단/정원 (추천).** 바닥과 연결된 낮은 석조 화단, 흙, 기존 잎/식물의 군집, 도착 후 순차 성장으로 마무리한다. 유적 수로와 한 공간으로 보이게 한다.
- **B · 물레방아 옆 습지 정원.** 완만한 물 가장자리, 자갈, 수초/갈대 느낌의 식물 군집을 중심으로 구성한다. 자연스러운 복원 주제에 어울리지만 물가 접합 작업이 늘어난다.
- **C · 소규모 전망 쉼터.** 안전한 기초·난간·작은 식재와 물레가 잘 보이는 마무리 시점으로 정리한다. 작고 명료하지만 풍성한 정원 느낌은 줄어든다.

검증: 정원 도착 조건 유지, 마지막 통로와 높이 연결, 물레 가림 없음, 복원 전후 차이, 리스폰/재시작 후 식물/효과 중복 없음.

선택 A의 구현 결과와 도착 영상은 [유적 화단 검증](ruin-garden/RESULT.md)에 정리했다.
