# 2번 · 자연 하천 (B 선택)

## 적용 범위

평지에 물 표면만 놓여 있던 네 구간을 자연 하천으로 정리했다.

1. 유적 누수 폭포 아래 → 천창 주변의 큰 굽이 → 아래쪽 폭포 직전.
2. 아래 폭포 착수점 → A 연못 유입부.
3. D5의 맨바닥 누수 → D2 수조 유입부.
4. 출구를 지난 협곡 하류 → 물레방아 웅덩이 연결부.

기존 인공 수로 벽, 퍼즐 수조/얼음길, 물레방아 웅덩이의 구조는 유지했다. 수로/다리 배치 개선은 4~5번, 카메라 가림은 6번, 물소리는 3번 선택 이후에 다룬다.

## 지형과 물의 변화

- 천창 주변의 급한 두 코너를 더 넓은 굽이로 바꾸고, 짧은 미세 경사를 줬다. 큰 폭포의 상단/출수 방향과 상류 유적 수로는 유지했다.
- 큰 굽이 구간의 수면을 기존 3.225m에서 약 2.90→2.85m로 낮췄다. 주변 지형은 약 3.01m이며, 실제 하상은 수면보다 약 0.30m 아래다. 얕은 흙 둑이 물을 유도한다.
- 연못 유입부도 낮은 수면으로 연결했다. 받는 연못/수조 방향에 둑이 가로막히지 않도록 하류 끝에서는 조각을 완만하게 풀었다.
- 흙/젖은 자갈/잔디 전이 재질과 소량의 작은 돌/풀을 더했다. 세부 장식은 두 개의 합친 메시로 만들고 통행/조준을 막는 충돌체는 추가하지 않았다.
- `T_Terrain`, `HALL_Floor`, `PLT_South_W`, `ROOF_E/N/S`의 해당 부분을 복사 메시로 조각했다. 보이는 바닥과 실제 MeshCollider가 같은 메시를 사용한다.
- 위의 지형과 아래 지붕판을 동일한 표면으로 눌러 겹치지 않도록, 원본 층 사이의 높이 차를 보존하며 함께 변형한다. 원본 FBX 및 임포트 설정은 변경하지 않는다.
- 기존 39개 물 세그먼트/15개 표시 소유자, 공급·동결·분기·복원 상태, 물 셰이더, 플레이어와 낙하 복귀 코드는 유지했다.

## 검증

- `checks.txt`: **34개 통과**. 실제 충돌 쿼리로 하상 깊이와 양쪽 둑 높이, 표시 메시와 충돌면 일치를 확인했다. 실제 W 입력으로 하천을 걸어서 건너고, 발이 낮아진 하상으로 내려갔다가 반대편으로 올라오는 것을 확인했다. 능력 모드 정지/취소 재개와 재시작 시 중복 생성도 검사했다.
- `water-state-checks.txt`: 기존 물 상태 통합 검사 **28개 통과**. 공급, 분기, 구조물/물 동결 차이, 해동, D4 및 물레방아 복원, 재시작을 확인했다. 이 검사는 명시적 상태 배치이며 입력 완주 증거는 아니다.
- `continuous-route.txt`: 새 지형에서 시작부터 A 잎/C 경로/G 석문/D5 정렬/D4 수문/물레방아 복원/정원/엔딩 재시작까지 연속 입력 검사 **63개 통과**. 선택·정지·확정 과정을 우회하지 않은 합성 키보드/마우스 입력이다. 사람의 첫 플레이 시간/사용감 검증과는 구분한다.
- `before-overview.png`, `after-overview.png`: 동일한 관찰 카메라 위치/시야각의 전후 비교. 캐릭터 위치와 안내 표식은 강제 재현 시작 위치 차이로 다를 수 있다.
- `after-bend.png`: 큰 굽이의 하상/둑 화면.
- `river-review.mp4`: 물리 횡단 및 관찰 영상(1280×720). 카메라는 비교용 관찰 구도이며 카메라 자체의 개선 검사는 아니다.

확인한 공식 로컬 문서: Unity 6000.3의 `class-MeshCollider.html`, `class-CharacterController.html`.

최종 씬 재열기로 메시 오버라이드 6개가 저장됐는지 확인했다. fixed 캐릭터와 1번 외곽 낙하 설정은 유지되며, 플레이 검증 설정을 원래대로 복원했다. 현재 컴파일/콘솔 오류 없음. 공급/동결/퍼즐 생성/낙하 복귀 런타임 코드와 물 머티리얼 파일 해시는 작업 전과 같다.

## 파일과 복구점

- `Assets/EverflowMap/Editor/EFNaturalRiverTools.cs`: 복사 지형 조각, 재질, 둑 장식 생성.
- `Assets/EverflowMap/Editor/EFNaturalRiverBackup.cs`: 원래 바닥 메시/재질과 변경 전 물 메시 참조.
- `Assets/EverflowMap/Editor/EFNaturalRiverPlayChecks.cs`: 지형/실제 W 횡단 검사.
- `Assets/EverflowMap/Editor/EFWaterNetworkTools.cs`: 자연 하천의 연결 곡선과 낙차. 기존 네트워크 재생성 시에도 새 굽이를 보존한다.
- `Assets/EverflowWater/NaturalRiver/`: 지형 복사 메시, 새 재질과 장식, `BeforeNaturalRiver.asset`, `BeforeMainWater.asset`.
- `Assets/EverflowWater/Network/W_H_to_G_Fall_Network.asset`: 이어진 상류→누수→연못 물 표면.
- 대상 씬: 위 메시/재질/영향점 연결 저장.
- `before/`: 변경 직전 씬/생성 코드/물 메시와 유지 대상 파일 해시.

재생성 메뉴는 `Tools > EVERFLOW > Water > Natural River > Apply Carved Riverbeds`다. 대형 지형 생성은 Ctrl+Z의 native Undo 대신 저장된 복구점을 사용한다. 단순 Ctrl+Z 복귀를 제공하는 도구는 아니다.

## 작업 중 오류와 복구

두 번째 생성 시 `Undo.DestroyObjectImmediate`에서 약 973MB 추가 할당을 시도하다 Unity 메모리 오류가 발생했다. `unity-memory-error.log`에 보관했다. 저장된 씬/복구점으로 같은 프로젝트 에디터를 재시작하고, 생성 메시/오브젝트의 native Undo 기록을 제거했다. 이후 재생성이 정상 완료됐으며 실제 Play 검사 34개와 물 상태 검사 28개가 통과했다. Unity로 오류 로그를 전송하지 않았다.
