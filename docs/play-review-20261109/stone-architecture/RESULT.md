# 4/9 · 유적 석조 계단·교량 — A 적용

대상: `Everflow_Map_v2_test_with_puzzle`. 사용자 선택에 따라 고정 통로를 유적의 석조 구조로 정리했다. 겹친 안전판·뿌리 배치 정리는 다음 5번 선택을 기다린다.

## 변경

- 고정 계단 8개: B/C 유적 진입, D3→D5, D5 우회 접근, 조건부 D3 복귀, D5 횡단로 양쪽 짧은 경사, 외곽 출구. 연속된 석조 하부와 필요한 구간의 측벽·두겁을 더했다.
- 고정 데크 16개: C/G 접합부, D5 작업 통로, D3 복귀, D2/D4 외곽과 문턱을 같은 석재로 연결했다. BLOOM으로 나타나는 A 뿌리 계단·B 뿌리 다리·D3 덩굴 길의 성장 형상은 유지했다.
- B↔C 긴 판은 여섯 개 아치가 있는 석조 교량으로 바꿨다. 교각은 기존 지면에 매입하고, x=-35 부근의 자연 하천 위에는 교각이 들어가지 않도록 간격을 조정했다. 접근부 난간을 열어 기존 대각선 진입을 유지했다.
- 새 석조 몸체·난간은 보이는 메시와 같은 MeshCollider를 사용한다. 기존 발판의 폭·XZ 동선·시작/끝 높이와 체크포인트는 보존한다. D5 수로 바로 아래에는 교각을 추가하지 않았다.
- 외곽 계단은 연속 하부 구조와 기존 난간의 석재 표현을 적용하고, 위쪽의 실제 홀 외벽에 닿는 구간에는 받침을 연결했다. 바닥이 없는 곳까지 허공의 기둥을 내리지는 않았다. 정원 공간과 섬 기초 연출은 9번 검토 범위로 남긴다.

## 실제 통행 중 발견해 함께 수정한 접합

새 구조물을 끈 비교 검사에서도 두 기존 계단은 걷기만으로 통과하지 못했다(`baseline-checks.txt`). 이전 연속 경로 기록에도 해당 지점에서 점프한 이력이 있었다.

- **C 계단**: 기존 절벽 면이 발판 안으로 들어왔다. 현재 자연 하천 지형의 복사본에서 C 계단 주변만 국소적으로 절삭했다. 변경된 삼각형은 494개이며, 원본 FBX와 기존 하천 메시 자산은 그대로다. 보이는 지형과 실제 충돌면은 같은 새 메시를 쓴다. 또한 상단 착지판 아래로 머리가 들어가지 않도록 마지막 25%를 같은 높이의 착지부로 만들었다. 캐릭터의 45도 경사 제한·점프·stepOffset은 변경하지 않았다.
- **D3→D5**: 계단 중간에 옆 작업 통로 판이 겹쳐 머리를 막았다. 동일한 XZ 경로와 시작/끝 높이 안에서 48% 지점까지 상승한 뒤 평탄하게 접합한다. 발판과 연속 지지면, 보이는 석조 하부 모두 같은 높이 형상을 사용한다.
- 초기 연속 경로에서 D5 합류 시 새 난간 끝을 밟는 문제도 발견했다. 마지막 2m를 열고, 계단 상승 직후 옆 통로로 꺾는 동작을 추가 검사했다. 검사에서 선택/사용 과정을 건너뛰거나 캐릭터의 이동 능력을 높여 통과시키지 않았다.

## 검증

Unity 6000.3.21f1에서 실행했다.

- **구조·통행 검사 28/28 통과** (`checks.txt`). 모든 고정 계단, 아치 교량, D5 횡단로, 외곽 출구, 계단을 오른 뒤 옆 통로로 꺾는 동작을 점프 없이 확인했다. 재시작 후 조건부 길 초기화와 생성 중복 없음도 확인했다.
- **B 연속 입력 경로 46/46 통과** (`route-bloom.txt`). A 뿌리→B 뿌리 다리→G 뿌리 문→D3 덩굴→D5 우회→D4 뿌리 문→물레방아→정원→Enter 재시작. 게임 경과 143.44초이며 사람의 첫 플레이 시간은 아니다. D3→D5 접합과 이후 방향 전환에서 점프가 필요하지 않았다.
- **C 대체 연속 입력 경로 63/63 통과** (`route-alternate.txt`). A 잎→C 성장 잎→G 수차→D3 얼음길→D5 정렬/고정→D4 수차→얼음 해제→물레방아→정원→Enter 재시작. 게임 경과 143.67초. 이전 기록에서 점프하던 C 계단도 걷기로 통과했다.
- **기존 지형 비교 8/8 일치** (`terrain-preservation.txt`). C 절삭 범위 밖 하천·주변 7지점의 직접 지형 레이캐스트 높이 차이는 0이었다. 나머지 한 지점은 양쪽 모두 해당 지형에 미적중했다. 추가로 절삭 범위의 높이 영역에 물 메시 정점이 없음을 확인했다(`water-near-cut.txt`).
- 퍼즐 월드·낙하 복귀·물 공급/동결 표현·물소리·메인 물길 메시·물 재질의 SHA256이 직전 백업과 동일하다(`unchanged-contracts-result.json`). 조립 코드에서는 표현 생성과 위 두 접합의 높이 형상만 바꿨다.
- **29.07초 확인 영상** `stone-structure-review.mp4` (1280×720 H264/AAC). 격리된 실제 WASD 통행과 B 계단·B↔C 교량·C 착지부·D5 관찰 화면을 포함한다. 시작 위치/카메라를 배치한 검사 영상이며, 두 연속 퍼즐 경로의 녹화라는 뜻은 아니다. 해당 경로는 별도 입력 검사 기록으로 남겼다.

- 격리 통행 검사는 시작 위치를 명시적으로 배치하고 고정 관찰 카메라를 썼다. 이후 실제 Input System WASD와 기존 CharacterController로 이동한다. 조건부 D3 복귀 길만 이 검사에서 강제로 활성화했으며, 일반 게임에서는 작업대 도착 조건을 유지한다.
- 전체 경로 검사는 시작부터 실제 입력과 커서 선택·정지·방향 선택·확정·기존 능력 적용을 거쳐 진행한다. 직접 Teleport/Apply/문 열기/강제 수로 상태로 퍼즐 과정을 우회하지 않는다.

## 변경 파일과 복구 자료

- `Assets/EverflowMap/Runtime/EFV2StoneArchitecture.cs`: 씬 내 고정 통로의 석조 메시·기초·아치·난간 생성, 해당 런타임 메시/재질 정리.
- `Assets/EverflowMap/Runtime/EFV2PuzzleAssembly.cs`: 석조 표현 연결과 C/D3 두 계단의 조기 착지 형상.
- `Assets/EverflowMap/Editor/EFStoneTerrainCutTools.cs`: C 계단에 겹치는 절벽의 국소 절삭, 백업, Unity API를 통한 지형/씬 저장.
- `Assets/EverflowMap/Editor/EFStoneArchitecturePlayChecks.cs`: 격리 통행, 접합부 회전, 원래 기하와의 비교 및 녹화.
- `Assets/EverflowMap/StoneArchitecture/`: 절삭 전 지형 복사본과 적용 메시. 원래 자연 하천 메시와 백업의 기하는 같으며 자산 이름만 다르다.
- 대상 씬: T_Terrain의 메시 참조 1개만 새 절삭본으로 변경했다. 런타임 조립 과정이 동일 메시의 MeshCollider를 만든다.

직전 조립 소스·씬은 `before/`에 있다. 검증 중 실패했던 첫 두 결과, 기존 구조 비교, 첫 B 연속 경로 결과도 보존했다. 지형 재생성에는 대용량 Undo 대신 명시적 백업을 사용했다. 원본 FBX·물 공급/동결 로직·낙하 복귀·물길 네트워크·물소리 코드는 변경하지 않았다. 패키지나 유료 에셋을 추가하지 않았다.

Unity 설치본의 공식 로컬 문서 `class-CharacterController.html`, `class-MeshCollider.html`을 확인했다. 한 번 Play 진입 직후 Pipeline 연결이 일시적으로 끊겼으나 같은 에디터가 정상 준비 상태와 프레임 진행을 회복한 것을 확인하고 계속했다. 외부 로그 전송은 하지 않았다.

작업 종료 시 Play를 중지하고 Run In Background·자동 틱 임시 설정을 해제했다. 대상 씬을 다시 열어 절삭 메시 참조가 유지되는지 확인했다. 초기 실패 기록은 최종 통과 결과와 구분해 보존했다.
