# EVERFLOW V2 후속 작업

작성: 2026-11-05. 기준은 [개편 기획 v0.2](EVERFLOW_redesign_v0.2.md)이며 이전 6퍼즐 문서는 역사적 참고다. 실제 구성·조작·검증 절차는 [씬과 스크립트 안내](EVERFLOW_V2_Scene_And_Script_Guide.md)를 참조한다.

## 1. 현재 상태와 근거

새 맵의 탐색 구성을 파일에 반영했다. 기존 `EFMapPlayer` 프리팹 인스턴스 하나와 기존 `EFMapCamera`를 연결하고, 독립 이동 모드·시작점·메시별 지형 충돌·낙사/R 복귀를 설정했다. 퍼즐 통합은 시작하지 않았다. 실제 새 맵 Play는 이번 실행 환경에서 하지 못했으므로 탐색의 물리·조작성 검증은 남아 있다.

| --- | --- | --- |

이름이 비슷한 `Everflow_World_Graybox`, `Everflow_Map_MVP`, `Everflow_6Puzzles`를 지정 실험실 대신 사용하지 않았다. 지정한 두 문서와 세 분석 씬은 모두 발견했다. 다른 이름의 기획서로 v0.2를 대체하지 않았다. 문서 안 Notion 링크는 이번에 열지 않았으며 로컬 v0.2 내용만 기준으로 삼았다.

공간 크기도 동일하지 않다. FBX 분석에서 지하 `HALL_Floor` 상면은 y=-12, `G_RuinPaving`은 y=15.12, H 연못 수면은 y=20.55, W 주변 수면은 약 y=-17.8이다. 기획의 상대 높이 D2=-8/G=+10/H=+14/W=-12와 차이가 있다. 시작 전망대 상면 y=.12를 기준으로 보더라도 큰 차이가 남는다. FBX의 전체 지형 경계는 약 114×104m로, 기획 지상 제안 90×80m와도 다르다. 외곽까지 포함한 경계이므로 플레이 구역 크기로 확정하지 않는다.

## 3. 그레이박스 퍼즐별 실제 상태와 검증 수준

아래 오브젝트와 컴포넌트는 현재 전체 실험실 씬에서 직접 확인했다. `PuzzleLab.areas`는 T01→T02→T03→T04→지하 순서로 연결되어 있으나 디버그 이동/초기화 목록이며 클리어 순서 조건이 아니다.

| 구역 | 실제 오브젝트·구현 | 확인된 검증과 남은 일 |
| --- | --- | --- |
| T01 / A | `A ROOT STEP`, `A WATER CURRENT`, `A LEAF`. 1.2m 성장 발판과 2.4m 둔덕, 잎 운반/고정, 접지 목표 판정 | 과거 `full-play-checks.txt`에 중앙 광선 클릭·두 경로 점프·이동체 추종 통과 기록. 현재 씬으로 이번에 재실행하지 않음. A→C 바람 대안·사람의 발견성 미검증 |
| T02 / B | `B LONG ROOT ROUTE`, `B WIND ROTOR`, `B ROTARY PLATFORM`. 성장 우회로와 풍향 구동 왕복 발판 | 과거 API 기록은 고정 유지·정지 해제 위상 유지. 두 경로를 걸어서 끝낸 기록은 아님 |
| T03 / C | `C UNFOLDING LEAF`, `C WIND ZONE`. 작은/큰 잎 속도·도달 범위 차이, 두 목표 선반 | 과거 API 기록은 성장·풍향·고정 유지와 해제 반응. 두 선반 착지·가림·실제 난이도 미검증 |
| T04 / G | `G WATER BRANCH`, `G GATE LIFT ROOT`, `G STONE GATE`, LabGateFlow | 과거 API 기록은 수차·뿌리 대안, 걸쇠 유지. 문 아래 통과·카메라·부분 개방 실패 복구를 직접 확인해야 함 |
| 지하 D1~D5/W | `D3 GROWN VINE PATH`, `D3 DOCK LEAF`, `D3 ICE CROSSING`, `D5 ALIGNMENT WIND`, `D5 AQUEDUCT STRUCTURE`, 별도 `D5 WATER INSIDE (not structure)`, `D5 BYPASS ROOT GATE`, `D2 CENTRAL THREE-WAY`, `D4 EXIT SLUICE`, `MAIN ICE WALKWAY / SUPPLY BLOCK`, `Hydraulic circuit - single reset unit` | 과거 API 기록은 연결/우회·분기·얼음 차단·문·3초·복구·국소 초기화. 전체 물리 동선·입구에서의 장치 식별은 미검증 |

`docs/puzzle-lab/full-play-checks.txt`에는 **45 checks; 0 failures**가 기록되어 있다. 파일 시각은 2026-11-04 21:49, 현재 실험실 씬 시각은 같은 날 22:27이며 검사 보고서 자체에는 씬 해시가 없다. 이후 안내판 변경은 `signage-verification.json`에서 게임플레이 구성 보존을 검사했지만, 과거 Play 결과를 현재 씬의 재검증으로 올려 표시하지 않는다. 이번 실행은 **LabState 실제 소스 관리 코드 38개 통과**, 씬 참조 정적 검사, 오프라인 컴파일까지만 확인했다.

## 6. 사용자가 직접 확인할 것과 팀 결정

- 새 씬을 더블클릭하고 Play: A 연못이 자연스러운 전방인지, 플레이어/카메라가 겹치지 않는지, 마우스 감도가 기존 맵과 비슷한지 확인한다.
- A 주변의 접지/점프, 타워·D1·D3 계단, B/C 다리와 난간, 지하 바닥을 직접 확인한다. 도달하지 못한 장소는 통과 표시 대신 접근 실패로 기록한다.
- R 직후 달리기·점프·C, 낙사 후 다시 이동, Esc 두 번 복귀, 좁은 공간의 카메라 관통/캐릭터 숨김을 확인한다.
- 첫 퍼즐 예정지가 A가 맞는지, 전망대와 G/W 조망, 임시 다리 유지 여부, 문 개방 전 탐색 범위를 팀원과 결정한다.
- X 해제 조작과 즉시 적용 단위는 Lab의 현재 선택이다. 최종 UX로 확정되었다고 간주하지 않는다. 연출 중 구체 상태·세이브 필요 여부도 별도 결정한다.

Codex에는 “새 맵 A만, 선택한 실제 목표와 안전점에 Lab의 두 해법을 연결하고 Q/X/국소 초기화·착지 회귀까지 완료”처럼 맡긴다. 다른 구역의 아트/진행 구조를 함께 고치라는 넓은 요청으로 묶지 않는 것이 좋다.

**가장 먼저 할 작업은 P0-1 새 맵 Play 탐색 인수 검증이다.** 지금 남은 가장 큰 불확실성은 스크립트 존재가 아니라 Unity importer·MeshCollider cooking·실제 CharacterController·카메라가 팀원 지형에서 함께 작동하는가이다. 이 결과와 위치 기록을 확보한 뒤 A 통합에 착수해야 잘못된 거리·충돌 위에 퍼즐을 올리지 않는다. 이번 작업에서는 후속 퍼즐 이식을 실행하지 않았다.
