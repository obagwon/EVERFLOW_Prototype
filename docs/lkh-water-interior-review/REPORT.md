# EVERFLOW · E 물길과 풍차 내부 점검

**진행 차단** — 이번 Unity Play Mode 표본에서 재현되지 않았다. 동일 세션에서 타이틀부터 외부 엔딩까지 연결을 확인했다. E와 풍차 진입은 플레이어 위치와 수집 상태를 준비한 표본을 사용했다. Windows 배포 빌드와 전체 무보정 플레이는 미검증이다.

## 변경 사항

- **lkh · E 바위 샘** — 기존 물 메시와 노멀맵에 E 전용 깊이·흐름 설정을 적용했다. 얕은 곳의 바닥과 깊은 곳의 청록색을 나눴고, 수문에서 물레방아를 지나 연못으로 이어지는 반짝임을 물길 진행 방향으로 움직이게 했다. 물이 닿는 날개 쪽에 기존 물보라 재질로 입자를 추가하고, 접점에는 흩어지는 거품을 넣었다. 물이 방아에 도달하기 전에 입자가 나오지 않는다. 최종 수면이 기존 설정값인 34.340m에 도달함을 확인했다.
- **inside_fan** — 입구 아치가 화면 양쪽을 가리던 문제를 시작 위치와 카메라 거리 조정으로 줄였다. 첫 잎에 따뜻한 빛을 두고, 위쪽의 푸른 빛과 구분했다. 벽 쪽에 기존 목재 물레방아·통과 금속 재질을 활용한 배관을 배치했다. 씨앗이 수관에 닿으면 벽면 구동륜이 돌고 상부 조명이 밝아진다. 내부의 0/3 표기는 실제 의미에 맞게 ‘순환 복구’로 바꿨다.
- 장치와 발판의 콜라이더, 숨결 조각 획득 판정, 퍼즐과 엔딩 조건을 유지했다. 새 장식과 물보라는 충돌 없이 배치했다.
- E에서 숨결 조각을 얻을 때 별도의 복귀 장치가 없는데도 ‘복귀로 열림’이 붙던 안내를 바로잡았다. 실제 복귀 장치가 연결된 코스에서 해당 문구를 표시한다.
- 마지막 획득 문구 수정은 Unity의 C# 컴파일러로 검증했다. 씬 변경 확인 창에서 에디터가 멈춰 이 문구의 Play Mode 재검증은 남았다.

## Play Mode 검증

| 구간 | 방법과 결과 |
|---|---|
| 타이틀 및 lkh HUD | 타이틀의 시작 버튼을 실행했다. 실제 첫 착지 후 능력 탭 세 장을 넘기고 게임을 시작했다. 수량 0/6과 현재 목표가 표시됐다. |
| E 수문과 물길 | 플레이어를 수문 앞으로 옮긴 뒤 게임의 E 입력 경로로 작동시켰다. 시작 시 물길과 물보라가 꺼져 있었고, 작동 후 물레방아 회전, 물보라, 하류와 연못의 수위 상승, 물방울 출현을 확인했다. 활성 셰이더 오류가 없고 다른 수면에는 E 전용 설정이 적용되지 않았다. |
| E FREEZE와 보상 | 조작 위치와 카메라를 준비해 물방울 모델에 FREEZE 클릭을 넣었다. 별도 탑승 표본에서 얼어 있을 때 콜라이더가 켜지고, 해동 후 접지한 캐릭터가 물방울과 함께 0.38m 이상 올라갔다. 보상 위치 표본에서는 수량이 1/6으로 오르고 깃털이 사라졌다. 샘 입구부터 보상 발판까지의 무보정 연속 이동은 미검증이다. |
| 풍차 문과 내부 진입 | 수집 상태를 5/6으로 준비해 문이 닫혀 있음을 확인했다. 보상 위치에 들어가 여섯 번째 획득을 처리한 뒤 문이 열린 것을 확인했다. 입구 위치에서 실제 진입 판정이 작동해 `inside_fan`이 로드됐다. |
| 내부 퍼즐과 엔딩 | 기본 입구 카메라에서 첫 잎 모델에 BLOOM을 사용했다. 테스트 이동·점프 입력으로 실제 캐릭터를 조작해 잎 두 장과 중층 발코니에 차례로 착지했다. 환기판의 열린 타이밍과 조준 카메라를 재현해 모델을 클릭했다. 씨앗을 향해 FLOW를 보내 수관 회복과 컷어웨이를 확인했다. 통합 세션에서는 내부가 언로드되고 외부 풍차가 회전하며 6/6 엔딩 HUD가 열렸다. |

## 남은 작업

1. **진행 차단** — 재현된 항목은 없다. 공개 전 Windows 빌드로 시작부터 엔딩까지 수집 상태를 바꾸지 않고 통과해야 한다. 엔딩 크레딧의 팀원 이름 자리도 실제 표기로 채워야 한다.
2. **눈에 띄는 연출** — E는 수심과 물의 도착 지점이 가장 선명해졌다. 내부는 입구에서 통로가 열려 보이고, 복구 때 켜지는 상부 조명과 회전 장치가 생겼다. 남은 연출 문제는 큰 컷어웨이에서 씨앗이 작아지는 점과 HUD가 복구 장면을 가리는 점이다.
3. **후속 개선** — 다른 해상도와 배포 PC 성능은 미검증이다. 다음 30분은 **Windows LKH 빌드에서 시작부터 엔딩까지 수집 상태를 바꾸지 않고 한 번 플레이**하며, 특히 E 물방울 탑승과 보상 턱 착지를 기록하는 데 쓰는 것이 우선이다.

검토 기준은 Unity 스킬의 `scene-lighting.md`, `visual-scorecard.md`와 Unity 6000.3의 [MaterialPropertyBlock 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MaterialPropertyBlock.html)를 참고했다.
