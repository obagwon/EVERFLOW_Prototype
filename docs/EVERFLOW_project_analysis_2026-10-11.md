# EVERFLOW 프로젝트 분석 및 다음 작업 제안

분석일: 2026-10-11

**EVERFLOW는 새 통합 맵에 퍼즐 6개와 임시 엔딩까지 연결되어 있지만, 기본 실행·배포 흐름은 아직 기존 퍼즐 검증 씬을 사용합니다.** 현재 구현을 활용하려면 새 맵을 전시용 진입 흐름에 통합한 뒤, 실제 마우스 조작과 초심자 안내를 검증하는 것이 우선입니다.

프로젝트 내부에서 `AGENTS.md`는 발견되지 않았습니다. 이번에는 파일·씬 수정, Unity 실행, 플레이 테스트, 빌드를 하지 않았습니다. 아래는 **코드·씬 참조·설정의 정적 분석**이며, 기존 테스트 기록은 별도 근거로 구분했습니다.

프로젝트에는 역할이 다른 세 구현이 있습니다.

| 구성 | 역할과 연결 관계 |
|---|---|
| `EverflowPrototype` + `MechanicsLab` | 실행 중 실험용 오브젝트를 만드는 초기 기능 실험실. 기본 빌드에서 제외 |
| `EverflowMVP` + `Everflow_6Puzzles` | 기존 퍼즐 검증 버전. 완료 후 Enter로 다음 퍼즐 시작점으로 이동 |
| `EverflowGraybox` + `Everflow_World_Graybox` | 기존 레이아웃·퍼즐 로직을 활용한 독립적인 통합 맵. 구역 사이를 걸어서 이동하고 중앙 물레방아로 돌아오는 구성 |
| `Everflow_Title` | 현재는 기존 `Everflow_6Puzzles`만 로드 |

새 맵은 기존 씬을 함께 로드하는 방식이 아닙니다. 별도 네임스페이스의 플레이어·카메라·진행 코드를 사용하며, 씬에 퍼즐 노드 **14개**, 완료 영역 **6개**, 중간 체크포인트 **3개**가 연결되어 있습니다. 주요 플레이어·노드·전도·탑승·환경 참조에서 끊어진 로컬 참조는 발견하지 못했습니다.

근거: [새 맵 진행 참조](../Assets/Scenes/Everflow_World_Graybox.unity) 7716행, [환경 참조](../Assets/Scenes/Everflow_World_Graybox.unity) 7795행, [맵 구성 코드](../Assets/EverflowGraybox/Editor/EFGrayboxLayout.cs) 40행.

**현재 실행 흐름은 두 갈래입니다.**

- **기본 빌드·Release 메뉴:** 타이틀 → `Everflow_6Puzzles` → 퍼즐별 완료·Enter 이동 → 마지막 `WORLD RESTORED` 표시. 타이틀 복귀와 전체 재시작은 연결되어 있지 않습니다.
- **별도 Graybox 테스트 빌드:** 새 맵으로 바로 시작 → P01~P06 보행 진행 → 물레방아 회전·물 표현 활성화 → 광장 도착 시 전체 조망 → 3초 후 `Restart world` 버튼.

타이틀 버튼의 `StartGame` 이벤트와 UI 참조는 연결되어 있습니다. 다만 **Build Settings만 바꿔서는 통합이 끝나지 않습니다.** 타이틀의 게임 씬 경로, Release 설정 코드, Release 빌드 코드가 모두 기존 씬을 지정합니다.

근거: [빌드 씬 목록](../ProjectSettings/EditorBuildSettings.asset) 7행, [타이틀 진입 대상](../Assets/EverflowMVP/Runtime/EFTitleScreen.cs) 10행, [Release 설정](../Assets/EverflowMVP/Editor/EFReleaseSetup.cs) 39행, [Release 빌드 대상](../Assets/EverflowMVP/Editor/EFReleaseBuild.cs) 110행.

## 2. 기획 목표 대비 구현 상태

여기서 ‘구현 확인’은 코드와 씬 연결을 확인했다는 뜻입니다. 실제 사용감·안정성을 확인했다는 뜻은 아닙니다.

| 기획 목표 | 상태 | 실제 구현과 남은 부분 |
|---|---|---|
| 생명성·동결성·전도성 | **구현 확인** | 성장, 동결·해제, 전원 토글·전도 구현. 능력은 반복 사용 가능 |
| 이동·점프·카메라 | **구현 확인 / 실행 확인 필요** | WASD, 카메라 기준 이동, Space 점프·덩굴 이탈, 우클릭 드래그 회전. 카메라 충돌 보정 있음 |
| 능력 선택·사용 | **구현 확인 / 실행 확인 필요** | 1·2·3 선택, 좌클릭 대상 지정. 사거리 15, 가림 검사, 현재 구역 대상 제한 |
| 핵심 퍼즐 6개 | **구현 확인 / 실행 확인 필요** | 새 맵에 노드·완료 영역 연결. 실제 클릭으로 끝까지 푸는 검증은 필요 |
| 하나의 연결된 맵 | **일부 구현** | 새 맵에서는 보행 연결. 기본 빌드에는 미연결이며 진행 순서 제한이 강함 |
| 퍼즐에 따른 환경 복원 | **일부 구현** | 구역별 식생·문양과 다음 연결 길 활성화. 즉시 나타나는 임시 표현 |
| 최종 물레방아 | **일부 구현** | 여섯 완료 후 회전·입출수 표현, 광장 도착 후 조망 엔딩. 물의 이동 표현·음향은 없음 |
| 초심자의 목표·방향 이해 | **일부 구현** | 영어 조작·해법 안내, 바닥 방향 표식, 완료 수 표시. 단계별 학습 안내와 선택 능력 표시 부족 |
| 사운드·시각 피드백 | **일부 구현 / 음향 미구현** | 상태별 색 변화·문구·오브젝트 활성화. 음원·재생 코드·AudioSource는 확인되지 않음 |

| 전체 초기화·관람객 교대 | **일부 구현** | 새 맵 엔딩에서 전체 재시작 가능. 플레이 도중 운영자 전체 초기화와 타이틀 복귀 없음 |
| 플레이 시간 8~9분 | **실행 확인 필요** | 새 맵의 초심자 플레이 시간 자료 없음. 기존 개발자 1분 기록으로 추정할 수 없음 |

퍼즐별 완료 판정은 다음과 같습니다. **모두 해당 출구의 완료 영역에 들어가야** 완료됩니다.

**기존 검증 기록의 의미**

- 새 맵에는 **55개 자동 검사 통과** 기록이 있습니다. 실제 플레이어·충돌체로 이동하지만 능력은 `EFNode.Apply`로 직접 적용하고, 꽃 시험 시작 위치도 별도로 배치합니다. 실제 조준·클릭 전체 플레이를 보장하지 않습니다.

- 저장된 화면에서 큰 물레방아와 연결 맵 배치는 확인했습니다. 캡처에는 게임 HUD·엔딩 버튼이 포함되지 않아 UI 검증 근거로 사용할 수 없습니다.

## 3. 전시 완성을 방해하는 중요한 문제

1. **전시 목표에 가까운 새 맵이 기본 실행 경로에 없습니다.**  
   현재 Release 메뉴로 빌드하면 기존 검증 씬이 배포됩니다. 씬 목록·타이틀·빌드 도구를 함께 통합해야 합니다.

2. **실제 관람객 입력을 검증하지 않았습니다.**  
   사거리와 가림 검사가 실제 클릭 경로에 있으므로, 자동 검사에서 풀린 퍼즐도 관람객 시점에서는 대상이 잘 안 보이거나 클릭하기 어려울 수 있습니다. 이는 **실행 확인 필요**이며, 확정된 실패로 판단하지 않았습니다.

3. **새 맵에서 선택한 능력이 HUD에 표시되지 않습니다.**  
   기존 HUD에는 `Selected` 표시가 있지만 새 환경 HUD에는 없습니다. 안내도 `grown`, `power`, `frozen` 같은 내부 상태값과 영어 해법 중심입니다. 숫자키를 눌렀을 때 선택 결과를 읽기 어렵습니다.  
   근거: [새 HUD](../Assets/EverflowGraybox/Runtime/EFGrayboxEnvironment.cs) 60행, [기존 HUD](../Assets/EverflowMVP/Runtime/EFHud.cs) 20행.

4. **관람객이 중도 이탈했을 때 초기화 흐름이 부족합니다.**  
   R은 현재 퍼즐만 초기화합니다. 전체 재시작 버튼은 엔딩에서만 제공됩니다. 또한 기존 검증 씬은 F1~F6 이동이 일반 빌드에서도 활성화됩니다.  
   근거: [새 맵 부분 초기화](../Assets/EverflowGraybox/Runtime/EFWorld.cs) 114행, [기존 디버그 이동](../Assets/EverflowMVP/Runtime/EFWorld.cs) 37행.

5. **8~9분과 ‘세계 복원’ 체험의 완성도를 아직 판단할 수 없습니다.**  
   맵이 커졌다는 사실만으로 시간을 충족했다고 볼 수 없습니다. 복원은 즉시 활성화되는 도형, 최종 물은 고정된 면 표현이며 음향이 없습니다. 기능은 연결되어 있지만 변화가 관람객에게 충분히 전달되는지는 별도 검증이 필요합니다.

추가로, 클릭 차단 영역이 고정값 `980×162` 기준인데 HUD 크기와 정확히 일치하지 않습니다. 해상도에 따라 HUD 밖 클릭까지 막는 부분이 생길 수 있습니다. [클릭 영역 처리](../Assets/EverflowGraybox/Runtime/EFPlayer.cs) 51행을 UI 작업 때 함께 정리하는 것이 좋습니다.

누락된 `SampleScene` 항목은 **비활성**이라 현재 빌드 차단 원인으로 볼 수 없습니다. 이번 정적 분석에서는 확정적인 컴파일 오류나 주요 참조 누락을 발견하지 못했습니다.
