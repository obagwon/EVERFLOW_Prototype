# EVERFLOW LKH 퍼즐 맵 플레이 검증

대상은 `EVERFLOW_Map1123_puzzle_lkh` 씬이다. Unity 6000.3.21f1에서 씬·프리팹·게임 코드를 읽기 전용으로 다뤘다.

**판정은 개선 필요다.** 기본 전망대에서 별 6개를 모아 풍차 문을 통과했다. 진행을 영구적으로 막는 사례는 이번 표본에서 재현되지 않았다. 다만 **W 날개와 B 누수구가 정상 조작 위치에서도 카메라 각도에 따라 선택되지 않는다.** 두 구간 모두 사거리 안이었으며, 카메라 각도나 조작 위치를 바꾸면 진행할 수 있었다.

## 검증 방법

- **연속 Play**에서는 저장된 기본 위치부터 키보드·마우스 입력만 사용했다. W에서 4/6 상태로 조준 실패를 기록한 뒤, 같은 Play 세션에서 카메라를 돌려 이어 갔다. 플레이어 위치나 퍼즐 상태를 강제로 바꾼 횟수는 0회다. [전망대에서 W까지](evidence/EVERFLOW-Audit-01-Continuous.txt) · [W 재조준에서 풍차까지](evidence/EVERFLOW-Audit-01-Continuation.txt)
- **별도 Play 표본**에서는 조작 위치를 반복 재현하기 위해 런타임에서만 플레이어 위치와 일부 선행 상태를 설정했다. 조준, 점프, 활공, 복귀 입력은 이 위치에서 직접 시험했다. 센터와 좌우 약 0.65m를 포함해 조준을 46번 측정했고, 이 중 43번은 의도한 대상에 커서가 잡히고 기본 발동 조건도 충족했다. E의 회전 타이밍은 기본 조건과 별도로 판정했다. [조준·충돌·치수 원자료](evidence/EVERFLOW-Audit-02-Geometry-Aim.txt) · [복귀·착지 원자료](evidence/EVERFLOW-Audit-03-Edges-Recovery.txt)
- **콜라이더 치수**는 Unity 월드 단위로 측정했다. 이 문서에서는 1유닛을 1m로 표기한다. 발판 간격은 진행축을 따라 양쪽 밟는 면의 끝을 비교했다. 아래 표에서 ‘겹침’은 진행축 투영값이다. 이 수치는 실제 통과 여부와 함께 읽어야 한다. 플레이어 설정값은 캡슐 높이 2.00m, 지름 0.80m, Step Offset 0.55m, 기본 점프 높이 1.35m다.

## 경계·우회·가독성 판정

- **사거리와 발판 경계.** B 누수구의 같은 방향 표본에서 발판 반경 **6.50m**는 허용됐고 **6.70m**는 발판 조건으로 차단됐다. 표식 거리 **17.90m**에서는 발판 조건 안내, **18.10m**에서는 사거리 안내가 표시됐다. 최대 사거리 **18.00m** 안에서도 개별 발판 조건을 적용한다. 이 경계값은 런타임 위치를 고정해 읽은 결과다. 실제 접근 가능 여부와 조준 성공은 위의 발판 근처 표본과 따로 확인했다.
- **우회.** 여섯 코스에서 마지막 기믹을 풀기 전에 걸어서 또는 점프로 보상 쪽에 접근했으며, 시도한 경로에서 별을 획득하지 못했다. B·D·E·W·채광실의 보상실 전면·측면·복귀 방향은 캡슐 검사로 막힘을 확인했다. D·채광실은 실제 상부 낙하도 시험했다. C에서는 발사턱에서 기본 이동으로 섬을 향했을 때 낙하 복귀가 발생했다.
- **진행 유지.** B에서 별을 얻어 복귀로를 연 뒤 `R`로 돌아갔을 때 수집 상태 **1/6**, 별 모델 비활성 상태, 열린 복귀로가 유지됐다. [획득 후 복귀 로그](evidence/EVERFLOW-Audit-06-Reward-Retention.txt)
- **안내와 효과.** 1920×1080에서 밝은 물·하늘 앞의 HUD, 능력 타일 선택 상태, 실제 누수구 선택 성공 문구를 읽을 수 있었다. B는 동일 표식의 정상 조준 화면과 다른 표식이 가로채는 화면이 구분됐고, W는 도개교가 가리는 동안 대상 강조도 화면에서 가려졌다. B의 컷어웨이 후 이동 복구를 연속 Play에서 확인했다. 카메라가 모델 내부로 실제 들어가는지에 대한 전 구간 충돌·회전 각도 검사는 **미검증**이다.
- **검증 범위.** 코스 순서 전체 조합, 초회 플레이어가 안내만 보고 입구를 발견하는 시간, 먼 거리에서 모든 효과의 구분 가능성, 다른 해상도와 전시 PC Windows 빌드는 **미검증**이다. 이번에 확인한 옆길·복귀로·상부 낙하 사례 외에도 모델 교체 뒤 새 지름길이 생길 수 있다. 연속 Play를 완료한 구간과 별도 런타임 표본에서 새 Unity Console 오류는 확인되지 않았다.

## 팀원 맵 모델 교체 후 다시 잴 것

1. **B와 W부터 조준선을 재검증한다.** B는 발판 중앙과 좌우에서 물받이·누수구 투영을 비교한다. W는 세운 도개교·기둥·새 날개가 동시에 화면에 들어오는 각도, 표식부터 캐릭터까지의 발동선을 본다. B 표지의 정면 방향도 같은 동선에서 확인한다.
2. **실제 콜라이더의 가장자리를 비교한다.** B 첫 잎 **+0.41m**와 마지막 간격 **0.57m**, E 선반–잎 연결부 **+0.03m**, W 도개교 양쪽 겹침, C 부두–배의 높이 **0~0.01m**를 기준점으로 기록한다. 새 메쉬의 시각적 끝과 실제 콜라이더 끝이 일치하는지 함께 확인한다.
3. **C와 채광실의 이동 경로 전체를 본다.** C 출발턱 **2.15×1.85m**, 착지 면 **3.40×3.20m**, F 창틀 **폭 2.95m**와 보상실 옆면 출구를 기준으로 가장자리 출발과 착지를 반복한다. 새 난간·돌출 장식·창틀이 비행 캡슐과 카메라에 닿는지도 확인한다.
4. **진행 잠금과 출구를 다시 시험한다.** F·D 지붕과 측면, W 리프트와 우회로, B·E·W 복귀로, 풍차 양쪽 문을 5/6과 6/6에서 다시 테스트한다. 마지막으로 0/6 분기부터 풍차 문턱과 엔딩까지 한 번에 플레이한다.
