# EVERFLOW v2 퍼즐 씬 배치 정리

대상은 `Assets/Scenes/Everflow_Map_v2_test_with_puzzle.unity`다. 씬을 열고 **Play**해야 런타임 배치 정리가 적용된다. 원본 맵 씬, 팀원 FBX, PuzzleLab, 물 에셋, 빌드 목록과 퍼즐 규칙은 보존한다. 씬 YAML을 다시 저장하는 대신, 이 씬의 기존 `EFV2PuzzleWorld`가 호출하는 생성 코드에 반영했다.

## 바로 확인할 위치

| 위치 | 변화 |
| --- | --- |
| S 앞 A 연못 `(-46,0,-13)` | 반투명 바람 상자와 충돌이 없는 옛 튜토리얼 받침을 숨김. 떠 있는 흰 발판/중복 바닥판 정리 |
| C 입구 `(-64,6,-40)` | 카메라 앞의 큰 파라솔을 같은 테라스 서쪽으로 옮김. 성장한 잎 밑 직사각형 받침을 실제 잎 형태의 충돌 셸로 교체 |
| 탑 내부와 D1 발코니 | 기존 착지판 위에 덧씌워진 안전 지점 판 제거. D1 횃불을 남쪽 가장자리로 옮겨 카메라와 캐릭터 사이를 가리지 않게 함 |
| D5 수로 교차부 `(-56,-5.35,-63.9)` | 평평한 서비스 보행판을 나누고 고정 수로 위에 작은 보행교와 양쪽 진입 계단을 배치 |
| W 정원 `(-84,-17.3,0)` | 서로 겹치던 큰 잎 8개의 크기/피벗/배치를 정리. 줄기가 있는 작은 새싹으로 만들고 중복 착지판·불필요한 미세 계단 제거 |

## 발견한 문제와 수정

1. **바람 미리보기 상자가 실제 풍경을 덮음.** `VOL_A_Wind`, `VOL_C_Wind`, `VOL_D5_Wind`의 Renderer만 끈다. GameObject와 기존 기능/콜라이더 상태는 건드리지 않는다. 방향 선택은 기존 FLOW 장치 표시를 그대로 사용한다.
2. **A의 사용하지 않는 발판이 실제 이동 발판처럼 보임.** 충돌이 이미 꺼져 있던 `PH_A_Tut_MovingPad`, `PH_A_Tut_WitheredPad`의 Renderer도 숨긴다. 현재 A 잎과 뿌리 해법은 유지한다.
3. **중복 안전 지점 바닥판.** 기존 바닥이 9개 표본 지점 전체를 받치고 높이 차가 0.18m 이내인 경우에만 덧댄 판의 Renderer와 BoxCollider를 끈다. 움직이는 발판과 다른 안전 지점 판은 지지 근거에서 제외한다. 실제 맵에서는 **17개**가 정리됐다. 원래 지형/데크의 충돌과 체크포인트 Trigger/리스폰 위치는 유지한다. 지지가 부족한 G·D1 하단·D2·D4의 판은 남겼다. 근거는 `visual-cleanup/after-cleanup.txt`.
4. **C 잎보다 큰 직사각형 받침.** 성장한 잎과 같은 메시·위치·회전·성장 배율을 가진 렌더 없는 MeshCollider 셸로 교체했다. 원래 작은 이동 캐리어의 충돌체와 타깃 Proxy는 유지한다. 판정 셸은 잎과 함께 움직이고 성장/초기화 상태를 따른다. 파라솔 `PROP_C_ParasolLeaf01`은 서쪽 12m, Z -0.5m 이동했다. 비충돌 장식이며 능력 대상/레일/착지점은 이동하지 않았다.
5. **D5 보행판의 수로 관통.** 기존 27m 보행판을 동·서 구간으로 나누고 X -56의 고정 수로 위에 폭 3.2m, 통행 폭 2.4m, 상면 Y -5.35m의 다리를 설치했다. 양쪽 1m 진입 구간은 3단 계단과 연속 지지면을 갖는다. 나머지 서비스 길은 원래 높이 -5.95m다. 정상 공급 때 고정 수로와 난간 위로 건너며, 누수 자체의 기존 물 표시와 판정은 바꾸지 않았다.
6. **큰 조준 구체가 장치를 가림.** 실제 조준용 SphereCollider 크기와 위치는 유지하고 렌더링만 별도 자식으로 55% 크기로 표시한다. 장치 색 변화와 조준 대상 연결은 그대로다. 능력 구체·선택·조작 규칙은 수정하지 않았다.
7. **정원 잎 겹침과 이중 바닥.** 기존 잎 메시의 바운딩 중심을 보정하고 긴 변을 1m 기준으로 정규화해 배치했다. 복원 후 최대 길이 약 0.65m, 간격 0.9m이며 두 줄 사이 통행 공간을 남긴다. 작은 줄기는 비충돌 장식이다. 색을 주변 잎에 맞춰 낮추고, 정원 착지판과 기존 데크가 겹치던 미세 계단을 정리했다.
8. **D1 횃불이 캐릭터를 관통해 보임.** 첫 정상 입력 경로의 캡처에서 발견했다. `UG_Torch01`을 `(-2,0,-3.8)m` 이동해 발코니 남쪽 가장자리에 놓았다. 원래 비충돌 장식이며 바닥 높이는 유지한다. 이후 다시 정상 입력 경로를 실행했다.

## 실제 Play 검증

| 구분 | 실행 내용 / 결과 근거 |
| --- | --- |
| 일반 입력 연속 경로 1 | S→A 뿌리→B→G 뿌리→탑·D1→D3 덩굴→D5 보행교·우회→D4 뿌리→D2 주 출구→W→정원→Enter 재시작. 최종 18개 통과, `visual-cleanup/runtime-route-bloom.txt` |
| 일반 입력 연속 경로 2 | A 잎→C 성장 잎 탑승·착지→G 수차→D1 계단→D3 얼음→D5 정렬·고정→D4 수차→주 물길 동결·해동→W→정원→Enter. 28개 통과, `runtime-route-alternate.txt` |
| 움직이는 장치·낙하 분리 검사 | 초기 위치/공급은 강제 설정하고 이후 입력으로 B 돌 발판, B↔C 연결길, 부두 잎 탑승 및 실제 낙하·복귀를 확인. 15개 통과, `runtime-platforms-isolated.txt` |
| 물 상태 회귀 | 강제 상태 검사로 정상/우회 공급, 세 분기, 동결·해동, 기존 얼음 충돌, 물레 복원·재시작 확인. 23개 통과, `runtime-water-integrated.txt` |
| 컴파일·참조·보존 | Unity 임포트/Play와 별도 Roslyn 구성 검사. 보호 파일 해시와 Git 사용자 diff 비교는 `preservation-results.json` |

연속 경로는 Input System의 합성 키보드·마우스 이벤트로 기존 CharacterController와 Cinemachine, 조준·구체·문·발판 코드를 실행한다. 해당 경로에는 강제 순간이동/장치 Apply/문 Tick 호출이 없다. 사람의 첫 탐색 플레이와는 다르다. 검사 카메라 캡처나 강제 상태 회귀를 보행 완주로 계산하지 않는다.

정상 경로 관찰기는 실제 카메라의 0.08m 근접 충돌 샘플도 기록한다. 첫 뿌리 경로에서는 34,758프레임 중 21샘플이 검출됐다. 이 숫자를 카메라 끼임이 전혀 없다는 근거로 쓰지 않는다. 기존 카메라 알고리즘은 이번 작업에서 수정하지 않았다. 최종 실행 값은 `camera-route-bloom.txt`를 따른다.

최종 뿌리 경로는 35,229프레임 중 근접 20샘플이다. 정상 경로 캡처에서 D1 횃불이 캐릭터를 가리는 문제를 수정하고 재실행했으며, 모든 위치의 근접 샘플 원인을 추적·해소했다고 주장하지 않는다. 뿌리 경로 정원 도착은 최종 **138.14초**, 잎 경로는 **136.85초**였다. 미리 정한 입력 경로의 unscaled 시간이며 사람의 첫 플레이 시간이나 15~20분 기획 목표 실측값은 아니다.

## 변경 파일과 재현

- `Assets/EverflowMap/Runtime/EFV2PuzzleAssembly.cs`: 잎 충돌 셸, D5 보행교, 작은 조준 표시, 정원 생성과 정리 호출.
- `Assets/EverflowMap/Runtime/EFV2VisualCleanup.cs`: 이 퍼즐 씬의 미리보기 렌더·장식 위치·중복 착지판 정리. 실행마다 동일하게 적용한다.
- `Assets/EverflowMap/Runtime/EFV2Plant.cs`: 정원 복원 색 조정.
- `Assets/EverflowMap/Editor/EFV2VisualChecks.cs`: 비교용 고정 카메라 캡처와 정상 경로의 관찰 전용 기록기.
- `Assets/EverflowMap/Editor/EFV2EditorBridge.cs`, `tools/request_v2_editor.py`: 고정된 `visual-before` / `visual-after` 검사 명령.
- `tools/verify_visual_cleanup.py`: 작업 시작 해시·GUID·기존 Git 변경 보존 검사.

원래 씬/FBX를 편집하지 않았고 물 셰이더·재질·공급 연동 코드도 수정하지 않았다. 씬의 기존 World가 생성할 때 정리가 적용되므로 Play를 다시 눌러도 유지된다. 빌드 목록과 파이프라인/색 공간은 보존한다. 테스트 중 임시 배경 실행 설정은 마지막 참조 검사에서 작업 시작 값으로 원복한다.

## 남은 부분

- 기본 계단·뿌리 다리·회랑은 아직 단순한 프로토타입 형태다. 전체를 새 모델로 교체하는 작업은 하지 않았다.
- 높은 유적의 문틀과 기존 수로, 지하의 두꺼운 벽은 원래 형태를 유지했다. 문 통과는 실제 경로로 확인했지만 모든 시점의 미세한 겹침까지 조사한 결과는 아니다.
- 월드 안내 문구와 HUD 디자인/내용은 유지했다. 이번 작업은 모델과 통행 배치에 집중했다.
- 중복 바닥판 판단은 고정 맵의 9지점 지지 검사와 실제 경로 재검증을 조합했다. 모든 비정상 이동·점프·카메라 각도에 대한 사람 검증은 남는다.
- 모바일/다른 그래픽 API/배포 빌드는 이번 검사 범위에 포함하지 않았다.
