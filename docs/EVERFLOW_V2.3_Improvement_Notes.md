# EVERFLOW v2.3 보완점과 검증 계획

**2026-11-06 · 기획 검토 및 플레이테스트용**

v2.2 기획서, 씬·스크립트 가이드, 후속 작업 문서와 FBX 구조도를 대조했다. 아래 우선순위와 해결안은 검토 제안이다. 씬의 구현·검사 상태는 첨부 자료를 기준으로 정리했다.

## 1. A를 붙이기 전에 확인할 것

| 우선 | 보완점 | 근거와 확인 방법 |
| --- | --- | --- |
| **P0** | **Cinemachine 전환 후 탐색을 다시 확인한다.** | 첨부 가이드의 이동 방향과 리스폰 시점 복구는 `EFMapCamera`를 참조하던 구성이다. 현재 씬에서 마우스로 시점을 돌린 뒤 WASD, 점프, R/낙사 복귀 직후 이동을 확인한다. 좁은 계단과 벽 앞에서는 카메라 가림과 조준을 확인한다. 기존 검사 메뉴가 `EFMapCamera`를 전제로 하면 검사도 현재 연결에 맞춘다. |
| **P0** | **A에서 두 해법의 도착 지점을 먼저 고정한다.** | FBX 조사에서 A 연못 주변 일부 지점은 보행 지형이 검출되지 않았고, B/C 임시 다리 주 보행판은 y≈6으로 보고됐다. 수치는 실제 통과 판정과 별개다. 팀원과 S의 시작 방향, A의 착지면·안전 선반, B/C 접속점을 지정하고 두 해법의 발판 높이·간격을 현재 점프로 직접 잰다. |
| **P0** | **새 맵에서 구체 자동 회수를 먼저 시험한다.** | 실험실의 `Q` 회수로는 v2의 거리 회수와 즉시 재발사를 확인할 수 없다. A에서 같은 능력으로 대상을 바꿀 때와 멀어질 때를 각각 테스트하고, 성장·고정·방향이 남는지 확인한다. 발사 중 연속 클릭, 회수 중 재사용, 이동하는 잎의 경계 통과, 낙사·복귀에도 구체가 중복되거나 사라지지 않아야 한다. |
| **P0** | **퍼즐을 옮기기 전에 좌표와 상태 관리 주체를 정한다.** | Lab의 이동 레일, 문 닫힘 위치, 수로 연결점, 복귀 범위에 월드 좌표가 있다. A 한 구역의 기준점으로 다시 연결한 뒤 이동·초기화를 실행해 제자리로 복구되는지 확인한다. 시작 배치·커서·복귀를 Exploration과 PuzzleLab이 동시에 처리하지 않도록 씬에서 담당을 하나로 정한다. |

**자동 회수의 우선 결정**은 효과를 적용하는 도중 새 입력을 받았을 때의 처리다. 첫 이식에서는 한 번의 적용을 짧게 끝내는 방식부터 검증한다. 다른 유효 대상을 선택하면 기존 구체가 새 대상으로 바로 이동해야 한다. 거리 기준은 잎이 움직이는 상황을 포함해 조정하고, HUD나 구체의 귀환 궤적으로 회수 이유가 보이는지 확인한다. 구체 회수와 효과 해제는 별도 동작으로 다룬다.

## 2. 퍼즐 구성에서 보완할 것

| 우선 | 발견한 문제 또는 검증할 가설 | 보완안과 완료 기준 |
| --- | --- | --- |
| **P1** | **D3의 잎 해법은 초기 물 공급에 따라 막힐 수 있다.** 작업대(D3)에서 D5를 고쳐야 중앙에 물이 들어오는 구성이라면, 작업대에 가는 데 필요한 잎도 처음에는 움직이지 않을 수 있다. | 현재 Lab에서 D5 연결 전 부두 분기에 실제 운반이 성립하는지 먼저 확인한다. 막힌다면 부두로 잎을 옮길 만큼만 흐르는 초기 물을 명시하고 최종 공급과 구분하거나, 잎 해법을 복구 후 지름길로 설명한다. 어떤 경우에도 덩굴이나 얼음 등 초기 상태에서 가능한 접근로가 하나 이상 있어야 한다. |
| **P1** | **지하에서는 실패 원인이 한눈에 구분되어야 한다.** D5 누수, D2 방향, D4 폐쇄, 물길 동결은 모두 W에 물이 닿지 않는 결과로 이어진다. | D1에서 끊긴 연결과 닫힌 출구를 보여준다. 진행 중에는 물이 새는 곳, 분기에서 물이 실제로 향하는 곳, 닫힌 수문 앞에 물이 멈추는 곳, 얼음 앞에서 흐름이 끊기는 곳을 각각 보여준다. 테스트 참가자가 설명을 듣기 전에 막힌 위치를 가리킬 수 있는지 본다. |
| **P1** | **얼음길을 쓴 플레이어에게 해동 후 돌아올 길이 필요하다.** 얼음이 통행과 공급을 동시에 좌우하면 작업을 끝낸 뒤 자기 길을 없애게 될 수 있다. | D3와 중앙 사이의 가장자리 보행로를 확인한다. 얼음길로 건넌 후 안전한 위치에서 해동하고, 분기대와 수문에 재접근해 W까지 복원한다. 조준 시 수로 구조물 고정과 물 동결, 해제를 구분해 표시한다. 해제 입력은 이 경로를 플레이해 정한다. |
| **P1** | **B/C가 실제로 서로 다른 선택인지 확인해야 한다.** 구조도와 Lab은 배치와 개별 장치를 보여주지만 새 맵에서 연결길을 통과했다는 증거는 없다. | B는 뿌리·돌 발판, C는 잎·바람이 주로 쓰이게 한다. B만 사용해 G에 가기, C만 사용해 G에 가기, 중간에 갈아타기를 각각 확인한다. C의 높은 선반은 카메라에서 착지점이 보이고, 떨어져도 근처에서 다시 시도할 수 있어야 한다. |
| **P2** | **쉬운 해법만 연달아 선택하면 FREEZE를 건너뛸 수 있다.** A·B·G·D5·D4에는 BLOOM 중심 대안이 있고, 마지막 D2 분기는 FLOW로 해결한다. | 초심자가 스스로 고른 경로와 실제 능력 사용을 기록한다. FREEZE를 경험시키고 싶다면 A의 잎 고정이 뿌리 경로만큼 눈에 잘 띄게 하고, 지하에서 가동 수로를 멈추거나 얼음길을 쓰는 이득이 보이는지 먼저 확인한다. 모든 능력의 사용을 필수 조건으로 만들지는 별도 기획 결정이다. |
| **P2** | **W까지 물이 가는 과정과 플레이어 출구를 함께 확인해야 한다.** 지하 판정이 성공해도 문 충돌이나 출구 단차가 남으면 복원된 정원까지 걸어갈 수 없다. | 문짝과 충돌체가 함께 이동하는지, 3초 출발값에 도달하기 전에 공급이 끊기면 타이머가 초기화되는지 확인한다. 복원 카메라 뒤 조작을 돌려받아 D4에서 W까지 안전하게 걷고, 이후에 계속 탐험할 수 있는지 확인한다. |

## 3. 실제 플레이에서 남길 기록

| 언제 | 무엇을 기록할까 |
| --- | --- |
| **새 맵 탐색 직후** | 시작 위치와 처음 보이는 목표, A 접근, 계단·다리·좁은 벽·낙사/R. 막힌 곳은 위치, 상황, 다시 시도하는 방법을 남긴다. |
| **A 이식 직후** | 두 해법의 실제 착지, 자동 회수 두 조건, 연속 사용 후 이전 효과 유지, 낙하 뒤 재시도. 두 경로를 각각 직접 걷고 점프한다. |
| **지하 연결 직후** | D5 정렬·우회 각각의 공급, D4 뿌리·수차 각각의 개방, 주 출구 전환 뒤 걸쇠 유지, 얼음 차단·해동, D4→W 통과를 확인한다. |
| **첫 완주 가능 시점** | 초심자가 별도 설명 없이 플레이할 때 지상 경로 선택, 지하에서 처음 이해한 장치, 힌트 요청, 낙하, 마지막 복원까지 걸린 시간을 적는다. 15~20분은 목표이며, 이동·재시도에 쓴 시간과 퍼즐을 이해하는 데 쓴 시간을 구분한다. |

첨부 자료에 나온 **과거 PuzzleLab 45개 검사 통과**와 **관리 코드 38개 검사 통과**는 검증 범위가 다르다. 새 맵 Play 결과는 현재 씬, 실행 시각, 입력·물리·상태 검사 범위를 함께 기록한다.
