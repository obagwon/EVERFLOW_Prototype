# EVERFLOW v0.2 Puzzle Lab 사용 안내

작성: 2026-11-04. 기준: [EVERFLOW_redesign_v0.2.md](EVERFLOW_redesign_v0.2.md)와 이번 작업 명세. 단일 에이전트 작업.

**현재 `Assets/Scenes/Everflow_V02_PuzzleLab.unity` 씬이 존재하며, 2026-11-04 안내판 정리 작업은 이 씬을 재생성하지 않고 수정·저장했다.** T01~T04와 지하 통합 구역에 박스형 안내판 5개를 적용했다. 이번 세션의 Scene/Play 화면 확인은 실행 계정의 Unity 라이선스 IPC 제한으로 미검증이다. 아래 7절은 최초 구현 세션의 검증 기록이며, 현재 안내판 변경과 검증 범위는 8절을 참조한다.

## 1. 씬 생성과 열기

- 생성 대상: `Assets/Scenes/Everflow_V02_PuzzleLab.unity`
- T01 단독 확인용 생성 대상: `Assets/Scenes/Everflow_V02_PuzzleLab_T01_Check.unity`
- Unity: **6000.3.21f1**, 기존 **URP 17.3.0**, Input System **1.20.0**, 입력 설정 Both 유지.
- 새 패키지·외부 배경·캐릭터 에셋을 추가하지 않는다. 기본 도형, URP 재질, TextMesh와 IMGUI만 사용한다.

Unity Hub에서 기존 프로젝트를 정상 사용자 세션으로 열고 스크립트 컴파일이 끝난 다음 다음 순서로 실행한다. 라이선스 연결 실패가 계속되면 먼저 Hub/Editor의 로그인·라이선스 연결을 정상화해야 한다. 이번 오류만으로 라이선스 만료라고 판단할 근거는 없다.

1. 현재 편집한 씬을 저장한다. 생성 도구는 미저장 씬이 있으면 중단하며 기존 씬을 저장하거나 덮어쓰지 않는다.
2. `Tools > EVERFLOW > v0.2 Puzzle Lab > Create or Open T01 Check`
3. 같은 메뉴의 `Run T01 Checks`. Play로 진입해 T01 자동 검사를 실행하고 종료한다. `docs/puzzle-lab/t01-play-checks.txt`의 실패 항목을 먼저 확인한다.
4. `Create or Open Lab`으로 전체 씬을 생성한다. T01~T04와 지하 대공간을 함께 만든다.
5. `Validate Open Lab References`로 생성된 실제 오브젝트 참조를 확인한다. 생성 시에도 이 검사가 저장 전에 실행된다.
6. `Run Saved Lab Checks`로 저장된 기본 경로의 전체 씬을 검사한다. 결과는 `docs/puzzle-lab/full-play-checks.txt`에 기록한다.
7. 직접 Play를 눌러 실제 마우스 조준·점프·탑승과 안내 시인성을 확인한다.

`Create or Open Lab`은 파일이 이미 있으면 **열기만 한다**. 기존 씬을 다시 생성하거나 오브젝트를 추가하지 않는다. 생성 코드를 갱신한 뒤 새 배치를 확인하려면 `Generate Fresh Copy (preserve existing)`를 사용한다. `Everflow_V02_PuzzleLab 1.unity`처럼 사용하지 않은 경로에 새 씬을 만들며 기존 수동 편집본은 보존한다. 복사본 검사에는 `Run Open Lab Checks`를 사용한다.

Play 중에는 생성할 수 없다. Play 검사는 메모리상의 상태만 바꾸며 씬을 저장하지 않는다. 검사 제한 시간은 150초이며 시간 초과 시 별도 `play-check-timeout.txt`를 기록한다. 과거 결과 파일이 있더라도 현재 실행 성공으로 간주하지 않는다.

| FLOW 화살표 좌클릭 | 해당 화살표 방향 확정. 화살표 이름과 HUD 미리 보기를 확인 |

Esc 메뉴에서는 이동·카메라 입력을 멈추고 커서를 보여 준다. 구역 이동·초기화·재개 버튼을 클릭할 수 있다. 디버그 이동은 시작 위치로만 이동하며 성공 상태를 설정하지 않는다. `navigationUsed`는 별도 기록이다.

조준은 중앙 카메라 광선, 플레이어와 대상 사이 가림, 플레이어 기준 14m 사거리를 확인한다. 잘못된 능력, 가림, 사거리, 다른 대상에 놓인 구체가 있으면 HUD에 이유를 표시한다. FLOW를 새 구역에 배치하려면 Q로 회수해야 한다. 같은 구역의 방향 재설정에는 회수가 필요 없다.

X로 발판 성장을 취소하거나 물을 해동할 때는 그 대상 구역의 안전 시작점으로 먼저 이동한다. 움직이는 발판의 정지 해제는 현재 위치에서 재개하며 강제로 시작점에 옮기지 않는다. X를 누르기 전에 하단 조준 안내의 `RELEASE` / `THAW` 결과를 확인한다.

## 3. 구체와 변화 유지 규칙

- `PuzzleLab.slots`는 정확히 세 개다. BLOOM 하나, FREEZE 하나, 물·바람을 함께 쓰는 FLOW 하나다.
- 배치는 짧은 완료 단위로 즉시 적용한다. 부분 성장·이동 중 적용 상태는 구현하지 않았다.
- 각 `LabTarget`의 `LabWorldState`가 성장·고정·동결·방향을 보관한다. 구체 슬롯과 독립적이다.
- Q는 슬롯만 비운다. 여러 대상에 순서대로 적용하고 회수하면 모든 완료된 변화가 함께 남는다.
- 새 FREEZE 대상에 배치해도 이전 대상은 풀리지 않는다. X로 해당 대상의 정지를 해제하거나 물을 해동해야 한다.
- FLOW는 물체를 직접 끌지 않는다. 표시된 물살·바람 구역의 2~3개 방향을 선택하면 연결된 잎·회전체·수로가 반응한다.
- 비활성화·파괴된 대상은 관련 슬롯을 반환한다. Unity의 파괴된 오브젝트 참조도 사용 가능 상태로 정리한다.
- 구역 초기화는 해당 대상과 구체 참조, 이동체, 문, 성공만 복구한다. 다른 구역의 완료된 변화와 구체 배치는 보존한다.
- 지하 D1~D5·W는 하나의 초기화 단위다. 디스크 저장·불러오기는 없다.

## 4. 구역별 사용

### T01 — A / 같은 둔덕

목표는 높이 2.4m의 같은 둔덕 위 노란 표시에서 착지하는 것이다. 일반 점프 높이는 1.35m다.

1. **뿌리:** `A ROOT STEP`에 BLOOM 적용 → Q → 생긴 높이 1.2m 발판에 점프 → 둔덕으로 점프.
2. **잎:** `A WATER CURRENT`를 `DEPARTURE`로 선택 → Q → 출발지 쪽으로 온 `A LEAF`에 점프 → 물살을 `MOUND`로 변경 → Q → 잎을 FREEZE → Q → 둔덕에 착지.

특정 능력 사용 기록을 조건으로 검사하지 않는다. 목표의 지면에 도달하면 인정한다. 안전 선반은 낮은 복귀 위치이며 둔덕으로 이어지는 계단이 아니다. 최초 잎 위치는 추가 조작 없이 둔덕으로 점프하기 어렵도록 뒤쪽에 두었다. 이 거리의 실제 조작성은 Play에서 확인해야 한다.

정지 해제는 잎을 조준하고 2 + X. 현재 물살을 따라 현재 위치에서 다시 움직인다. 물에 떨어지면 Backspace로 돌아가거나 R로 이 구역만 초기화한다.

### T02 — B / 뿌리 테라스 두 경로

- **긴 경로:** `B LONG ROOT ROUTE`를 성장시키고 뒤쪽 뿌리 세 구간을 따라 같은 테라스에 도착한다.
- **짧은 경로:** `B WIND ROTOR`의 `FORWARD`를 선택하고 회전체가 작동시키는 이동 발판에 탑승한다. 테라스 가까이에서 FREEZE하여 점프한다.
- 발판은 폭 2.6m의 제한된 왕복 레일을 사용한다. 정확한 회전 각도 한 점을 요구하지 않는다. 방향과 왕복 위상, 고정 상태가 실제 이동에 반영된다.
- X로 고정을 풀면 기존 위치·왕복 위상을 이어 간다. R만 시작 위치를 복구한다.

### T03 — C / 바람과 넓은 잎

1. `C UNFOLDING LEAF`를 BLOOM으로 펼치고 Q.
2. `C WIND ZONE`에서 `LOW SHELF` 또는 `HIGH SHELF` 선택 후 Q.
3. 잎에 탑승하여 이동하고 FREEZE 후 Q.
4. 높이 2.4m 또는 3.6m의 넓은 선반에 착지한다. 둘 다 인정한다.
5. 2 + X로 잎을 해제하면 남아 있는 풍향에 다시 반응한다. `RETURN` 방향으로 잎을 회수할 수도 있다.

작은 잎은 폭 1.3m, 속도 30%, 레일 도달 범위 25%다. 펼친 잎은 폭 3m, 전체 속도·도달 범위를 사용한다. 자유 비행이나 글라이더 조작은 없다. 아래 복귀 높이로 떨어지면 시작점으로 돌아가며 상태는 유지한다.

### T04 — G / 수차와 석문

- **수차:** `G WATER BRANCH`를 `SMALL WHEEL`로 선택 → 문이 끝까지 올라가 걸쇠가 돌아갈 때까지 기다린다.
- **뿌리:** `G GATE LIFT ROOT`를 BLOOM으로 성장시킨다. 제어된 문 이동으로 뿌리와 문을 연결한다.
- 두 방법 모두 완전히 열리면 걸쇠가 유지한다. Q나 `SPILL` 방향 변경으로 문이 닫히지 않는다.
- 부분 개방 상태에서 공급을 끊으면 걸쇠 전에는 문이 내려온다. 완전 개방·통과를 비교한다.
- 프레임, 문짝, 수차 날개, 노란 걸쇠, 성장 뿌리를 별도 도형으로 배치한다.

### 지하 — D1~D5 및 W

F5는 입구 발코니로 이동한다. 지상 구역 뒤 공용 보행로와 서쪽 서비스 계단으로도 내려갈 수 있다. 천장을 막지 않은 한 대공간이며 D1에서 D5 상부 수로, D3 작업대, D2 분기, D4 수문과 W를 함께 관찰하도록 배치했다.

- **D1:** 왼쪽 넓은 계단으로 내려간다. Backspace는 발코니 안전점으로 복귀한다.
- **D3:** 성장 덩굴 계단, `MAINTENANCE DOCK` 물살로 운반한 잎, 지정된 `D3 ICE CROSSING`의 얼음 발판을 각각 시험한다. 서쪽 고정 계단은 상태 수정용 기본 보행로다.
- **D5 구조물 해법:** 작업대에서 `D5 ALIGNMENT WIND`를 `CONNECT`로 선택한다. 도수로가 수신 수로의 0.5m 이내로 정렬되면 연결을 인정한다. `D5 AQUEDUCT STRUCTURE`를 FREEZE해 현재 위치를 유지할 수 있다. 이미 고정했다면 X로 해제해 재정렬한다.
- **D5 대체 해법:** `D5 BYPASS ROOT GATE`를 BLOOM으로 성장시키면 우회 수로 문이 올라가고 우회 공급이 열린다.
- `D5 WATER INSIDE (not structure)`는 구조물과 **별도의** 물 동결 대상이다. 구조물 고정은 내부 물을 막지 않는다. 내부 물을 얼리면 상부 직접 공급만 막는다. 우회 공급은 별개다.
- **D2:** `MAINTENANCE DOCK`, `SMALL WHEEL`, `MAIN EXIT` 중 하나만 공급한다. 부두는 잎 운반, 작은 수차는 D4 개방, 주 출구는 최종 공급에 반영된다. Q로 방향을 지우지 않는다.
- **D4:** 공급이 연결된 상태에서 D2를 `SMALL WHEEL`로 두어 문을 완전히 열거나 `D4 GATE LIFT ROOT`를 성장시킨다. 걸쇠가 걸리면 D2를 `MAIN EXIT`로 바꿔도 문이 유지된다.
- **W:** 상부 연결 **또는** 우회 공급, 열린 D4, D2의 `MAIN EXIT`, 주 공급로 비동결이 동시에 성립해야 물이 도착한다. 연속 3초 유지하면 식생 도형이 커지고 초록색으로 복원된다. 물레방아는 현재 물 도착 여부에 따라 회전한다. 복원 완료는 유지하며 현재 공급 여부는 별도로 표시한다.

권장 비교 실험은 먼저 우회 뿌리 + D4 뿌리 + MAIN으로 연결하고, R로 지하를 초기화한 뒤 상부 정렬 + 작은 수차 개방 + MAIN으로 연결하는 것이다. 이 순서를 강제하는 판정은 없다. 방문 순서, 사용 횟수, 지상 구역 완료 여부를 검사하지 않는다.

| 실패 설정 | 확인할 결과 | 복구 |
| --- | --- | --- |
| D2가 부두 방향 | 잎이 이동하고 W 하류는 마름 | FLOW 회수 후 중앙을 MAIN으로 변경 |
| D4가 닫힘 | 문 앞까지 공급되고 문 뒤는 마름 | SMALL WHEEL로 끝까지 개방 또는 D4 뿌리 성장 |

## 5. 조정 위치

Inspector에서 다음 컴포넌트 값을 조정한다. 다시 생성할 기본값은 `Assets/EverflowPuzzleLab/Editor/PuzzleLabBuilder.cs`에 있다. 수정한 씬은 생성 메뉴로 덮어쓰지 않는다.

| 컴포넌트 | 조정 값 |
| --- | --- |
| `EFMapPlayer` | `moveSpeed=6`, `jumpHeight=1.35`, `gravity=24`. 실험실은 `puzzleLabLocomotion=true` |
| `EFMapCamera` | 거리 6m, 시야각 65°, 감도·피치·카메라 충돌·추종 지연 |
| `PuzzleLab` | 조준 사거리 `castRange=14`, 구역 배열·구체 시각화 참조 |
| `LabMover` | `speed` 0.8~1.2m/s, `home`, `destinations`, `oscillate`, `smallSpeed`, `smallReach`, 회전체 속도 |
| `LabTarget` | 성장 전후 크기, 활성화할 뿌리 도형, FLOW 방향 이름·화살표, 물/구조물 구분 |
| `LabGate` | `speed=1.8`, `lift=3.6`, 닫힘 위치·문·수차·걸쇠 참조 |
| `LabCanal` | `connectionPoint`, `connectionTolerance=0.5`, `successSeconds=3`, 실제 공급 단계별 수면 참조 |
| `LabArea` | 안전 시작 위치, 구역 Bounds, 낙하 복귀 높이, 목표 Bounds와 두 번째 착지 목표 |

현재 레일의 `home` / `destinations`, 문 닫힘 위치, 수로 연결 기준점은 **월드 좌표**다. 구역 전체를 손으로 옮기면 관련 좌표도 함께 수정해야 한다. 작은 거리 조정 뒤에는 참조 검사와 직접 점프 검증을 다시 한다. 물 표면과 이동 화살표 활성화는 `LabCanal`의 실제 공급 조건과 연결된다. 유체 시뮬레이션은 없다.

## 6. 구조와 기존 기능 재사용

- 기존 `EFMapPlayer`의 CharacterController 이동·점프·회전·Teleport와 이동 지면 추종 계산을 재사용했다. `puzzleLabLocomotion`은 기존 씬에서 기본 false다. true인 실험실만 기존 능력 입력·Stage World 의존·기존 낙하 처리를 건너뛰고 일반 Collider에도 탑승 추종을 사용한다.
- 기존 `EFMapCamera`, `EFMapInput`, `EverflowGraybox.EFInput`의 이동·시점·일반 키 읽기를 재사용한다. Q/X/Tab/Backspace/F9는 실험실에서 별도로 읽는다.
- 기존 `EFMapNode` 능력은 StageIndex 및 이전 Pulse·초기화 의미에 묶여 있어 재사용하지 않았다. 기존 `EFMapCheckpoint`, 수문·수로 실험 코드도 기존 World 및 Stage 참조가 필요하므로 안전 복귀·수문·초기화는 작은 전용 컴포넌트로 분리했다.
- `LabState.cs`는 실제 런타임이 사용하는 구체 슬롯, 완료 변화, 수문 걸쇠, 도착 타이머와 공급 논리다. Unity 밖 상태 검사도 복제 모델 대신 이 파일을 직접 컴파일한다.
- `LabTarget`, `LabMover`, `LabGate`, `LabCanal`, `LabArea`, `PuzzleLab`이 반응 대상·레일·문·수로·초기화·입력을 나누어 맡는다.
- 기존 씬·타이틀·빌드 목록·URP·패키지·앱 버전은 변경하지 않았다. 기존 사용자 변경인 `Everflow_Map.unity`와 외부 에셋도 덮어쓰지 않았다. AGENTS.md는 프로젝트와 확인한 상위 경로에서 발견되지 않았으며 `지시사항.txt` 및 기존 개발 문서를 확인했다.

## 8. 안내판 정리 — 2026-11-04

현재 씬의 TextMesh 61개를 확인하고 긴 설명을 구역별 대표 안내판 5개로 모았다. 어두운 단색 배경과 제목 띠, 왼쪽 정렬, 목표·테스트 방법·조작/복구·상태의 별도 영역을 사용한다. 반응 대상에는 짧은 라벨 20개를 남겼으며 이전 긴 안내 35개는 각 구역 `Presentation/Legacy Text (inactive)`에 보존했다. 씬 전체를 재생성하지 않았다.

- Hierarchy: 각 구역의 `Presentation/Board T01`~`Board T04`, `Board D`, `Short Labels`, `Legacy Text (inactive)`.
- 문구·기본 배치: `Assets/EverflowPuzzleLab/Presentation/Signage.json`.
- 상태 갱신: `LabInfoBoard`가 기존 LabArea/LabCanal 상태를 읽는다. 기존 `sign`/`readout` TextMesh 참조 ID를 그대로 유지하고 안내판 하단으로 옮겼다. 구역 성공·문 걸쇠·연결·우회·내부 물 동결·분기·공급·주 얼음·W 타이머를 표시한다.
