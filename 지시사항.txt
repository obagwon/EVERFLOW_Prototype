현재 Unity 프로젝트를 먼저 파악한 뒤, 빌드 문제 해결과 시작 화면 구현을 진행해줘. 설명만 하지 말고 필요한 코드, 씬, UI 연결, 프로젝트 설정까지 실제로 반영해줘.

## 1. 작업 전 프로젝트 파악

- 프로젝트의 AGENTS.md 등 작업 지침이 있으면 먼저 읽고 따라줘.
- Unity 버전, 렌더 파이프라인, 입력 시스템, 씬 구성, 기존 UI, 게임 초기화 구조, 빌드 설정과 기존 빌드 스크립트를 확인해줘.
- 현재 변경되어 있는 파일을 확인하고, 사용자가 작업한 내용을 덮어쓰거나 되돌리지 마.
- 프로젝트를 파악한 결과와 수정 계획을 간단히 설명한 다음 구현을 진행해줘.

이 프로젝트는 EVERFLOW라는 3D 퍼즐 어드벤처 게임이야. 세 가지 능력을 활용하는 핵심 퍼즐 6개를 단순한 형태로 구현해둔 상태야. 이번 작업은 기존 퍼즐을 유지하면서 빌드 실행부터 게임 진입까지의 흐름을 완성하는 것이 목적이야.

## 2. 목표 실행 흐름

Windows 실행 파일 실행 → 시작 화면 → ‘게임 시작’ 버튼 클릭 → 기존 Everflow_6Puzzles 씬 진입

- 게임 플레이 씬은 정확히 `Everflow_6Puzzles`야. 프로젝트에서 실제 씬 경로를 찾아 사용해줘.
- 이 씬은 Unity 에디터에서 실행할 때 기존 퍼즐이 나오는 씬이야.
- 퍼즐을 새로 만들거나 복제하지 말고 기존 씬으로 연결해줘.
- 플레이어, 카메라, 퍼즐 배치와 동작은 유지해줘.

## 3. 빌드에서 게임 화면이 나오지 않는 문제 확인

현재 에디터에서는 게임 화면이 나오지만 빌드에서는 나오지 않는 문제가 있어.

- 활성 빌드 프로필 또는 빌드 설정의 씬 목록과 순서를 확인해줘.
- 카메라, 게임 초기화, 에디터 전용 코드 의존성, 확인 가능한 빌드 및 실행 로그를 조사해줘.
- 시작 화면을 만드는 것과 별개로 실제 원인을 확인하고 필요한 부분을 수정해줘.
- 추정 원인과 확인된 원인을 구분해서 설명해줘.

## 4. 시작 화면 구현

- 별도의 시작 화면 씬을 만들고 빌드의 첫 씬으로 설정해줘.
- 화면 중앙에 로고를 배치하고 그 아래에 ‘게임 시작’ 버튼을 배치해줘.
- 시작 화면 로고는 `Assets/logo/EVERFLOW_color.png`를 사용해줘.
- 원본 이미지의 비율과 투명도를 유지하고, UI에 필요한 임포트 설정을 적용해줘.
- 배경은 로고가 잘 보이는 어두운 청록색 계열로 단순하게 구성해줘.
- 화면 크기와 화면비가 달라져도 로고와 버튼이 잘리지 않게 해줘.
- 화면 하단 구석에 현재 게임 버전을 작게 표시해줘. 버전 문자열을 별도로 하드코딩하지 말고 프로젝트의 앱 버전 값을 사용해줘.
- 설정 메뉴나 복잡한 애니메이션은 이번 범위에 포함하지 마.

## 5. 게임 시작 버튼 연결

- 버튼 클릭 시 `Everflow_6Puzzles` 씬을 로드해줘.
- 연속 클릭에 의한 중복 씬 로드를 방지해줘.
- 타이틀에서는 커서가 보이고 UI 클릭이 가능해야 해.
- 게임 진입 후에는 기존 게임의 커서 상태와 입력 방식이 정상적으로 적용되어야 해.
- 씬 전환으로 카메라, EventSystem, 플레이어 또는 유지되는 매니저가 중복 생성되지 않는지 확인해줘.
- 타이틀 씬과 게임 씬이 실제 사용되는 빌드 씬 목록에 포함되도록 해줘.

## 6. 게임 아이콘 설정

- `Assets/logo` 폴더에서 `EVERFLOW_icon.png`를 찾아 사용해줘.
- Windows 빌드의 실행 파일 및 앱 아이콘에 적용되도록 Unity Player Settings의 해당 아이콘 설정을 구성해줘.
- 시작 화면 로고와 앱 아이콘은 각각 지정한 파일을 사용해줘.
- 원본 파일은 덮어쓰지 마. 크기나 형식 때문에 정상 적용이 어렵다면 문제를 설명해줘.

## 7. 빌드 버전 관리

현재 버전은 `1.0.1`이고, 이번 변경을 포함한 다음 빌드는 `1.0.2`로 만들어줘.

- 실제 프로젝트 버전 값이 1.0.1인지 먼저 확인해줘. 다르면 임의로 낮추지 말고 차이를 알려줘.
- 이후 새 배포용 빌드를 생성할 때마다 패치 번호가 한 번씩 증가하도록 해줘.
  예: 1.0.1 → 1.0.2 → 1.0.3
- 에디터 실행, 스크립트 컴파일, Play 모드 진입만으로 버전이 증가하면 안 돼.
- 빌드 실패 또는 취소로 버전이 계속 소모되지 않도록 해줘.
- 빌드에 포함된 버전, 시작 화면에 표시되는 버전, 성공 후 프로젝트에 기록된 버전이 일치해야 해.
- 기존 빌드 자동화가 있으면 통합하고 중복 증가를 방지해줘.
- 별도의 배포용 빌드 메뉴가 필요한 경우 구현하고 사용 방법을 알려줘. 일반 Build/Build And Run에도 적용되는지, 전용 메뉴에서만 적용되는지도 명확히 설명해줘.
- 기존 빌드 산출물은 덮어쓰지 말고 가능하면 버전별 출력 폴더를 사용해줘.

## 8. 구현 및 검증

- 프로젝트의 Unity 버전과 기존 패키지에 맞춰 구현하고, 불필요한 패키지를 추가하지 마.
- 필요한 스크립트뿐 아니라 씬 생성, UI 구성, 버튼 이벤트, 로고 연결, 아이콘과 빌드 설정까지 완성해줘.
- Unity 에디터를 직접 조작할 수 없다면 Editor 스크립트 등으로 설정 작업을 자동화하고, 내가 실행해야 할 메뉴와 순서를 알려줘.
- 자동 설정 작업을 다시 실행해도 씬이나 UI가 중복 생성되거나 기존 수정 사항이 불필요하게 초기화되지 않도록 해줘.
- 열려 있는 Unity 에디터와 충돌할 수 있는 작업은 피하고, 종료가 꼭 필요한 경우 알려줘.

가능한 범위에서 다음을 확인해줘.
- 컴파일 오류 없음
- 시작 화면의 로고, 버튼, 버전 표시 정상
- 버튼 클릭 후 Everflow_6Puzzles 진입
- 기존 플레이어 이동과 퍼즐 조작 정상
- Windows 빌드의 시작 흐름과 아이콘 적용 정상
- 버전 증가 및 빌드 실패·취소 처리 정상

직접 실행하지 못한 검증은 ‘미확인’으로 표시하고 완료했다고 주장하지 마.

완료 후에는 프로젝트 구조 요약, 확인된 문제 원인, 변경 사항, 내가 해야 할 Unity 작업, 다음 배포 빌드 방법을 간단히 정리해줘.
